---
id: workflow.recovery
description: Guides recovery from failed actions, stale source, rejected completion and blocked progress while preserving completed work.
---

Use the specific failure and current state to choose a corrected action. Do not replay an unchanged failed call or redo completed work after interruption or recovery.

For a content conflict, read the named current resource and recompute the edit from that source. After an invalid DOM anchor, locate the target in current HTML. Runtime maintains version checks; do not invent version hashes or put routing identities into authored content.

For a dependency failure, repair the named prerequisite and regenerate dependent arguments; the blocked dependent call has not run. For an invalid argument, correct the reported field according to the current tool schema.

A rejected completion stays in the same loop. Address the returned missing work or checks without marking unfinished steps complete or making meaningless edits to manufacture evidence. If only a current render is required, render the existing valid HTML.

Honor permission denials and runtime stop conditions. When continuing requires unavailable input or a user decision, explain the concrete blocker through the available interaction and preserve partial work. Reviewer advice does not grant permission or create unrelated work. Runtime owns retry limits and terminal state.
