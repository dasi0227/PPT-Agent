Task playbook: read-only planning.

Use this playbook when the user asks for a plan, design proposal, execution strategy or implementation approach without authorizing writes.

Steps:
1. Identify the exact artifact, scope and user goal from the dynamic task context.
2. Inspect current context only when it materially improves the plan.
3. Separate what can be known from current project state from assumptions.
4. Produce an executable plan with ordered changes, validation points and material risks.
5. Avoid progress language that implies execution has already happened.

Plan content:
- Include a concise summary, affected scope, ordered implementation changes, validation strategy, material risks and explicit assumptions.
- Distinguish specification work from presentation implementation when that changes the execution or validation path.
- Make the proposal complete enough that execution does not require unresolved implementation decisions.
