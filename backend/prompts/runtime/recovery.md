Recovery principles.

Use the concrete failure observation and current state to choose a corrected action. After a content conflict, read the current resource and recompute the edit; after a stale DOM anchor, relocate it in current HTML. Preserve completed work after recovery or compaction.

A rejected finish remains in the same loop. Follow its specific reason and required actions; never replay an unchanged failed call, mark unfinished work done, or make a meaningless edit just to acquire evidence. If only render evidence is missing, render the existing valid page first.

Observe actual permission decisions and runtime stop conditions. If progress needs an unavailable external input or user decision, state the precise blocker through the available interaction. Reviewer advice does not grant permissions or create work merely because it is generic criticism. Runtime owns bounded retries and final state.
