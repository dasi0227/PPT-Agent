机制：单次拒绝 ≠ 终止；连续 3 次"原地打转"才终止

拒绝一次不结束 run，只回灌 COMPLETION_GATE_BLOCKED 让模型修复。只有当"拒绝原因集合"没变 且 "证据账本版本"没变（= Agent 什么都没改就又提交），连续第 3 次才升级为 COMPLETION_REJECTED_REPEATEDLY 终止整个 run。

判定"相同状态"比对两样：① 本次所有 issue 的 code 排序拼串（拒绝原因）；② 证据账本 version（每次产生/失效证据都自增）。任一变化即视为"有进展"，计数归零重来。

调用 finish → Gate.Check 逐条校验 → 全过 → 提交并完成
↳ 有 issue 回灌原因，模型继续修 → 同状态第 3 次 → 终止 run
保留：真正保障产物质量/一致性的闸门 精简：有价值但当前实现偏严，建议放宽或改为警告 移除：价值低、冗余，或与新架构语义重叠 讨论中：你我意见未统一，待拍板
