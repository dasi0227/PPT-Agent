# 目录结构创建与保存一致性

日期：2026-10-10。状态：前后端已实施，待用户手动验收界面。

## 已确认决策

- 新项目不自动生成 `.outline.json`。快照中的空 `sections` 只是展示值，真实存在性由 `hashes.outline` 判定。
- 缺失目录复用内容要求、视觉要求的「暂无文件／新建」画布；点击「新建」才创建真实的空目录文件。此决策补充 2026-10-08 资源按需创建设计中目录不支持新建空文件的约定。
- 普通目录编辑确认后立即持久化；取消章节、小节或页面的新增不提交变更。普通画布不显示「恢复／保存」按钮，也不保留空底栏。
- 普通保存反馈复用管理编辑器的「正在保存…／已保存」及错误样式；失败保留输入，版本失效后禁止覆盖。
- 目录文件创建后支持只读 JSON；文件缺失或编辑／保存期间禁止切换 JSON。审批中的 JSON 展示隔离草稿，不依赖正式文件存在。

## 创建接口

`POST /projects/:id/mutations` 增加 `outline.create`，前端继续通过现有请求头提交预期场景修订号。

服务端在现有项目锁和缓冲事务内确认文件缺失，写入 `{"sections":[]}` 并返回真实资源哈希。已有空文件、已有非空文件或缺失文件携带非空预期哈希时返回内容冲突，不覆盖原文件。创建失败后前端刷新快照，并在仍缺失时允许重试。

`outline.init` 继续用于初始化实际结构；不通过其空结构无变更分支创建文件。

## 审批编辑

- 行内确认、增删和移动均立即调用审批草稿 API，使用当前草稿修订号，成功后以服务端返回的草稿和修订号更新画布及 Timeline 差异。
- 「恢复」回到 Agent 原始 `proposal`，必要时写入审批草稿；不是回到项目基线。
- 底部「保存」先持久化尚未确认的输入，待编辑和忙碌状态清除后，将实际保存的修订号标为可审阅。
- 草稿 API 不写正式项目资源。最终批准和运行继续仍由 Timeline 完成，并再次核对草稿修订号。

## 验证

定向检查覆盖空文件落盘、创建冲突、新项目保持缺失、普通保存反馈、失败保留输入、取消新增、草稿增删改移动即时持久化、重新打开草稿、恢复提案和 Timeline 修订门禁。内容要求编辑的相关回归检查通过。界面交互与视觉由用户手动验收。
