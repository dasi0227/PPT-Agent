# 设计要求统一与页面装饰位置冲突

日期：2026-09-30。状态：已实施，待用户手动验收。

## 1. 用户决定与适用范围

视觉方向和排版偏好合并为一份全稿视觉设计要求；视觉要求页面的二级标题采用「设计要求」，与「页面装饰」并列。装饰在设置时反馈位置占用并阻止冲突，后端与渲染链路遵守同一规则。

本文替代 [视觉要求、排版偏好与主题职责边界](2026-09-24-visual-requirements-theme-boundary-design.md) 中的 `direction`、`layout_preferences` 字段、展示和写入约定。该文关于主题来源、公共 HTML 创作合同、Runtime 装饰归属及导出一致性的约定继续有效。内容要求沿用 Manifest，单页布局沿用 Spec。

## 2. 唯一数据结构

实际创作文件为 `artifacts/.design.json`，结构如下：

```json
{
  "requirements": [],
  "decorations": {
    "page_number": "bottom-right",
    "section_title": "top-left",
    "deck_title": "none",
    "key_message": "none"
  }
}
```

两个顶层字段均必需。删除 `direction`、`layout_preferences`；不保留兼容读写、迁移或旧字段降级分支。不新增主题、风格枚举、密度枚举或项目元数据。

## 3. `requirements`：设计要求

完整定义：

> 整套演示文稿在页面创作时需要持续遵循的视觉设计要求。以自然语言逐条记录，可涵盖整体观感、信息密度、排版与层级、图文表达、视觉元素使用、参考与品牌约束，以及动效表现。每条要求应独立、明确、可执行，允许包含适用条件、偏好或明确禁令。

- 类型：`string[]`；默认：`[]`。
- 最多 32 条，每条 1–600 个字符，顺序保留；界面支持逐条增删改，Agent `edit_design` 提交数组时整体替换；补丁可操作 `/requirements` 及单项路径。
- 只记录本项目实际要求，无需填满所有维度，不自动生成空分类或泛化默认要求。
- 「少用卡片」是偏好，「禁止卡片」是明确禁令；均可放在同一列表，无需另设禁止字段。
- 「少字」或低密度不能删除必须保留的内容，应通过组织、精简或拆页解决。
- 单页具体布局放在该页 Spec；内容、目标、受众放在 Manifest。
- 不重复通用质量规则或所选主题的已有配置；明确配色、字体要求由主题能力落实，无法落实时说明限制，不虚构可写字段。动效同样受现有 HTML 与导出能力约束。
- 参考通过现有附件引用关联，不在 Design 中复制素材数据。
- 修改列表更新创作依据，不自动重写已有 HTML，也不推进生成参考基线。已有生成参考、净差异和内容指纹改为使用新列表。

示例：

```json
[
  "整体专业克制，以结构示意图和流程关系解释概念。",
  "每页突出一个重点，必要内容通过合理拆页保留。",
  "少用卡片，优先通过留白和对齐区分内容。",
  "数据分析页可以更紧凑，避免连续多页采用相同布局。"
]
```

## 4. 装饰位置唯一性

`decorations` 保留四个固定键及现有位置枚举。页码不允许 `none`，其他三项允许；文字继续由 Runtime 从对应内容资源推导。

规则：每个非 `none` 位置只能分配给一个启用的装饰。`none` 可重复。判断依据是全局配置，即使某页没有章节标题或核心信息，也不释放其已设置的位置；缺少文字仍不绘制。

前端复用公共 Select：

- 已被其他装饰占用的选项展示「左上 · 已被章节标题占用」并禁用，不等用户保存或查看画面后才提示。
- 当前装饰自身不算占用者，已选位置仍可正常显示；其他装饰改为隐藏或换位后，候选位置随数据立即更新。
- 页面简短说明「每个位置只能放一个装饰，已占用的位置不可选」。

后端在 Design 的统一校验入口检查位置唯一性，覆盖结构化管理、Agent 字段编辑、补丁、完整写入及严格源码解析。冲突错误明确包含两个装饰及位置，失败不保存。部分装饰编辑先合并，再校验最终配置，因此可以在同一请求中交换两个位置，无需中间态。

Runtime 和预览消息校验同样拒绝冲突配置，不隐藏其中一个装饰来掩盖错误。预览、放映、缩略图及各类导出继续共用公共装饰器。

本规则解决同一位置重复分配。不同位置的长文本与正文之间的避让仍属于布局与渲染工作，不新增自动移动或文本碰撞算法。

## 5. 实现范围与手动验收

同步更新 Go/TypeScript 类型、业务 Schema、初始化、补丁权限、工具输入与返回说明、Agent 提示词、生成参考快照、内容指纹、管理 UI、公共装饰器及相关测试数据。保留现有主题唯一来源和 Runtime frame 格式，不修改 `DESIGN.md`。

遵循仓库约定，本次不运行构建、自动测试或浏览器验证；已同步原有测试数据，并补充冲突写入、失败不保存、原子交换及旧字段拒绝的回归用例，交由用户执行。

手动验收：

1. 新项目 Design 仅有 `requirements` 和 `decorations`，要求默认空列表；视觉要求页面展示「设计要求」「页面装饰」。
2. 增删改要求只保存新字段；Agent 能更新设计要求，内容要求和单页布局归属正确；旧字段与旧补丁路径不再接受。
3. 页码位置菜单将章节标题的位置标为已占用且不可选；隐藏或移动章节标题后该位置释放，重复 `none` 合法，页码不能隐藏。
4. Agent 或管理接口提交冲突配置时收到包含冲突双方的错误，文件保持原状；同一次编辑交换位置可成功。
5. 修改要求改变设计内容指纹及生成参考净差异，但不自动修改 HTML；装饰修改在预览和导出中保持一致。
