# 时间线活动持久化与恢复

> 2026-09-25 持久化切换说明：本文中的旧数据库表、独立 user/model JSONL、命令专用执行接口及事件流描述已由[会话日志、命令与数据库重构总结](2026-09-25-session-storage-refactor-design.md)替代。其他产品行为仍按最新用户决定执行；新实现仅做静态复核，手动验收见新文档第 17 节。

日期：2026-09-22。按用户最新决定，所有 Timeline 活动均需由后端持久化并支持恢复，覆盖此前 rename、polish 仅保存在前端的约定。

## 命名展示

`keep` 保留当前会话名称，不产生新名称。空标题沿用会话标签的「新会话」，详情为「保留当前名称：新会话」；有标题时显示实际名称。历史记录保存执行时的名称，不随后续改名重写。

## 数据来源

- 主任务的消息、工具调用、计划、问题、范围审批、命令授权及终态来自 `run_events`，history 接口用数据库事件补齐 JSONL 投影；JSONL 缺失不再直接返回空历史。
- rename、polish、kickoff、handoff、手动 compact 使用 `command_activities`。保存活动 ID、独立尝试 ID、会话与项目、命令种类、手动／自动来源、状态、真实阶段、原名称、请求、结果及毫秒时间。
- commit 继续使用已有提交操作记录，正确恢复进行中、空提交、完成、失败、取消。
- 自动 compact 的成功结果来自 `context_compactions`，进行中或中断状态由已经落库的 Run 事件恢复。

前端发送 `X-Command-ID`，服务端在缺省时生成 ID。一次独立命令使用一个活动 ID，重试与调整建议复用该 ID，保持原时间位置并替换当前状态；尝试 ID 阻止旧请求迟到结果覆盖新尝试。失败修订保留上一版成功结果及本次请求，供再次重试。

## 写入与恢复

请求执行前创建进行态活动，真实阶段到达时更新，结果写入后才发送成功响应。活动中间件位于项目历史事务外层，失败和取消记录在事务回滚后重新保存。项目快照收录终态活动，排除进行态，避免恢复出无法继续的悬挂命令。

同步命令断线仍取消模型调用；刷新恢复记录后查询后端直至最终状态。服务重启将遗留同步命令标记为停止。恢复的是活动、结果及后续操作能力，不自动重放模型调用。主任务与提交继续采用各自的运行恢复机制。

History 返回 `command_activity` 条目，前端映射至已有命令组件，保留复制、应用、简报新建会话、失败重试与调整建议。相应 briefing／compaction 业务记录不再重复产生一条成功活动。活动记录不注入模型上下文。

不迁移过去仅存在前端内存的事件，刷新后已丢失的旧事件无法从后端恢复。

## 手动验收

按仓库要求，未执行自动化验证。关注：空白新会话执行 rename 后 keep 文案及刷新；六种命令成功、失败、停止后的刷新与重试；polish 恢复后应用与带建议重试；简报修订不重复；自动 compact 中断、服务重启及刷新；命令授权记录恢复；项目回退不会复活进行态命令。
