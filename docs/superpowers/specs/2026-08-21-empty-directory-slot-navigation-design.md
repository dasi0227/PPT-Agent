# 空目录节点页面移动设计

## 适用范围

本设计仅调整左侧目录中页面“上移 / 下移”的目标计算。它适用于 section 直属页面区、subsection 页面区以及这些目录节点为空的情况，不修改目录视觉样式、后端数据结构或拖拽协议。

## 问题

当前实现将所有实际页面展平成 `directoryEntries`，再以相邻页面作为上下移动目标。空 subsection 不包含页面，因此不会进入该数组。当 3.2 为空时，3.1 的末页向下寻找的下一张实际页面可能位于第 4 章，页面因此越过 3.2 直接改变 section 归属。

## 决策

### 结构组

前端从现有目录数据派生有序的结构组：

1. 每个 section 的直属页面区是一个组，即使没有直属页面也保留。
2. 每个 subsection 是一个组，即使没有页面也保留。
3. 组顺序严格遵循 outline 中的 section 和 subsection 顺序。
4. 每个组携带唯一 placement：`section_id`，以及 subsection 组对应的 `subsection_id`。

该结构只用于计算交互，不新增持久化字段，也不改变后端请求格式。

### 上下移动语义

- 页面在当前组内存在相邻页面时，只交换组内页面顺序，placement 不变。
- 页面是当前组最后一页并向下移动时，进入紧邻的下一个结构组，并插到该组开头。
- 页面是当前组第一页并向上移动时，进入紧邻的上一个结构组，并插到该组末尾。
- 紧邻结构组为空时仍然是合法目标，不得继续跳到后续非空组。
- 不存在上一组或下一组时，对应按钮禁用。
- 一次点击只跨越一个结构组。

### 数据提交

移动完成后，前端仍使用现有 restructure 请求提交完整 `ordered_ids` 和 `placements`。后端继续返回权威 `{slides, spec}` 快照，前端原子应用快照并保持当前 `slideId` 选中。

## 错误处理

- 结构更新进行中禁用其他移动操作。
- 请求失败时保留原结构并显示现有错误提示。
- 派生结构与页面 placement 无法对应时，不发送请求，并保持页面原位。

## 非目标

- 不新增或删除 section/subsection。
- 不改变拖拽落点交互。
- 不改变目录编号和展开收起行为。
- 不为旧接口响应增加兼容分支。

## 验收标准

1. 3.2 为空时，3.1 的末页向下移动后归属 3.2，而不是第 4 章。
2. 空的 section 直属区和空 subsection 均可成为相邻移动目标。
3. 组内上下移动只改变页面顺序，不改变 placement。
4. 跨组移动一次只进入相邻组，向下插到开头，向上插到末尾。
5. 移动后当前页面的 `slideId` 和 URL 保持不变。
6. 现有拖拽、删除、展开收起与后端快照流程继续通过测试。
