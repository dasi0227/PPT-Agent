# 智能体设置与失败展示

日期：2026-10-10。状态：已实施，未执行自动验证，待用户手动验收。

## 已确认决策

设置新增「智能体」栏目，采用现有设置页的分组、行式布局和开关样式。两个设置项均在名称下提供简短说明：

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 显示工具调用失败 | 关闭 | 隐藏单次失败及执行前阻止记录，Agent 继续依据完整工具反馈修复或重试。打开后显示这些记录。 |
| 资源编辑审批 | 开启 | 统一控制内容要求、视觉要求和目录结构的创建与修改；关闭后跳过人工等待，直接提交真实工具结果。 |

两个开关全局持久化，点击保存成功后热更新。资源审批在每次进入审批前读取最新设置；已出现的待审批项保持原流程，恢复同一待审批调用时也不能因开关关闭而自动提交。

保留实际工具执行、失败预算、原子提交、基线冲突校验及模型 Observation。计划审批、命令授权、范围扩圈和用户问答沿用原流程。用户已提交的拒绝决定仍保留可见记录。

## 配置与 API

`config.yaml` 增加 `agent`：

```yaml
agent:
  show_tool_failures: false
  require_resource_approval: true
```

未配置字段使用上述默认值，显式值必须为布尔值。配置不进入固定模型快照；运行中通过原始 live Registry 读取资源审批设置。

- `GET /settings/agent`：读取设置与独立 `revision`。
- `PUT /settings/agent`：提交 `revision` 和两个必填布尔值，拒绝缺失字段、未知字段及过期修订。
- `POST /settings/agent/reload`：加载有效磁盘配置后返回智能体设置。

智能体与模型设置共用配置管理器的锁及原子文件写入。分别维护修订身份，修改智能体设置不替换当前模型快照；任一设置保存都保留另一类字段及原有凭据。外部文件修改需先刷新，不能直接覆盖。

前端在保存成功后更新共享 store，使用跨窗口通知及窗口重新激活时的读取同步设置；忽略与本窗口保存交错的旧读取响应。保存失败保留服务端确认的值。

## 失败展示与最终原因

工具失败事件、持久化记录及模型反馈继续完整保留。前端在 Timeline 分组前应用当前开关，实时记录与历史记录遵循同一展示规则，开关切换无需新建任务。正常成功记录及最终任务状态始终可见。

运行内自动 Git 提交失败同样隐藏；用户主动发起的提交和其他独立命令保持原有反馈。人工拒绝属于已提交的决定，不因失败展示开关消失。

因连续工具修复失败而停止时，终止事件的原失败说明附带最后一次实际工具失败的公共原因。依赖跳过不能覆盖实际原因；成功修复后清除该原因。公共原因进入 checkpoint，最终展示不泄漏原始内部报错、请求信息或凭据。其他任务停止原因沿用已有终止投影。

## 手动验收

1. 在设置中找到「智能体」；确认默认失败展示关闭、资源审批开启。切换、刷新及重启后确认保存值。
2. 运行期间关闭失败展示，确认失败工具行消失，后续修复成功仍展示正常结果；重新开启后确认记录可见。终止失败原因始终可见。
3. 开启审批时编辑三类资源，确认仍需手动决定。关闭后重新触发创建或修改，确认直接提交并展示真实结果与 diff。
4. 在已有待审批或手动编辑草稿时关闭审批，确认当前提案保持等待；处理完成后，下一次操作按新设置执行。重启并恢复待审批任务时也保持此边界。
5. 在其他窗口切换设置，确认同步；交错保存模型与智能体设置，确认两类字段均保留，冲突或保存失败不会展示为成功。
