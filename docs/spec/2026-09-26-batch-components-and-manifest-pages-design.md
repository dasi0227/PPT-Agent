# 批量加载组件与演示页数

日期：2026-09-26。依据：用户确认的本轮分析与实施要求。

## 1. 批量组件加载

`load_component` 接收 `ids: string[]`，替换原来的单个 `id`。单个组件同样使用数组，不保留旧参数兼容入口。

```json
{"ids": ["metric", "diagram"]}
```

- 每次 1–8 个合法且不重复的稳定 ID，与 `load_skill` 的批量数量一致。
- 只读取启用且内容可用的组件；失败信息指出对应 ID。
- 按请求顺序读取并校验整批内容，全部成功后才保存当前 Run 的组件快照。任意一项失败，不新增或覆盖已有加载状态，也不报告部分成功。
- 每次最多加载 192 KiB HTML，按实际使用的正文快照合计；超限明确失败，不截断正文。
- 用户显式引用的组件沿用 Run 创建时的内容快照。
- 模型结果包含 `loaded`、`components`、`already_available` 和 `replaces_previous`。`loaded` 为本次返回正文的数量；相同版本已在可见上下文中的组件进入 `already_available`。上下文压缩后不再可见时重新返回正文。
- 时间线沿用资源数组及“已加载 N 个组件”，其中 N 为本次成功请求的组件数量；正文不进入公开事件。

## 2. Manifest 的期望页数

`.manifest.json` 新增顶层必填字段 `pages`：字符串，1–32 个字符，初始化为 `待明确`。允许 `10`、`11-12`、`约10` 等表达，不引入数值区间解析、页数硬门禁或自动补页。

基本信息的展示与编辑顺序：

| 字段 | 标签 |
| --- | --- |
| `title` | 演示标题 |
| `language` | 演示语言 |
| `pages` | 演示页数 |
| `audience` | 演示受众 |
| `goal` | 演示目标 |

“基本信息”仅为界面分组，不改变 JSON 的扁平结构。

`pages` 是规划要求，实际页数继续从 Outline 推导。保存字段只更新 Manifest，不直接增删页面，也不因当前页数不同而自动覆盖要求。Agent 在创建或调整整套演示时据此分配页面并检查实际目录。

后端类型、Schema、初始化、Agent 编辑、管理界面的 Patch 白名单、前端类型与表单一次性切换。遵循开发期规则，不增加旧数据兼容或自动迁移；旧 Manifest 缺失该必填字段时需补齐后使用新合同。

## 3. 基本信息与补充内容的边界

- `goal` 表达希望听众理解、决定或能够完成什么。
- `audience` 表达受众及其必要背景。
- `requirements` 保存额外的内容覆盖、案例、证据和表达要求，不重复基本信息。
- `prohibitions` 保存明确的内容禁忌与排除项。
- 视觉表达进入 `design.direction`，排版偏好进入 `design.layout_preferences`，配色和字体遵循用户控制的主题机制。不得把视觉配置塞入 Manifest；对于当前机制无法满足的明确视觉要求，应说明限制而非静默删除或虚构可写字段。

拆分混合要求时保留新增信息。例如“面向开发者，所以必须展示可运行代码”中的受众归入 `audience`，可运行代码要求保留在 `requirements`。不使用关键词过滤或程序自动删除自然语言条目。

字段 `description` 负责就近解释职责，`core/structure.md` 负责跨字段归属与去重原则，`playbook/deck.md` 负责期望页数在创作中的使用方式。Schema 的本地 `$ref` 展开保留同层字段说明，确保 `requirements`、`prohibitions` 的不同说明进入模型可见参数，同时保留共享数组约束。

## 4. 验收范围

关键自动检查覆盖批量失败不产生部分状态、用户快照与可见正文去重、压缩后重新加载、工具公开资源列表、字段说明传递、页数读写与实际目录独立，以及界面提交正确的字段路径。

手动验收：

1. 新项目的基本信息按上述顺序显示，演示页数初始为 `待明确`。
2. 将页数改为 `11-12`，保存并重新打开，内容视图和 JSON 预览一致，实际页面数量保持不变。
3. 请求 Agent 同时加载多个可用组件，时间线显示正确数量和组件名称。
4. 用包含语言、页数、内容与视觉要求的需求生成演示，检查基本信息不会再次抄入内容要求，并确认额外内容与视觉意图均被保留。
