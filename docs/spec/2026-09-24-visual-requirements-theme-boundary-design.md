# 视觉要求、排版偏好与主题职责边界

日期：2026-09-24。状态：已实施，待手工验收。

## 1. 目标与设计依据

同一份页面 HTML 应能在产品支持的主题之间切换，无需 Agent 按主题重新创作。视觉要求保存本套 PPT 的视觉表达、排版偏好和公共装饰位置；主题作为用户控制的项目设置，由 Runtime 应用。

本文记录本次讨论的最终决定，相关冲突以本文为准：

- 替代 [视觉要求预览与页面装饰结构](2026-09-24-design-decorations-design.md) 中的装饰对象、`requirements`、初始化及主题展示约定。
- 调整 [HTML 主题契约与运行时重构](2026-09-23-theme-refactor-design.md) 中的主题选择来源和 Agent 主题上下文；保留公共角色、无刷新换肤、资源指纹和冻结导出等能力。
- 保留 [组件边界与仓库预览](2026-09-24-component-boundaries-and-preview-design.md) 确定的组件独立设计与显式主题接入方式。
- 内容要求继续遵循 [内容要求与固定渲染规则的边界](2026-09-24-manifest-content-boundary-design.md)。

本文结构已在前后端、Agent 上下文、Runtime 与导出链路中切换。验收结果以实际运行和手工检查为准。

## 2. 最终数据结构

`design.json` 的业务字段如下。`version`、`project_id`、`created_at`、`updated_at` 等现有系统元数据继续由 Runtime 维护，示例省略这些字段。

```json
{
  "direction": "",
  "layout_preferences": [],
  "decorations": {
    "page_number": "bottom-right",
    "section_title": "top-left",
    "deck_title": "none",
    "key_message": "none"
  }
}
```

| 字段 | 类型 | 初始值 | 职责 |
| --- | --- | --- | --- |
| `direction` | `string` | `""` | 整套 PPT 的视觉表达方式 |
| `layout_preferences` | `[]string` | `[]` | 可逐条维护的全局排版偏好 |
| `decorations` | 固定键的对象，值均为位置字符串 | 如上 | 公共装饰的位置及显隐 |

删除 `theme`。装饰项不再嵌套对象，不保留 `placement`、`requirements`、`style` 或 `enabled` 子字段。

## 3. 视觉方向与排版偏好

### 3.1 `direction`：视觉方向

回答“本套 PPT 采用怎样的视觉表达方式”，用于保存跨页面、跨对话仍应遵循的表达约定，例如图解、结构示意、流程关系、摄影或插图的运用方式。

示例：

> 以工程图解为主要视觉表达，使用结构示意和流程关系解释概念。

约束：

- 保持单个自然语言字符串；初始为空，取消 `待确定` 等写入数据的占位文本。
- 不重复目标、受众等内容要求，不重复当前主题的字体、颜色、阴影或背景说明。
- 不继续包揽密度、留白、卡片使用和对齐方式，这些移入排版偏好。
- 不自动把默认主题解释成已确定的视觉方向；根据用户需求和实际创作决定维护。

### 3.2 `layout_preferences`：排版偏好

使用字符串数组，每条表达一项可独立理解、添加、修改或删除的偏好。初始为空数组，不预设低密度、少卡片等偏好。

```json
{
  "layout_preferences": [
    "整体保持中低信息密度，数据分析页可以适当紧凑。",
    "少用卡片，优先通过留白和对齐区分内容分组。",
    "标题和正文以左对齐为主，保持规整的网格关系。",
    "避免连续多页重复相同的等宽三栏布局。"
  ]
}
```

可覆盖文字量、信息密度、留白、版面饱满程度、分组方式、卡片使用、对齐秩序和页面间的布局变化。允许自然语言条件，不拆成一组固定枚举或额外的 `density` 字段。

执行原则：

- “少用卡片”表示优先采用其他分组方式；“禁止使用卡片”按用户明确约束执行。
- “工整”不等于所有页面使用同一模板；具体布局仍由内容决定。
- “少字”或“低密度”不能成为删除用户明确要求的必要内容的理由，应通过组织、精简或合理拆分解决。
- 仅针对某一页的构图写入该页 Spec 的 `layout`，不自动扩展为全局偏好。
- 不逐项目重复存储清晰、可读、对齐等通用质量规则；只保存实际的项目偏好。

### 3.3 边界与生效方式

| 信息 | 所属位置 |
| --- | --- |
| 标题、目标、受众、语言、内容要求与禁忌 | Manifest |
| 整套 PPT 的视觉表达方式 | `design.direction` |
| 整套 PPT 的密度与排版偏好 | `design.layout_preferences` |
| 某一页左图右文等具体布局 | 单页 Spec 的 `layout` |
| 公共装饰位置和显隐 | `design.decorations` |
| 全局字体、配色及公共角色外观 | 主题与公共 Runtime 样式 |

`direction` 和 `layout_preferences` 由 Agent 解读并落实到页面 HTML，修改要求文本不等于已有页面已经修改。不得仅为了整理措辞或一次局部编辑而重写整套视觉约定。

## 4. 公共装饰

### 4.1 固定键与位置值

`decorations` 必须完整包含四个键，不使用数组、任意类型或重复实例：

| 键 | 初始位置 | 内容来源 | 是否允许 `none` |
| --- | --- | --- | --- |
| `page_number` | `bottom-right` | 目录推导的当前页序号 | 否 |
| `section_title` | `top-left` | 当前一级章节标题 | 是 |
| `deck_title` | `none` | `Manifest.title` | 是 |
| `key_message` | `none` | 当前页 `Slide Spec.key_message` | 是 |

显示位置沿用 `top-left`、`top-center`、`top-right`、`bottom-left`、`bottom-center`、`bottom-right`、`left-edge`、`right-edge`。可隐藏项额外允许 `none`，不使用空字符串、缺键或 `null` 表达隐藏。

页码保持每页显示，封面和结论页不例外。章节标题取一级章节，不自动改用子章节标题；没有对应内容时不绘制。位置默认启用不等于初始化时生成一份装饰文字，内容不得在 Design 中重复保存。

写入路径直接指向字符串，例如 `/decorations/section_title`；删除旧的 `/placement`、`/requirements` 子路径。

### 4.2 渲染与外观

公共 Runtime 在每页 HTML iframe 外绘制装饰。编辑器预览、放映、缩略图、图片/PDF 导出和离线 HTML 使用同一套装饰规则。

删除装饰的 `requirements` 及其关键词解析逻辑。公共外观由 Runtime 样式与主题提供的语义变量统一决定，不再允许每个装饰写入自然语言外观要求或固定字号、颜色覆盖。

这意味着暂不支持通过对话单独指定页码字号、颜色、字重等样式。后续若存在明确需求，再独立设计可执行的结构化样式配置，本次不预留空对象或新增样式字段。

Agent 仍能读取并修改装饰位置。它需要据此为正文预留空间，避免重复绘制，并处理用户的位置与显隐请求。选区继续能识别装饰类型、位置、文本和范围，但不再携带 `requirements`。

## 5. 主题选择的唯一来源

项目当前主题由数据库 `projects.theme` 保存，继续通过已有的用户主题选择入口修改。主题 CSS、字体等资产保持各自现有存储方式，数据库只保存项目选择的主题标识。

实现要求：

- 删除 `design.json.theme`，项目读取不再用文件中的主题覆盖数据库值。
- 切换主题不再改写 `design.json`，不保留文件与数据库双写或双读。
- 项目目录中不再生成无人读取的 `artifacts/state.json`；项目状态、项目名称和主题选择由数据库维护，演示内容要求由 `manifest.json` 维护。创建项目接口不再传递无实际业务效果的 `brief`、`slide_count`、`language` 参数。
- 项目接口、前端主题选择器、Runtime frame、截图和导出从同一项目设置取得主题；禁止继续从 Design 反推主题。
- 项目内容快照可以携带只读的主题设置投影和外观描述，供前端、Runtime 使用；它们不是 Agent 可写的设计字段，也不是第二个权威来源。
- 主题变化及主题资产变化都应被多窗口同步、预览缓存和外观指纹识别；不能仅依赖 Design 是否变化。
- 保留现有主题可用性、停用状态、失败反馈及换肤行为，不隐式选择替代主题。

主题属于影响交付结果的项目设置，不属于仅存在于当前浏览器的界面偏好。项目 checkpoint 继续恢复当时的主题选择；现有数据库快照已包含 `projects`。导出继续冻结主题标识、CSS 和所需资源，离线文件不依赖实时数据库。

现有项目内置 Git 提交主要记录工作目录文件。移除文件中的主题后，这类提交不会自动记录数据库主题变化。本次不为此恢复可写副本；若后续要求单靠文件 Git 历史还原主题选择，应另行设计从数据库生成的设置快照，并明确其派生性质。

## 6. Agent 面向公共样式合同创作

### 6.1 模型需要的信息

Agent 不以当前所选主题为创作前提。移除主动注入的当前主题 ID、名称、风格描述、CSS 内容及实际 token 值，现有依赖所选主题的 `theme_context` 由公共创作合同替代。

公共合同包含：

1. 所有受支持主题都实现的 token 名称、语义与配对规则，例如 `--color-accent` 配合 `--color-on-accent`。
2. 公共 class 的角色与组合方式，例如标题、正文、图表标签、普通容器。
3. 固定 1920×1080 画布、最小页面结构、Runtime 注入资源、正文与装饰的职责边界。
4. 主题变化时的动态行为，例如 Canvas 在 `ppt:themechange` 后重新读取实际变量并重绘。

以 `backend/internal/designsystem/tokens.go`、`backend/internal/runtimeassets/base.css` 和 `backend/prompts/core/html.md` 为现有基础，公共清单由产品定义，所有主题实现。不得通过提取当前主题 CSS 或临时求主题变量交集来决定创作接口，也不新增多套重复的语义说明。

公共 class 是可复用的视觉角色，不是固定 DOM 模板。Agent 可以自由组织 Grid、Flex、自定义布局类和 SVG，不强制卡片、统一嵌套层级或固定整页结构。

### 6.2 Runtime 与模型上下文分离

Runtime 必须知道实际主题，负责加载 CSS、解析实际外观值、计算外观指纹和渲染；这些运行时依赖不等于模型必须接收当前主题说明。生成出的页面代码可以在浏览器运行时读取计算后的变量，不得按主题 ID 编写布局分支。

模型可以查看渲染结果、选区和必要的布局诊断。移除主题上下文不意味着隐藏截图或禁止观察实际效果；修正应保持对受支持主题的适配，不把眼前外观重新固化为全局创作要求。

公共合同的组装不再依赖成功读取某个所选主题。实际预览、截图和导出仍需正常的主题资产，可用性错误继续由对应运行环节处理。

### 6.3 换肤兼容的实现边界

只移除主题信息不能保证布局兼容。当前主题除颜色外，还会改变标题字号、字体、部分最大宽度及标签内边距；这些变化可能影响换行和占用空间。现有 token 校验主要检查必需声明是否存在，尚不能证明布局稳定。

后续实现需核对公共角色的尺寸行为：明确哪些几何属性保持稳定、哪些允许在受支持范围内变化，避免主题任意改变内容布局。页面应使用有弹性的排版并预留合理换行空间，不按单一主题的字形或具体像素值挤满画布。本次不新增一套未经确认的数值尺寸规范，也不宣称已完成跨主题验证。

组件继续拥有独立结构与设计。需要随页面变化的组件接口显式连接到公共语义变量；保留固定配色的组件应具有完整、可读的独立外观。不得通过只针对当前背景修一次颜色来实现适配，也不强制把所有组件内部改成公共角色。

## 7. 视觉要求文档展示

视觉要求仅展示视觉方向、排版偏好、页面装饰，不再重复展示当前主题。

- 视觉方向为空：显示“暂无视觉方向”。
- 排版偏好为空数组：显示“暂无排版偏好”；有值时按条展示。
- 页面装饰按页码、章节标题、演示标题、核心信息展示位置。
- `none` 显示“暂不展示”，不再展示“额外要求”或“暂无额外要求”。

沿用现有公共文档组件和项目视觉规范；本文不修改 `DESIGN.md`。

## 8. 实现范围与依赖语义

前后端一次性切换新结构，不保留旧装饰对象、旧主题字段、占位文本的兼容层，不设计历史开发数据迁移。

| 范围 | 需要同步的内容 |
| --- | --- |
| 类型、Schema、初始化 | 空 `direction`、字符串数组、装饰字符串及默认位置，删除主题与装饰要求 |
| Agent 写入与读取 | 排版偏好逐条增删改、装饰直接字符串路径、公共合同、上下文压缩和简报 |
| 项目主题服务 | 数据库唯一来源、项目投影、锁与历史一致性 |
| 前端 | API 类型、项目同步、主题选择器、视觉要求展示、装饰选区 |
| 渲染与导出 | Runtime frame、公共装饰器、截图 worker、离线播放器、冻结主题资源 |
| 指纹与页面状态 | 设计内容、外观、frame 和渲染证明的依赖同步 |

`direction` 和 `layout_preferences` 纳入设计内容指纹；仅换主题不改变创作要求或 HTML 正文字节，而是改变外观、frame 及相关渲染证明。装饰位置进入 frame；保留其可能影响正文预留空间的设计依赖，不因公共绘制就假设位置变化永远不影响正文。绘制装饰本身不要求 Agent 在 HTML 中生成副本。

字段调整应贯穿所有消费方，不能仅修改 Schema 或视觉要求页面。

## 9. 后续验收要点

仓库约定由用户执行验证；本次未执行构建、自动测试或浏览器验证。手工验收重点包括：

1. 新项目使用本文默认数据，空方向与空偏好展示正确；章节左上、页码右下，其余默认隐藏。
2. Agent 能逐条维护排版偏好、直接修改装饰位置；旧嵌套对象及子路径不再被接受。
3. 视觉要求和模型创作输入不再携带当前主题说明；公共 token 语义、class 和结构约定仍完整可用。
4. 更换主题只更新项目设置与运行外观，`design.json` 和页面 HTML 不因换肤被改写；其他窗口及历史回退同步正确。
5. 同一 HTML 在受支持主题间保持可读，关注长标题换行、标签尺寸、独立组件对比度、Canvas 重绘与装饰避让。
6. 预览、放映、图片/PDF、离线 HTML 的装饰内容、位置与主题外观一致，导出不依赖后续主题变更。
