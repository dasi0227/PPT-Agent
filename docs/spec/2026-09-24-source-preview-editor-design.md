## 1. 目标与最终决定

中间工作区同时承担阅读与手动开发两种用途。用户先选择「设计稿 / 幻灯片」，再选择「预览 / 源文件」；源文件与预览对应同一个内容对象，避免把内容对象和查看方式混为一组切换。

本文以本次讨论中的最终用户决定为准，取代讨论期间被否决的建议。

| 决策 | 最终约定 |
| --- | --- |
| 内容对象 | 保留「设计稿 / 幻灯片」 |
| 查看方式 | 新增「预览 / 源文件」，首次进入默认预览，不提供分屏 |
| 新图标 | 预览使用 Lucide `AppWindow`；源文件使用 `FilePen`，描边 `1.75` |
| 编辑范围 | 仅已有页面的 `spec.json` 与 `index.html` |
| 编辑器 | 轻量代码编辑器，支持行号、高亮、缩进、括号匹配、查找替换、撤销重做、错误定位 |
| 正式保存 | 用户点击保存或按 `⌘S / Ctrl+S`；输入、失焦、切页不自动保存正式文件 |
| 自动暂存 | 自动保存本地草稿，切页、切对象、切项目均保留 |

| 同文件外部更新 | 直接显示最新正式内容，清除该文件旧草稿及旧撤销记录；不做差异对比、合并或强制覆盖 |
| Spec 与 HTML | 独立保存，不自动触发 Agent，不自动正向生成或反向同步 |

| 项目历史切换 | 旧草稿保留为可找回副本，但不自动套用到切换后的文件 |

## 3. 工作区与交互

### 3.1 两个独立维度

| 内容对象 | 预览 | 源文件 |
| --- | --- | --- |
| 设计稿 | 现有结构化设计稿展示 | 当前页 `spec.json` 原文编辑器 |
| 幻灯片 | 现有隔离 HTML 预览 | 当前页 `index.html` 原文编辑器 |

保留原有内容对象图标和名称。新增查看方式使用 `AppWindow + 预览`、`FilePen + 源文件`，始终保留文案；使用现有分段切换的中性底色和 soft blue 选中反馈。两个控件分组呈现，不能合并成四个平级选项。

左侧目录继续按页面导航，不增加文件树。切换源文件只改变中间主体；右侧对话保持原有用途。切换内容对象时保留当前查看方式，例如从 HTML 源文件直接切到 Spec 源文件。

首次打开项目使用幻灯片预览；同一工作区会话中按项目记住查看方式。显式 URL 与项目历史恢复的目标优先于会话记忆。编辑器位置按项目、页 ID、文件种类保存，页序变化不改变文件身份。

### 3.2 布局与工具栏

原有顶部工具栏加入查看方式切换；宽度不足时分组换行，不缩成仅图标、不省略模式名称、不增加第三个侧栏。

源文件模式下：

- 编辑器填满中间可用宽高，移除预览主体的 16:9、最大画布宽度、缩放变换、平移手势与画布内边距。
- 使用项目浅色面板、细分隔线、等宽字体；正文默认 13px、约 1.6 行高、两空格缩进。行号弱化，长行在编辑区横向滚动，不撑宽工作区。
- 顶部一条紧凑文件栏，左侧显示 `spec.json / index.html` 与语言，悬浮可见相对路径；右侧显示状态和「保存」。不展示本地绝对路径。
- 多文件有草稿时，在文件栏显示「未保存 N 个」入口，展开按页序排列的文件列表；列表含页标题、文件名和跳转入口，底部提供「保存全部」。不建立常驻文件管理面板。
- 源文件模式隐藏元素选择、框选、缩放与放映按钮；读写能力不受这些预览工具控制。
- 上一页 / 下一页按钮仍可用，切页不触发正式保存。主题等项目级控件沿用既有门禁。
- 概览入口进入 `preview + overview`；从概览点击源文件切换时回到当前选中页的 `source + main`。放映只使用已保存 HTML，不执行草稿。

预览模式继续使用现有展示。当当前对应文件存在草稿时显示一条低干扰提示「有未保存修改，当前为已保存内容」，提供「编辑源文件」和「保存」；保存调用与编辑器相同的管线，不引入第二套逻辑。

焦点沿用项目无描边规范；通过选中态、光标、文字与读屏标签表达状态。新增编辑器和切换控件提供清楚的 `aria-label`，诊断信息可由键盘访问。

### 3.3 文件缺失与异常

- Spec 未生成：显示「设计稿源文件尚未生成」。HTML 未生成：显示「幻灯片源文件尚未生成」。不显示可编辑空白框或创建按钮。
- 文件存在但加载失败：显示错误与「重试」，不得当成文件缺失，更不能生成空字符串覆盖。
- HTML 文件存在但内容为空：展示真实空内容及校验问题，仍可编辑该已有文件；空 Spec 按下述系统字段无法确认的规则处理。
- Spec 可解析且系统字段有效、业务字段有误：允许打开原文并修复；Spec 严重损坏、无法确认系统字段时只读显示错误，由 Agent 修复。
- 页或文件被删除：停止编辑、取消该文件异步任务、清除活动草稿及撤销记录，显示最新缺失状态。不得通过迟到保存重新创建它。

## 4. 编辑器选型与状态

采用 CodeMirror 6，按需加载 JSON / HTML 语言支持、搜索、历史、括号匹配和诊断扩展；封装项目级 `SourceEditor`，由 React 管理生命周期，不在组件外直接改编辑器 DOM。选择依据是所需能力可以按模块组合；只读状态与 DOM 可编辑性需分别配置。参见 [CodeMirror 官方参考](https://codemirror.net/docs/ref/)。

预计依赖包括 `@codemirror/state`、`@codemirror/view`、`@codemirror/commands`、`@codemirror/language`、`@codemirror/search`、`@codemirror/lint`、`@codemirror/autocomplete`、`@codemirror/lang-json`、`@codemirror/lang-html`。按实施时可用版本锁定依赖，不加载完整语言集合或引入额外 IDE 框架。

编辑器保留一个活动 `EditorView`，切文件保存和恢复各自 `EditorState`、选区与滚动位置。同一会话切页、切项目、切模式和正常保存不得重建该文件的历史基线；外部正式更新与项目历史切换是例外。

```ts
type SourceKind = 'spec' | 'html';
type ContentMode = 'preview' | 'source';
type SourcePhase =
  | 'loading' | 'ready' | 'formatting' | 'saving'
  | 'reloading' | 'missing' | 'error';

interface SourceDocument {
  projectId: string;
  slideId: string;
  kind: SourceKind;
  sceneRevision: number;
  baseSourceHash: string;       // 真实源文件字节 hash
  baseContentHash: string | null;
  baseText: string;
  draftText: string;
  editGeneration: number;      // 仅用于拒绝迟到的本地异步结果
  phase: SourcePhase;
  readonlyReason?: string;
  draftPersistence: 'pending' | 'saved' | 'error';
}
```

`dirty` 从草稿与编辑基线的文本比较得到，不使用业务 hash 代替；JSON 格式变化也是尚未保存的修改。编辑器内部统一处理行分隔时，基线和草稿必须使用同一表示，打开 CRLF 文件不能立即变成 dirty。原始字节 hash 仍由服务端返回，不能用编辑器文本重新推导。

状态应拆为内容加载、保存阶段、写入权限和暂存结果，不把「只读」误当成「没有草稿」。文件缓存键必须包含项目、稳定页 ID、kind 和历史现场，不能只用当前页码。

| 情形 | 主状态文字 | 编辑 / 保存 |
| --- | --- | --- |
| 正常且无修改 | 已保存 | 可以编辑、可以主动保存并格式化 |
| 有修改且暂存成功 | 未保存 | 可以编辑、保存；悬浮说明本地草稿已暂存 |
| 正在格式化 | 正在格式化… | 当前文件暂时只读，防止重入 |
| 请求已发出 | 正在保存… | 当前文件暂时只读，禁止重复保存 |
| 格式 / 校验失败 | 无法保存 | 保留原输入，允许修复，显示定位信息 |
| 项目有活跃 Agent | Agent 任务进行中，暂不可编辑 | 禁止输入、替换、撤销、重做与保存；可阅读、复制、查找 |
| 更新文件尚未读回 | 正在加载最新内容… | 只读，禁止把旧草稿作为最新内容保存 |
| 暂存失败 | 草稿暂存失败 | 保留内存输入，允许正式保存，离开时保护未备份修改 |

## 5. 草稿暂存与恢复

草稿保存在浏览器 IndexedDB，不上传为正式创作文件。内存模型是当前输入的权威来源，IndexedDB 是恢复备份；不能每次输入都把整份项目序列化到同步 localStorage。

记录至少包含工作区会话 ID、项目 ID、页 ID、kind、`scene_revision`、`base_source_hash`、基线文本、草稿文本、更新时间、光标及滚动位置。每个标签页使用独立会话命名空间，避免两个窗口的本地暂存互相覆盖；刷新沿用原会话 ID。

输入后约 300ms 防抖暂存；失焦、切页、切对象、切模式、切项目及关闭项目 Tab 时立即刷新暂存。暂存写入带 generation，不能由较旧任务覆盖较新草稿。暂存失败不删除内存文本，也不能显示「已保存」。

恢复顺序固定为：加载本地草稿索引 → 读取服务端现场与对应原文 → 比较现场和源文件 hash → 决定恢复或替换。校验完成前禁止输入和启动 Agent。

- 同现场、相同源文件 hash：恢复草稿，保持 dirty，恢复可用的光标及滚动位置。
- 同现场、源文件已变化：按第 9 节加载最新并删除旧草稿，不弹出恢复选择。
- 历史现场变化：按第 10 节处理为历史草稿副本，不自动覆盖新现场。
- 源文件已删除：加载缺失状态并移除活动草稿，不能创建原文件。

普通导航不询问保存。浏览器刷新后仅恢复文本和位置，不恢复完整撤销栈。存在未完成或失败的本地备份时才注册离开保护；`beforeunload` 不能等待 IndexedDB，`pagehide` 仅做尽力刷新，不能承诺强制退出或系统崩溃时最后一个防抖窗口的输入必然恢复。

本地草稿不跨浏览器或设备同步。启动检查覆盖当前工作区会话该项目的全部草稿，包括未显示页面；其他窗口由自身草稿门禁、服务端项目锁和外部更新机制处理，不引入跨设备草稿锁。

## 6. 保存与自动格式化

### 6.1 保存入口

「保存」、预览中的保存入口与 `⌘S / Ctrl+S` 使用同一个 `saveSource(resourceKey)`。快捷键保存当前中间栏选中的文件；源文件编辑器优先处理并阻止浏览器“保存网页”，不能同时触发翻页或全局命令。右侧对话输入、弹窗和设置页的输入不被源文件快捷键接管。

保存快捷键加入已有快捷键目录和设置系统，但编辑器内的分发单独适配：现有 `useAppShortcuts` 会跳过文本目标，不能只给它增加一个回调。项目新快捷键配置结构前后端一起更新，不保留旧目录长度的兼容分支。

文件无 dirty 时也可以主动保存以统一格式；最终字节未变化时服务端返回无变化，不重复写文件或改时间戳。

「保存全部」串行处理当前项目的活动草稿，按页序、Spec 在 HTML 前排列。每个文件独立生效，遇到失败立即停止并定位到该文件；之前成功的文件保留，不承诺跨文件事务。保存完成不会自动发送此前被阻止的 Agent 请求，用户需重新提交。

### 6.2 格式化实现

只在用户明确保存时自动格式化。加载文件、恢复草稿、输入、失焦、外部更新均不触发格式化，也不后台保存格式化结果。

JSON 使用严格解析后的两空格格式，拒绝注释、尾逗号、重复键及多个根值；后端依现有 Spec 字段顺序与序列化方式给出最终规范文本。前端先检查原始 JSON 语法树中的重复键，再进行对象解析和重排，不能只依赖会吞掉重复键的 `JSON.parse`。不要先用宽松格式化器“修好”非法 JSON 再绕过校验。只改变空白或字段排列时允许写入规范格式，但不更新业务时间戳、不把 HTML 标为 Spec 过期。

HTML 使用 `prettier/standalone`，显式加载 `html`、`babel`、`estree`、`postcss` 插件，统一随项目打包。浏览器版无需 Node.js，插件不会自动加载，需显式传入；支持识别到的内嵌语言格式化。参见 [Prettier 浏览器文档](https://prettier.io/docs/browser)。

默认设置：两空格缩进、不用 Tab、LF 换行、`printWidth: 100`、`embeddedLanguageFormatting: 'auto'`、`htmlWhitespaceSensitivity: 'strict'`。HTML 使用更保守的空白敏感设置，避免按标签默认 display 推断布局；不使用压缩器，不重命名选择器、不删注释、不改资源地址。相关配置语义见 [Prettier 选项](https://prettier.io/docs/options#html-whitespace-sensitivity)。

可识别的 `<style>`、普通 JavaScript `<script>` 一并格式化；未知脚本类型按原内容保留，不执行脚本。内嵌代码解析失败时沿用格式化器保留该块的行为，编辑器有可用诊断时显示为警告，不把 JavaScript 运行错误升级成保存前渲染检查；若整体 HTML 格式化抛错则中止本次保存。嵌入语言的处理和失败回退机制见 [Prettier 插件文档](https://prettier.io/docs/plugins#optional-embed)。

格式化器和语言包懒加载。HTML 格式化放入 Web Worker，防止长文件阻塞输入线程；工作消息包含 resourceKey、generation 和现场标识，切项目、切历史现场或收到外部更新后丢弃过时结果。格式化失败或 Worker 加载失败时保留输入，不以“跳过格式化”静默继续保存。

### 6.3 保存管线

1. 检查文件已加载且真实存在、项目当前可写、草稿恢复已完成；冻结当前文件的编辑和重复保存入口。
2. 捕获本次文本、基线 hash、现场和 generation；先暂存输入，再生成格式化候选，不立即替换编辑器。
3. 执行本地可完成的语法检查，将候选和读取时的前置条件发送服务端。
4. 服务端在项目写门禁内重新检查活跃任务、历史现场、页面归属、文件存在、源文件 hash、内容结构与系统字段，完成单文件持久化。
5. 成功响应返回真实保存文本和最新 hash。前端采用返回内容建立新基线，清除该版本的草稿，恢复编辑，刷新项目快照和预览。
6. 本人保存产生的格式整理作为一次独立编辑事务进入当前撤销历史，不能用重建 EditorState 清空用户历史；服务端管理的时间戳同步不作为可撤销业务编辑。
7. 失败时按照第 9 节分类处理；只有确认服务端正式结果后才能显示「已保存」。

保存期间允许切页，结果必须回写原 resourceKey，不能把迟到响应写进新页。该文件的后台刷新先等待保存结算；本人保存的 hash 更新不能被误判为外部冲突并清空撤销记录，结算后再核对排队的最新通知。

## 7. 内容校验与预览关系

### 7.1 Spec

展示完整原始 JSON，系统字段用提示说明其只读含义，不把原文裁剪成不可回存的业务片段。首版不实现局部字符区锁定；用户修改系统字段时给出诊断并拒绝保存。

服务端必须校验原始 JSON 为单个对象、无重复键、无尾随数据、无未知字段，再使用现有 `slide-spec.schema.json` 验证字段类型、长度和枚举。当前结构体反序列化后再校验的路径不足以发现所有原文问题，需要补齐输入阶段的严格校验。

`version`、`project_id`、`slide_id`、`created_at`、`updated_at` 不允许由用户改变；前置 hash 已确认基线后，与正式文件及路由上下文核对。业务变化由服务端生成新的 `updated_at`，无业务变化保留原时间。格式整理后的系统字段同步不能导致下一次撤销被误判成用户篡改时间戳。

业务字段包括 `key_message`、`elements`、`layout`，仍受现有 Schema 限制。页面标题、章节、角色由大纲管理，不能借本编辑器写入 Spec 的额外字段。

Spec 保存成功后刷新结构化预览。如果业务 hash 改变，沿用 materialization 派生状态把已有幻灯片标记为待同步；如果只改变格式，则保持业务 hash 和同步状态不变。无 HTML 时继续显示未生成，不为了“同步”创建 HTML。

### 7.2 HTML

源文件编辑的是保存于 `index.html` 的原始内容，不读取 iframe DOM 或包含运行时注入的 `outerHTML`。前端格式化不替代服务端验证。

抽取并复用当前 HTML 创作约束的公共校验函数，避免仅 Agent 工具调用了 `ValidateHTML` 而 HTTP 手动保存绕过。必须存在真实的 `.slide-stage` 元素；不能只靠注释或字符串包含 `slide-stage` 通过。遵循既有禁止静态页码等约束；结构校验不进行浏览器渲染或外部资源访问。

布局溢出、资源下载失败、脚本运行错误不作为保存门槛。保存后的预览沿用 `IsolatedSlidePreview`、主题和运行时页框，不扩大 iframe 权限，不增加 `allow-same-origin`。编辑器中的草稿不执行。

HTML 字节变化后刷新 `html_hash`、主预览及缩略图；不能把手动保存伪装成已完成 `render_slide`，也不能自动更新或伪造 materialization proof。旧证明可能变成 `unknown`，但只要文件可读仍可预览。格式化本身改变 HTML 字节时也遵循此规则。

任何 HTML hash 变化都使旧 DOM 选择会话失效，沿用现有重建、拒绝迟到回包和引用过期处理；加载新画面期间可以保留旧画面，但不能继续接受其元素标记。

## 8. Agent 互斥与启动门禁

### 8.1 Agent 活跃时禁止编辑

互斥范围是整个项目，不是当前页、当前对话或本次 Agent scope。前端按项目汇总各对话的活动状态，覆盖创建中、运行中、等待确认、暂停、恢复中、取消中；服务端以非终态 Run 为权威。任务停止并确认终态前不恢复编辑。

读取、选择文字、复制、滚动、查找仍可使用。禁用键入、粘贴、拖放、替换、缩进、撤销重做、格式化以及保存，不能只灰掉保存按钮。CodeMirror 同时设置 `EditorState.readOnly` 与 `EditorView.editable`，并在应用命令层阻止改文档操作。

从本窗口启动 Agent 时，先完成第 8.2 节检查，再立刻设置项目级 `starting` 门禁，随后发送请求；请求失败后恢复相应状态。其他窗口启动后，通过现有任务同步尽快更新只读状态；状态传播前发生的保存仍由后端拒绝，不能依赖前端按钮保证互斥。

Git 提交、项目恢复、导出以及其他正在持有项目写锁的操作也沿用现有项目操作门禁。失败或无法确认项目写状态时保持只读，提供重试读取状态的途径。

### 8.2 有草稿不能启动 Agent

新增公共 `assertProjectSourcesSaved(projectId)`，供实际启动请求的统一入口调用，不只在发送按钮外观上检查。检查当前工作区该项目所有文件，切回预览或切到没有草稿的另一页不能绕过。

检查覆盖新建 Run、再次生成、失败重试、历史输入重发，以及项目上下文内会启动 Agent / 模型任务的命令；讨论、计划、盘问也使用同一规则。只读查看历史、停止任务等控制动作不受该门禁阻止。

任一文件 dirty、保存进行中、恢复索引尚未完成或保存结果待确认时，禁止启动。输入区显示「有 N 个源文件尚未保存，请先保存」，提供「查看」和「保存全部」，保留用户已输入的消息。没有「忽略修改」「仍然继续」或自动保存并发送分支。

全部保存后恢复提交入口，由用户再次提交。用户通过正常撤销使文本回到已保存基线时也视为无未保存修改。已经隔离的历史草稿副本不算活动草稿，不阻塞新现场创作。

后端并不知道浏览器尚未上传的本地草稿，因此该草稿门禁是工作区客户端规则；服务端强制保证的是正式文件保存与活跃任务互斥。不要用一个由客户端自报的 `dirty=false` 字段宣称实现了跨设备草稿校验。

## 9. 外部更新、冲突与失败

本节按用户明确要求采用“直接显示最新内容”。同文件更新会替换尚未保存的本地内容；不保留一个隐藏的合并分支，也不提供差异面板、合并编辑器、强制覆盖或冲突草稿恢复按钮。只有项目历史切换适用第 10 节的历史副本规则。

| 事件 | 行为 |
| --- | --- |
| 最新源文件 hash 与基线相同 | 保留输入、光标和撤销栈，不因轮询重新设置文本 |
| 已确认同文件外部 hash 改变 | 读取最新原文成功后替换编辑器、更新基线、清除旧草稿和撤销栈，提示「文件已更新，已加载最新内容」 |
| 保存返回 `CONTENT_CONFLICT` | 取消此次候选；自动重新读取最新原文并应用上述替换，不重试覆盖 |
| 已知外部更新，但读取最新失败 | 旧内容暂留只读，显示更新失败及重试；在成功取得新原文之前不提前删除本地草稿，也不能继续提交旧基线 |
| 格式化或校验失败 | 正式文件不变，保留用户原输入，显示行列或字段定位 |
| `RUN_ACTIVE` 或其他项目忙 | 保留草稿，进入只读；任务结束后重新读取文件，再决定保留相同基线草稿或加载最新 |
| 网络错误、超时、5xx | 不假定未保存；进入结果待确认并重读。仍是旧基线则保留 dirty 并允许重试；已变化则采用正式最新内容；重读失败继续保留草稿和错误状态 |
| 文件被删除 | 显示缺失，清除对应活动草稿，禁止迟到请求创建文件 |
| 历史现场变化 | 中止当前请求，先按历史切换规则隔离草稿；不走普通外部更新直接丢弃路径 |

每次打开源文件、窗口重新获得焦点、可见性恢复、Agent 持久化写事件、任务终态、保存冲突时都应核对当前源文件。当前源文件与本项目 dirty 文件纳入既有可见项目检查周期；同文件合并请求、同项目不重叠调度，页面不可见时停轮询。

Spec 仅改变格式或时间戳时，项目业务快照可能完全不变，所以必须直接核对源文件字节 hash，不能只订阅 `snapshot.hashes['spec:<id>']`。只需要读取已打开或有草稿的文件，不轮询整份项目的所有原文。

读取、诊断、格式化、保存响应都校验 resourceKey、现场和请求代次。迟到的相同旧 hash 响应不得回滚新基线；源文件刷新不能只用 React 挂载状态判断是否可接受结果。

## 10. 撤销、checkpoint 与历史草稿

正常输入、格式整理、保存、切页保留当前会话撤销能力。保存后撤销业务内容产生新草稿，需再次保存才改变正式文件。外部更新清空旧撤销历史，避免一次 `⌘Z` 把被替换的过时内容重新放回来。

手动保存不新增单页版本列表、不新增可见 checkpoint 条目，也不恢复 `artifacts/versions`。保存后的正式文件自然进入后续 Agent 任务前的项目 checkpoint；历史回退覆盖正式文件时遵循既有项目语义。

执行项目回退 / 恢复最新前，立即暂存并把该项目活动草稿写成历史草稿副本，绑定原 `scene_revision`、原基线及时间。备份失败时不执行本窗口发起的历史切换，保留输入并提示重试。切换成功后新现场重新读取正式内容，编辑器撤销栈重新建立，不自动附加旧草稿。

保留一个轻量「历史草稿」入口，仅在存在副本时出现在源文件工具栏更多操作中。列出页标题、文件种类、原现场时间，允许只读查看、复制和明确删除；不提供差异比较或一键覆盖当前文件。用户需要重新使用部分内容时，复制后在现有文件中编辑并按普通保存流程处理。文件不存在时仍不能从副本创建。

历史副本与普通冲突明确区分：它用于用户已确认的项目历史恢复能力；普通同文件外部更新仍直接清除旧草稿。服务端 `scene_revision` 的变化优先于内容 hash 比较，即使回退后的字节恰好相同也不能接收旧现场的保存回包。

新的 `content_mode` 随工作区路由与历史 scene 共同保存和恢复。UI 模式、光标与本地草稿不写进作者文件 Schema；前后端 scene 类型一次性更新，不迁移历史开发数据、不增加旧字段双读。

## 11. 后端接口合同

### 11.1 原文读取

新增统一的编辑器专用端点，保留当前预览读取端点的职责：

```http
GET /api/v1/projects/:id/slides/:slide_id/source?kind=spec|html
```

```json
{
  "project_id": "pro_example",
  "slide_id": "sli_example",
  "kind": "spec",
  "path": "slides/sli_example/spec.json",
  "language": "json",
  "content": "{\n  ...\n}",
  "source_hash": "sha256:...",
  "content_hash": "sha256:...",
  "scene_revision": 0,
  "writable": true,
  "readonly_reason": null
}
```

示例中的 `content` 仅缩写展示协议，实际必须返回完整原文。`source_hash` 对本次读取的 UTF-8 字节计算；Spec 的 `content_hash` 使用现有业务 hash，无法解析时为 null；HTML 两者相同。可选诊断用于说明已有文件问题。

服务端只接受 kind 枚举并由稳定 ID 构建路径，验证项目存在、页面属于该项目且在当前 outline 中、文件未缺失；不接受用户传入的路径。读取磁盘正式文件，不读正在构建的 Agent 内存 overlay，不读取运行时生成的 DOM。

原文、hash 必须来自同一次读取。读取前后核对历史现场标识与“现场正在切换”状态：切换过程中返回 `HISTORY_BUSY`，场景标识已变化则返回现场冲突，由前端重读。历史管理器应提供轻量的切换中状态，不能只比较尚未提交的 `scene_revision`，以免把恢复中的新文件配上旧现场标识。普通 GET 不抢占项目排他写锁，也不因无关的普通写操作而一律失败。`writable` 仅为读取时提示，保存必须重查。响应 `Cache-Control: no-store`，内容包装为 JSON 字符串，编辑器不可把它直接注入应用 DOM。

现有 HTML `ReadHTML` 的原始字节读取逻辑可以抽为共用读取函数；新统一端点增加编辑所需元数据，不让前端分别请求 hash 和文本再自行拼接基线。

### 11.2 原文保存

```http
PUT /api/v1/projects/:id/slides/:slide_id/source?kind=spec|html
Content-Type: application/json
```

```json
{
  "content": "完整的格式化候选原文",
  "expected_source_hash": "sha256:读取时的原文件hash",
  "expected_scene_revision": 0
}
```

`expected_source_hash` 必填且不允许空值；`expected_scene_revision` 必填，零是有效初始现场，不可与字段缺失混淆。两个前置条件职责不同：前者保护文件内容，后者阻止旧历史现场请求回写。

成功返回：

```json
{
  "changed": true,
  "document": {
    "project_id": "pro_example",
    "slide_id": "sli_example",
    "kind": "html",
    "path": "slides/sli_example/index.html",
    "language": "html",
    "content": "实际已保存原文",
    "source_hash": "sha256:...",
    "content_hash": "sha256:...",
    "scene_revision": 0,
    "writable": true,
    "readonly_reason": null
  }
}
```

正式写入后的文本和 hash 是权威回执；前端随后刷新项目内容快照。快照或预览刷新失败单独显示，不把已经完成的文件保存重新标成 dirty。

不把字节 hash 填进现有 mutation 的 `expected_hash`：它对于 Spec 是业务 hash。新端点使用明确的 `expected_source_hash` 名称，既有 Agent 工具协议和业务指纹保持不变。

### 11.3 写入顺序与持久化

1. 沿用 `projectHistoryGate` 的项目归属、串行门禁和恢复逻辑，先确定项目上下文；新源文件 PUT 将真正的历史分叉确认与 `BeginMutation` 延后到确认存在字节变化之后。
2. 在项目锁内检查 Run、Git 提交、导出和冲突操作；前端传来的可写状态不可信。不得仅检查当前线程。
3. 重新确认场景标识、outline 成员和目标文件存在；此端点严格为更新，不能借用允许创建文件的路径执行 upsert。
4. 从当前源字节计算并比对 `expected_source_hash`，再验证系统字段与完整候选内容。
5. Spec 以服务端规范结构输出。业务内容变化才刷新 `updated_at`；纯格式变化可以写文件，但不更新业务 hash 或失效清单。HTML 写入前端提交且通过校验的格式化候选。
6. 对完全相同的最终字节返回 `changed: false`，不改文件、不推进项目历史、不丢弃后续历史；用户修改后又改回原文也不得刷新业务时间。原文未变的保存不弹出历史分叉确认。
7. 有实际变化时，调用提取复用的历史确认 / `BeginMutation` 逻辑；需要确认则先返回既有错误码，尚不写文件。确认后仍在同一门禁内校验原基线并开始写入。不能为了沿用原中间件而让无变化保存提前丢弃后续历史。
8. 单次保存只修改一个已有作者文件。用同目录临时文件、flush / fsync、原子 rename 及目录同步替换，不直接复用目前 `Sandbox.Write` 的 `os.WriteFile` 覆写方式。
9. 新端点不改变页面身份、outline、materialization proof 或 SQLite 页面成员，因此不需要创建虚假的 Run 或复用带 `run_id` 的工具提交 receipt。
10. 文件持久化及既有历史门禁结算成功后才返回成功。历史分叉失败按现有 journal 恢复；若文件替换后历史结算或回包失败，属于“结果待确认”，前端重读，不能承诺失败响应必然代表原文件未变化。

写锁、读取前置条件、文件替换必须处于同一受保护流程。项目历史门禁与项目写锁保持既有获取顺序，不能反向获取导致死锁。代码复用以提取校验和读取函数为主，不能绕过原文基线校验调用宽松 mutation。

文件原子替换保证读者只读到完整旧文件或完整新文件，不承诺一次「保存全部」里的所有文件一起成功。直接使用外部编辑器改磁盘不受应用锁管理；打开和保存时核对 hash 能发现已完成的外部变化，不把本能力宣传为与任意进程的协同编辑协议。

### 11.4 错误合同

| HTTP / code | 含义与前端处理 |
| --- | --- |
| 400 `SOURCE_REQUEST_INVALID` | kind、请求结构或前置条件缺失；不写文件 |
| 404 `SOURCE_NOT_FOUND` | 页面或源文件不存在；显示缺失，不创建 |
| 409 `CONTENT_CONFLICT` | 字节基线已变；重新加载最新内容 |
| 409 `SOURCE_SCENE_CHANGED` | 历史现场已变；走现场切换和草稿隔离 |
| 409 `RUN_ACTIVE` / `GIT_COMMIT_ACTIVE` / 既有项目忙代码 | 禁止写入，进入只读并重新核对项目状态 |
| 409 `HISTORY_CONFIRM_REQUIRED` | 沿用已有“丢弃后续历史”确认，不增加第二个确认弹窗 |
| 422 `SOURCE_VALIDATION_FAILED` | JSON、Schema、HTML 结构或系统字段问题，保留输入 |
| 网络 / 超时 / 5xx | 保存结果可能不确定，按第 9 节重新读取确认 |

422 的 details 包含 `diagnostics[]`：稳定错误 code、message、可选 JSON Pointer、可选行列范围。前端不能用英文错误字符串猜测字段位置。返回位置以提交候选为坐标；格式化前后行数不同时需映射回原草稿，JSON 优先用 Pointer 定位，无法可靠映射时只展示字段级错误，不标错行。

历史确认取消只取消本次正式保存，保留草稿与输入；不在后台继续保存，也不自动启动任务。确认重试仍携带原基线和场景，期间文件或现场变化必须重新读取。

## 13. 实施顺序

1. 增加服务端原文读取 / 保存合同，完成页面归属、字节 CAS、场景保护、只更新已有文件和原子替换；提取必要的校验函数。
2. 引入 SourceEditor、文件模型与本地草稿存储，打通保存、自动格式化、错误定位与本人保存后的撤销行为。
3. 接入中间栏双维切换、文件状态、草稿导航、保存全部与模式专属工具栏。
4. 接入项目级 Agent 活跃只读、统一启动门禁、快捷键、外部刷新、场景恢复与历史草稿。
5. 完成下节定向行为验证和用户手动验收，确认没有扩大为任意文件编辑器。

每阶段最终合入的是同一完整能力，不能只做可输入的编辑框而遗漏后端写入保护或任务启动门禁。本任务当前仅产出设计文档，不执行上述产品开发。

## 14. 验证与验收

遵循仓库约定：不使用 Computer Use / Browser 自动化；交互与视觉由用户手动验收。以下为未来实施需要完成的检查，不表示本次已经运行。

### 14.1 必要的行为测试

集中覆盖容易出错的状态和并发，不为图标、静态文案或纯样式新增测试。

- 原文读取返回的文本与字节 hash 一致；Spec 格式变化不会改变业务 hash；错误项目、越界 kind、缺失文件不能读取或创建。
- 必填前置条件、旧字节基线、旧历史现场、活跃 Run、并行保存与页面删除均不能产生错误覆盖。
- 严格 JSON、重复键、系统字段、Schema 和 HTML 根容器校验；失败时不写正式文件；只含注释 `slide-stage` 不能通过。
- 原子替换前故障保留原文件；回包中断和替换后错误进入结果待确认；重读 / 重试不会盲目覆盖新内容。
- 无变化保存不修改项目历史或要求丢弃后续历史；真正写入仍沿用原确认规则；现场切换中的读取不能返回新文件加旧 scene 的混合结果。
- 同文件保存成功保留用户撤销；旧格式化结果、旧读取响应、跨页响应不会覆盖更新的内容；本人保存不被识别为外部冲突。
- 外部变化直接采用最新并清掉旧草稿 / 撤销，重读失败保留输入且只读；Spec 仅格式变化仍能触发原文更新。
- 所有页面的 dirty 文件、保存中与恢复中都会阻止任务启动；切页、快捷键和失败重试不能绕过；保存全部部分失败不启动任务。
- 只读期间粘贴、替换、撤销和 API 命令均不能改文档；终态确认后重新核对源文件再解除只读。
- 草稿跨导航及刷新恢复，旧异步 IndexedDB 写不能复活已清除草稿；历史切换隔离副本并拒绝旧现场保存。
- HTML 自动格式化含内嵌 CSS / JS；关注中文行内文本、相邻 inline 元素、`pre` / `textarea`、SVG、脚本字符串、已有运行时资源引用和异常格式输入。

### 14.2 用户手动验收清单

| 场景 | 预期 |
| --- | --- |
| 四种对象 / 查看方式组合 | Spec 与 HTML 不串文件，预览显示正确对象，图标为 FilePen / AppWindow |
| 窄工作区 | 两组切换可辨识，文件栏不撑开，编辑器可以独立滚动 |
| 修改后等待、失焦、切页 | 正式文件和预览不变，草稿自动暂存，返回后内容与位置保留 |
| 点击保存 / ⌘S / Ctrl+S | JSON 和 HTML 自动 format，成功后刷新预览，浏览器不弹保存网页 |
| 不合法 JSON / 缺根容器 HTML | 不落盘，保留输入，错误位置或字段可识别 |
| 多页各有草稿后切到第三页发送 | 发送被阻止，能查找全部未保存文件并保存，输入消息保留 |
| Agent 运行、等待审批、暂停、取消中 | 源文件保持只读；停止到达终态后才可编辑 |
| 另一窗口修改当前文件 | 当前窗口直接载入最新，无对比弹窗，旧草稿和撤销不再出现 |
| Spec 业务修改 | 设计稿预览更新，已有幻灯片待同步，不自动生成 |
| HTML 修改或仅格式化 | 幻灯片更新、旧选区失效，不反写 Spec，不假报渲染通过 |
| 文件尚未生成或后来被删除 | 空态无创建按钮，保存请求也无法重建 |
| 保存后撤销 | 恢复业务编辑前内容，产生未保存草稿，再次保存才生效 |
| 刷新与项目历史回退 | 普通刷新恢复同基线草稿；历史回退载入目标正式文件，旧草稿仅在历史副本入口可找回 |
| 网络中断、暂存失败、保存回包丢失 | 状态清晰，不虚报已保存，不丢失尚未取得替代内容的本地输入 |

用户执行范围建议：前端类型 / 构建检查；新增编辑器状态、草稿与保存门禁定向测试；后端原文接口、校验和历史门禁定向测试。通过后无需反复运行全量测试或追求覆盖率。
