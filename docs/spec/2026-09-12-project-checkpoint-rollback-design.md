## 1. 需求与依据

支持从用户消息回到该次任务发送前，完整撤销此后项目文件、会话历史、模型上下文和界面状态；允许连续向过去回退，但只允许一次恢复到首次回退前的最新现场。继续创作后丢弃旧未来，只保留单条历史。

本设计以本轮用户决定为准。已直接阅读 AGENTS.md、TODO.md、当前仓库和 Git 历史，没有使用 subagent。核对基线为 d28c4cc，相关提交包括 37c5c09（提示词合同）、4cd21af（导出）、da3c686（DOM 引用）、5a1b8cc（图片）、431ee15（范围选择）、90c094d（工作账本），并查看 fd3b87e 的历史文件为真相改造。历史设计不能替代当前代码。

设计时（d28c4cc）的已有能力和缺口：

- `backend/internal/workflow/checkpoint.go` 与 SQLite `run_checkpoints` 是运行中断恢复协议，不是项目时间快照。
- `backend/internal/service/slide.go` 的 RollbackSlide 只恢复 HTML、产生新版本并清除 materialization，不能实现整项目回退。
- `backend/internal/workflow/session.go` 提供 Run 写入 overlay，`service/workflow_commit.go` 提交产物及版本；项目 Checkpoint 需要覆盖更广的状态。
- `service/thread.go` 的 History 会合并 history 文件、steering、Git 操作、简报及压缩记录。仅截断 history 文件会使后续记录重新出现。
- `contextengine/transcript.go` 独立保存模型 transcript，压缩会替换内容，不能仅按消息数量裁剪。
- `run/lock.go` 已有项目执行锁，但实现时还必须审计所有项目写入口是否接入统一互斥与分支确认。
- `frontend/src/features/agent/Timeline.tsx` 已有用户消息复制按钮；新回退按钮放在其右边。
- composer 草稿、引用、范围以及 run timeline 分散在前端 store，必须统一切换，不能仅更新页面文件。

## 3. 时间模型与状态机

### 3.1 定义

- Checkpoint 对应一个 Run，保存发送前完整基线、原始输入封套与终态关联。任务结束后开放回退入口，即使文件未变也须有记录。
- 发送前指服务端接受并持久化本条用户消息之前，不能等到模型调用或工具写入后才截图存档。基线创建必须处于项目互斥范围。
- 项目内按真实操作顺序形成唯一时间边界。时间戳用于显示，服务端使用项目单调序号区分同一毫秒的操作；不依赖客户端时间、不按会话分别截断。
- 最新现场指首次回退操作前的完整状态，不等于最后一个成功 Run 的结束状态。
- 完成状态快照与发送前基线分开表达，避免把“回退 cp2”误解成恢复 cp2 完成后的产物。

### 3.2 单历史

正常状态可回退任一仍在当前历史内且已结束的 Run。首次回退保存唯一最新现场，切换到目标发送前，并回填目标输入。

已回退状态允许选择当前可见的更早 Run；不覆盖首次保存的最新现场。后续 cp 不出现在列表、timeline、上下文及正常查询中，服务端也拒绝对其直接恢复或回退。

点击恢复并确认：一次恢复首次保存的现场，恢复原始时间戳及所有可见入口，退出回退状态。恢复不产生新的创作 Run，不改写历史事件时间。

例：cp1 → cp2 → cp3 → cp4。在 cp2 回退后，内容为 cp2 发送前，输入框为 cp2，cp2 原执行过程及 cp3/cp4 隐藏。可再回退 cp1，但只能恢复到原 cp4 后的现场。恢复后才可再次选择 cp2/cp3。

已回退状态下开始持久化修改，必须先确认丢弃旧未来。取消确认不产生业务写入。确认只针对预览时的历史版本；并发变化使确认失效。旧未来应在新操作被可靠接受时失去恢复资格，不应因请求校验失败就无故丢失；后续 Run 执行失败也不重新开放旧分支。

## 4. 快照覆盖范围

实现需建立显式资源清单并审计读写入口，不允许全库回滚牵连其他项目。

| 范围 | 恢复要求 |
| --- | --- |
| 创作文件 | manifest、outline、design、页面 spec/HTML、项目内公共资源、素材及引用、版本快照与必要元数据；恢复改动及删除，移除目标之后新增内容。 |
| 页面状态 | 页面成员、顺序、版本关系、materialization 证据一致恢复；根据恢复后的文件重算状态，清除错误缓存。 |
| 会话 | 项目所有会话的成员与必要元数据、历史文件、Run、事件、steering、计划、账本、关联记录与时间戳；目标之后创建的会话从当前视图移除，恢复时带回。 |
| 上下文 | 完整 transcript、压缩结果及记录、上下文索引/manifest、窗口快照等影响下一次组装的状态；不允许未来摘要泄漏。 |
| 衍生记录 | 简报及版本、版本列表、Git 操作展示记录等按同一边界恢复可见性。真实 Git commit/分支不反向改写。 |
| 输入 | 目标原始文字、模式、模型选择、范围、图片、DOM 引用及顺序、相关资源选择；保存完整输入，不以展示摘要反推。 |
| 前端 | 所有受影响会话 store、timeline、耗时/时间展示、当前页、缩略图、预览、上下文窗口、草稿与引用状态一致刷新。 |
| 排除 | 个人库、全局配置、真实 Git 历史、项目外副作用；导出临时任务、临时渲染缓存不作为需原样复活的创作内容。 |

图片上传发生于发送前，基线应保留已上传图片；撤回的图片引用不能继续出现在当前模型上下文。旧未来保留期间，其恢复必需的字节不得被垃圾回收。回填 DOM/图片/Scope 在再次发送前重新校验，失效时明确提示，不静默丢弃或自动定位到其他对象。

草稿现场必须进入持久化恢复数据，不能仅保存在 Zustand 内存中。跨会话回退后若当前选中会话/页面不存在，选择仍有效的会话/页面；不存在页面时显示正常空态。目标消息所在会话在其发送前应存在，回填到该会话。

## 5. 服务端实现约束与建议

以下是为实现已确认行为提出的工程设计，字段和路由可在实现时按仓库规范调整，但不能改变产品语义。

### 5.1 独立项目历史协议

新增 ProjectCheckpoint、ProjectHistoryState、ProjectSnapshot 等项目级模型，不复用 RuntimeCheckpoint 作为完整快照。至少记录 project_id、run_id、时间边界/序号、基线引用、终态引用、完整输入、当前历史 revision、最新现场引用与快照完整性摘要。

快照存放在不属于活动创作目录的独立区域，防止递归快照、Agent 读取未来、Git 自动暂存备份和导出打包旧资源。禁止使用 Git reset/checkout 作为跨文件与数据库的唯一恢复机制。

### 5.2 查询与命令

提供项目历史状态查询、回退预览/执行、恢复预览/执行。执行请求携带目标 Run、expected revision、幂等操作 ID 及必要草稿现场。预览返回服务器权威时间、影响计数和变更概览；预览不修改项目。

回退、恢复、丢弃旧未来与正常写操作使用同一项目并发门禁。后端验证任务终态、目标是否仍在当前历史、revision、快照完整性、冲突任务和操作；不能只靠禁用按钮。

统一拦截项目持久化修改，尤其审计上传、手动编辑、会话增删改、简报、压缩、Run 创建、单页回滚等旁路。纯查询、切页、文字草稿编辑不创建新历史。临时缓存写入不能被误判为用户开始新分支。

### 5.3 一致性与崩溃恢复

文件系统与 SQLite 无法靠一个普通 DB 事务同时提交。实现必须选择可恢复的切换方案：先完整准备并校验目标快照，再持久化操作日志与前态备份，在项目互斥下切换文件及数据库，成功后发布新的历史 revision。中途失败恢复前态；进程崩溃后，开放项目读写前先完成或撤销未结束切换。

失败不能留下“页面回到了过去、上下文还在未来”的状态。快照失败不开放不完整的回退入口；错误可见，不假报成功。保留唯一最新现场直到恢复成功或新分支被可靠接受；清理备份失败不能破坏活动状态。

恢复不能把隐藏的已结束 Run 重新标成正在运行，也不能让旧幂等记录误拦新输入。须审计 Run 生命周期、任务查找、SSE 重放、工作账本及上下文检索的可见性。

## 6. 前端交互

任务起始用户消息复制按钮右侧增加回退按钮。追加指令没有独立入口；按钮应依据服务端 Checkpoint 可用性和任务终态，不以有没有产物判断。

回退弹窗：说明“回到此消息发送前”，展示时间、输入摘要、影响会话/任务数量、文件新增/修改/删除概览、草稿替换提示及可以恢复到最新的说明。点击确认后才执行，期间防重复操作。

回退成功后，timeline 不保留目标原始用户消息及其执行过程；目标输入完整回填 composer。在输入框上方固定显示“已回退”和“恢复到最新”。恢复弹窗显示最新现场时间、影响概览和替换草稿说明。

新分支确认弹窗用于已回退状态的首次持久化修改：清楚说明将丢弃旧后续记录及恢复入口，取消不落盘。图片选择/粘贴需在实际上传前接入该流程。

状态切换后按服务端 revision 重新加载整个受影响项目视图；取消旧订阅、失效旧异步请求，禁止旧 SSE、请求响应和缓存再次合并未来内容。时间、耗时、活动任务、上下文 token 展示来自恢复后的记录，不能沿用被撤销任务的计时器。

不增加独立 Checkpoint 管理页、历史完整交互预览、任意中间恢复、多分支或历史开发数据迁移。按 AGENTS.md 统一切换协议，不保留新旧双读双写。

## 7. 分阶段开发与验证

1. 建立项目时间边界、快照资源清单及存储模型；完成完整输入保存、Run 基线/终态接入。
2. 完成回退/恢复、唯一最新现场、项目写门禁、崩溃恢复和跨会话/上下文的一致切换。
3. 完成复制按钮右侧入口、三类确认弹窗、回退状态栏、输入回填和前端全量状态失效。
4. 完成集成验证、故障验证、文档与 TODO 更新。仅在实际功能及验证完成后勾选 TODO。

阶段划分不是部分交付许可；开发任务需贯通全部范围。允许在开发启动 prompt 明确授权下分阶段 commit，每次先检查 status/diff，以具体中文信息说明变动和验证；不 push。

验收至少覆盖：

- cp1–cp4 示例、连续回退、仅一次恢复到最新、恢复后再次回退中间任务。
- cp1 后手动修改再发送 cp2：回退保留发送前修改；cp4 后手动修改能随最新现场恢复。
- 纯聊天、失败、取消、第一条 Run 可回退；steering 与原任务整体撤回。
- 多会话交错、同时间戳顺序、后建会话撤回/恢复，无未来对话和简报回流。
- 文件新增/修改/删除、页序和视觉要求、素材、版本与 materialization 一致。
- 压缩后的上下文回退/恢复，下一次模型组装不包含旧未来内容。
- 图片和 DOM 输入恢复、草稿替换与原草稿恢复，失效引用校验。
- 浏览不失效恢复；持久化修改取消无副作用、确认后旧未来不可恢复；校验失败不误丢历史。
- 运行/等待/暂停以及导出/压缩占锁时拒绝；重复请求幂等、过期确认和并发请求拒绝。
- 刷新与服务重启仍能恢复；文件/DB/磁盘写失败及切换中断后不出现半恢复。
- 旧 SSE、延迟响应及前端缓存不复活旧 timeline、计时和上下文展示。

测试应覆盖真实状态切换与负面路径，不以静态文案测试代替整体一致性。按改动运行 Go/前端相关测试及构建，报告已验证和未验证的边界。

## 8. 实施记录（2026-09-13）

### 8.1 实际协议与落点

- `backend/internal/projecthistory/` 实现独立的项目基线、历史状态、完整快照与切换日志，不改变 `workflow.RuntimeCheckpoint` 的语义。
- 快照位于工作根目录的 `project-history/<project-id-sha256>/`，不位于项目工作目录。快照以内容 SHA-256 命名并校验，保存项目位置、创作文件字节/权限、显式数据库清单、时间边界与界面现场。
- 每次 Run 完成请求校验后、创建 Run/上下文记录和启动执行前保存基线；服务端毫秒时间用于展示，项目递增 sequence 确定先后。终态由当前数据库 Run 决定，不复制一套终态状态机。
- API 为 `GET /projects/:id/history`、`GET /projects/:id/history/preview?run_id=...`、`POST /projects/:id/history/switch`；省略 run_id 表示恢复最新。切换携带 revision、operation_id、scene。状态查询只投影可见终态入口，不轮询传输全部历史输入。
- 所有项目 HTTP 创作入口统一通过项目门禁，包括线程、上传、内容修改、单页回滚、简报、压缩、Run 创建及 Git 操作；项目、线程、Run、页面与 Git 展示读取也通过门禁。全局库不属于项目历史。
- 已回退时，服务端在请求绑定和业务写入前返回 `HISTORY_CONFIRM_REQUIRED`。前端确认后携带 `X-Discard-Future-Revision` 重试；取消不重试。校验失败撤回部分业务写入并保留旧未来。Run/Git 后台任务通过启动屏障，在接受标记持久化后才开始执行。
- 切换过程先保存前态和 journal，再恢复文件并同步文件/目录、事务替换 SQLite 项目行，最后发布新 revision 和操作标记。中断时根据标记保留已提交状态或恢复前态；启动开放 HTTP 前扫描 journal，项目删除导致数据库行消失时也可从已校验前态恢复。未完成恢复的项目不开放正常读写。
- 最新现场仅首次回退保存，连续回退不覆盖。新创作可靠接受后清除 latest，按当前基线及唯一最新现场的可达关系清理无用快照；清理失败延期，不撤销已接受的创作。

### 8.4 已知边界

- 开发期直接启用：旧 Run 没有发送前基线，无法事后可靠重建，不迁移、不伪造旧入口。新增 Run 均走新协议。
- 当前为完整 JSON 快照，文件字节在 JSON 中编码；项目越大、历史越长，磁盘及瞬时内存开销越高。尚未实现跨快照文件块去重、配额或历史保留期限。
- 回退保护产品 API 内的项目操作；外部编辑器或进程绕过项目门禁直接修改工作目录，不具备跨进程隔离。单个后端实例负责当前工作根目录。
- 真实 Git、外部操作、全局配置与个人库不回退；因外部资源删除而失效的回填引用须重新选择。
- 完整文档重载有一次短暂加载过程，用于彻底清除跨 store/iframe/订阅的旧现场。服务端恢复现场持久化，不依赖进程内存。
- 生产构建仍有项目既有的大于 500 kB bundle 提示；本次不调整整站拆包策略。
