# normal 输入触发的异步自动命名

## 状态与依据

- 日期：2026-10-17。
- 用户已确认方案，代码已实施；构建、测试、模型实测和运行验收交由用户手动完成。
- 参考最新提交 `5311f7c3`、`1ebc0b40`、`ce8f40d4`，当前输入分流、自动命名、命令状态与项目历史代码。
- 补充 `2026-10-17-jev-intent-routing-design.md` 的命名联动规则；本次决定优先于其中“既有自动改名业务规则保持原样”的旧描述。

## 问题

同一会话的首条 NBA 查询被正确识别为 `irrelevant` 并返回固定回复，但输入接受路径已提前启动自动命名。随后提交的新请求在保存项目历史基线时，被仍在运行的命名命令拦截，底层 `ErrBusy` 又被包装为 HTTP 500。

自动命名的模型请求已在后台执行，但触发时机早于分类结果，且命令状态仍参与主任务的忙碌判断。

## 触发与计数

- 仅在安全检查通过、最终分流结果为 `normal` 且判断已持久化后，提交自动命名任务。
- 新请求与普通输入框追加指令遵循相同规则；不在 HTTP 输入接受路径登记命名。
- `greeting`、`identity`、`irrelevant`、内部指令拒绝、绕过规则拒绝和检测失败，均不触发命名、不消耗首次命名资格，也不增加命名输入计数。
- `normal` 仅表示具备触发资格。首个有效输入使用首次命名策略；后续有效输入仍由既有 Jev 命名判断决定是否值得调用生成模型。
- 复用已有 `naming_input` 幂等记录，同一有效输入重试或恢复后只计数一次。首条输入与追加输入使用不同标识，接力到新 run 的输入沿用原始身份，不重复计数。
- 后台登记再次检查持久化的 `normal` 结果及 run 执行版本；已删除或被历史恢复替代的任务不能迟到登记命名。

## 异步边界

```text
用户输入 → 风险与意图识别 → 保存判断
                           ├─ normal → 主任务继续
                           │           后台登记、命名判断、模型生成、名称落库
                           └─ 其他分类 → 原固定回复或停止流程
```

- 分类路径只发起后台任务，不等待命名计数、命令登记、命名判断或生成模型。
- 命名使用独立的服务上下文、既有超时和取消机制；慢请求、失败和超时不改变主 run 的状态，也不令后续请求失败。
- 命名不占用主 run 的项目执行锁；项目历史忙碌检查排除 `kind=rename, source=automatic`，其他冲突命令、活动 run 与导出仍沿用既有约束。
- 命名登记、进度、名称应用和终态落库仅在短暂写入阶段参与快照保护，模型请求期间不持锁。
- 保留用户手动改名、关闭自动命名、项目删除和历史切换的取消与版本校验；迟到模型结果不得覆盖新状态。

## 命名材料

- 自动命名仅使用已持久化为 `normal` 的用户输入，以及这些任务的最终回复和计划进度。
- 待识别、寒暄、身份询问、业务无关和拒绝输入不进入自动命名材料。追加输入与接力输入按原始身份去重。
- 手动生成名称和后续建议继续使用原有完整上下文入口，不受本次自动命名过滤影响。
- 不增加 Jev 意图识别的材料块、调用次数或分类选项；不接入 `ask_user`。

## 项目快照与错误语义

- 允许自动命名在项目基线捕获期间继续进行模型生成，快照记录捕获时的状态。
- 恢复快照时，将其中活动的自动命名命令转为 `interrupted`，清除原执行权并提升执行版本；同一事务追加相应命令终态，恢复后按现有日志投递机制展示一致状态。
- 旧命名 worker 的迟到写入由操作版本、项目代际和命令执行版本共同拦截；不自动恢复旧模型请求。
- 其他活动命令仍不能被当作合法空闲快照恢复。
- 创建 run 时确有项目历史冲突，沿用明确的 `409 HISTORY_BUSY`，不再作为未知内部错误返回。
- 不新增数据库结构、历史开发数据迁移、兼容分支或前端提示块。

## 实施位置

- `backend/internal/service/input_decision.go`：持久化或复用有效判断后，仅调度 `normal` 的后台命名。
- `backend/internal/service/run.go`：删除新请求及追加接受后的提前命名触发。
- `backend/internal/service/thread_naming.go`：计数与命令登记后台执行，自动命名材料单独过滤，命令状态写入参与短暂快照保护。
- `backend/internal/store/sqlite/thread_naming_store.go`：校验有效分类、执行版本、原始输入身份，原子计数并生成自动命名材料。
- `backend/internal/store/sqlite/command_store.go`、`backend/internal/projecthistory/history.go`：区分阻塞命令与后台自动命名。
- `backend/internal/store/sqlite/project_snapshot.go`：恢复后中断快照中的活动自动命名，原子持久化终态并使旧 worker 失效。
- `backend/internal/httpapi/run_handler.go`：正确映射项目历史忙碌状态。

## 手动验收

1. 首条发送寒暄、身份询问、NBA 独立查询、内部指令索取，以及模拟检测失败，确认不启动自动命名；随后首条 `normal` 仍可触发首次命名。
2. 将命名模型保持在慢响应状态，完成当前主 run 后立即发送下一条输入，确认新请求创建、分类与执行均不等待命名。
3. 运行中追加上述非 `normal` 输入，确认不触发命名；追加有效演示要求正常计数，同一输入重试、恢复和接力不重复计数。
4. 检查自动命名材料只包含有效业务内容，手动生成名称和正常任务的后续建议继续按原流程工作。
5. 命名运行期间捕获基线并回退、恢复历史，确认命名记录成为中断终态，旧结果不覆盖名称，也不会阻塞后续 run。
6. 命名慢响应、失败、超时期间手动改名、关闭自动命名、删除会话或项目，确认旧结果不写回。
7. 真正的冲突命令仍遵守原有互斥，创建 run 的历史忙碌返回 `409 HISTORY_BUSY`。
