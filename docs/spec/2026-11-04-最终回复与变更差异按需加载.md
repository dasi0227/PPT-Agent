# 最终回复与变更差异按需加载

## 目标

执行完成后直接展示完整正文和「已更改 N 项内容」，移除最终回复底部用于补加载整条数据的「展开全部」。展开汇总显示变更清单，展开单项才请求该项差异。单项差异原有的高度折叠与横向滚动保持现有行为。

## 数据与读取

- `final`、直接回复 `message` 以及 `terminal_notice` 的时间线投影完整保留正文和变更清单，不进入通用的 32 KiB 整条摘要截断。
- `affected_targets` 保留资源身份、展示名称、增删统计，以及 `diff` 中的类型、状态和文件名。具体差异单独保存在既有 `timeline_details`，每项通过新增的 `diff_ref` 引用。
- `diff_ref` 复用现有内容引用格式，绑定会话、场景、父条目、条目版本和不可变详情 ID；全文接口只允许读取父条目当前变更清单中列出的引用。
- 复用 `GET /threads/:id/timeline/items/:itemId/detail?ref=...` 返回单项 `ArtifactDiff`，不增加接口或数据库表。
- 最终回复使用自身投影中的变更清单，避免将终态条目名下的引用拿到最终回复条目下读取。

## 前端行为

- 正文、汇总入口和变更项名称直接渲染；打开汇总不请求差异。
- 只有展开单项后才读取它的 `diff_ref`。详情缓存和加载状态按引用隔离，重新展开已加载项时复用缓存。
- 读取中展示现有加载图标，失败后展示错误和重试操作。会话刷新后，仍展开的单项可重新加载。
- 条目更新或删除时清理过期差异缓存；会话切换和场景变化继续使用共享 Store 的请求隔离。项目历史恢复同步重置引用中的场景版本。

## 交付边界

前后端直接使用新投影结构，不增加旧结构兼容分支，不迁移历史开发数据。本次没有重置开发数据库。

按项目约定未运行构建、自动测试或浏览器验证。人工验收重点：新任务完成后无需额外点击即可看到完整正文与变更汇总；打开汇总不加载差异，展开单项才加载；重试、重新展开、会话切换及项目回退后展示正确的差异。
