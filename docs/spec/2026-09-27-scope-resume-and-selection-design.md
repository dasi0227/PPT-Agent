# 恢复任务的有效范围与输入框选择

## 决策

依据 2026-09-27 用户决定：任务恢复完整的有效授权；已授权的页面不再申请扩权；输入框默认全部页，只有用户主动操作才改变选择。本决定替代此前按项目是否有页面自动选择当前页的行为。

## 后端

- `ResumeRun` 在组装上下文前读取并校验检查点中的完整 Scope；Runtime 也恢复 Scope，同步模型上下文和目标页集合，防止沿用空项目启动时的页集合。
- 恢复内容包括稳定页 ID、选择来源、本任务新增页授权及范围 revision。已提交扩权继续消费已保存的结果，不重新申请或重复递增版本。
- 保存检查点时，在同一条件写入中同步任务的 `scope_json`。新增页面更新有效页集合，不单独增加审批 revision，且不会使检查点和任务中的范围分离。
- 原子扩权提交要求传入范围与检查点范围完全相同，不能只比较 revision。
- 判断扩权时先取真正新增的页 ID；请求全部已在授权集合内时立即返回无变化，不受页面排序影响。确需扩权时保留原授权，包括已经删除的页 ID，避免隐式缩小权限。
- 保持现有权限边界：不依据 `all_pages` 标签无条件放行任意页面，仍依据有效页集合判断。

## 前端

- 移除根据页面数量设置默认范围的副作用及 `userTouchedTarget` 状态。
- 新项目默认全部页；页面生成、切换当前页和任务状态变化不改写范围选择；保存的草稿保留用户选择。
- 若用户选中当前页而页面不存在，保持选择并阻止提交，要求用户选择有效范围，不悄悄改为全部页。
- 扩权卡按实际页 ID 显示页码，标注“含本任务新增页”；没有页面、页面已删除及页码尚未加载分别表达，不再只用 `all_pages` 来源标签比较前后范围。

## 验证

- Runtime 恢复空项目启动后形成的有效页集合，直接编辑该页成功；已授权请求不发起审批。
- Runtime 恢复已经原子提交的扩权及待发布结果，不重复申请授权。
- 页面排序、删除不产生无效扩权；真正新增页不移除既有授权。
- SQLite 保存检查点后任务和检查点的范围一致；拒绝同版本但不同页集合的扩权提交。
- 输入框组件回归覆盖空项目生成页面、切页、恢复任务及手动范围选择；审批卡覆盖前后来源均为全部页但实际集合不同的显示。
- 相关后端回归、运行模块测试、前端 18 项相关测试和 TypeScript 编译通过。存储全量测试中的 `TestTagDictionaryUsesDatabaseNamesAndOrder` 失败，用 HEAD 版本的存储实现进行 Go overlay 对照后同样失败，确认是修改前已存在的问题。

不迁移历史数据，不自动修改已保存的输入选择；更新代码并重启后端后使用新恢复逻辑。
