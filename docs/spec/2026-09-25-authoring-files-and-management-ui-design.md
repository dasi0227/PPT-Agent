# 创作目录扁平化、结构化管理界面与 HTML 只读源码

日期：2026-09-25。状态：已实施，待用户手动验收。

## 1. 需求目标

保留文件作为 PPT 创作内容的持久化方式，简化项目目录；用户通过具有业务含义的界面管理内容要求、视觉要求、目录结构和页面设计稿，不再查看或直接编辑 JSON 源码。幻灯片继续提供 HTML 预览，并支持切换到带行号和语法高亮的只读源码视图。

本次不将创作 JSON 改存数据库，不改变 Agent 理解要求、维护设计稿和生成 HTML 的核心创作方式。

## 2. 更改原因

- **结构化数据应通过业务界面管理。**Manifest、Design、Outline 和 Spec 的字段、类型及合法值由产品定义。原始 JSON 编辑要求用户理解字段名称、格式和校验规则；改为结构化管理后，用户可以直接修改要求、选择装饰位置或维护页面元素。
- **文件存储仍符合当前产品。**现有创作、Git、项目历史和导出均已围绕文件建立流程。继续使用文件可以保留这些基础，避免仅为改变编辑体验而切换数据库存储。
- **目录可以更直接。**各页 Spec 集中后，每页不再需要单独的目录容纳一个 HTML。用稳定页面 ID 命名 HTML，既能直接定位页面，也不会因页序变化而重命名文件。
- **源码查看与创作操作分开。**用户需要查看 HTML 实现，但不再通过在线源码编辑器修改创作文件。取消原文编辑、草稿、保存及相关门禁，减少产品维护两套编辑方式的复杂度；业务数据仍可通过管理界面修改，HTML 仍由 Agent 创作。

## 3. 目标目录与数据职责

重构前的核心创作结构为 `manifest.json`、`design.json`、`outline.json`，以及各页的 `slides/<slide_id>/spec.json` 和 `slides/<slide_id>/index.html`。调整为：

```text
<project-root>/
├── artifacts/
│   ├── .manifest.json
│   ├── .design.json
│   ├── .outline.json
│   ├── .spec.json
│   ├── sli_aaa.html
│   ├── sli_bbb.html
│   └── attachments/
├── threads/
└── checkpoints/
```

图中仅列出相关目录；其他仍有用途的运行时目录继续承担原有职责。`threads/`、`checkpoints/` 保持位于创作工作目录之外，附件保持独立管理。

| 文件 | 职责 |
| --- | --- |
| `.manifest.json` | 演示标题、目标、受众、语言、内容要求和禁忌 |
| `.design.json` | 全局视觉方向、排版偏好和公共装饰位置 |
| `.outline.json` | 章节、页面成员、页面标题与顺序 |
| `.spec.json` | 以页面 ID 索引的全部已生成设计稿，包含可选页面角色 |
| `<slide_id>.html` | 对应页面的 HTML 创作产物 |

点号前缀用于减少普通目录视图中的干扰，不代表临时文件、缓存或访问权限。四类 JSON 仍是正式项目数据，必须纳入相应的 Git、备份、导出和恢复流程；不维护另一份可写副本。

### Spec 集合

`.spec.json` 使用对象而非数组，键为稳定的 `slide_id`，值为该页现有 Spec 业务结构。例如：

```json
{
  "sli_aaa": {
    "key_message": "企业客户贡献主要增量",
    "elements": []
  },
  "sli_bbb": {
    "key_message": "下一阶段优先提升留存",
    "elements": [],
    "layout": "左侧趋势，右侧行动建议"
  }
}
```

页面 ID 不重复写入 Spec 正文，对象键顺序不表示演示顺序。继续沿用创作 JSON 的业务字段精简规则，不重新加入版本、时间戳等已删除元数据。页面角色按 [可选角色归属设计](2026-09-26-optional-slide-role-in-spec-design.md) 由 Spec 唯一持有，未设置时省略。

Outline 是页面成员和顺序的依据。新项目 Spec 集合为空对象；页面已有 Outline 引用但无对应 Spec，表示设计稿尚未生成；HTML 是否存在独立表示幻灯片是否已生成。页面重排只调整 Outline，删除页面则同步清理对应 Spec、HTML 和关联状态，不留下孤立引用。

## 4. 结构化管理界面

内容要求、视觉要求、目录结构和页面设计稿统一通过业务 UI 展示和管理，不提供原始 JSON 查看、编辑或“预览 / 源文件”切换。界面沿用项目现有视觉规范和公共组件，不新增通用 JSON 编辑器或文件管理器。

| 管理对象 | 用户可执行的操作 |
| --- | --- |
| 内容要求 | 编辑标题、目标、受众和语言，添加、修改、删除要求与禁忌 |
| 视觉要求 | 编辑视觉方向，维护和排序排版偏好，选择合法的装饰位置 |
| 目录结构 | 沿用并完善目录中的章节、页面增删、属性修改与排序操作 |
| 页面设计稿 | 选择或清空页面角色，编辑核心信息、布局建议，添加、修改、删除和排序内容元素，选择合法的元素类型 |

普通文本编辑提供保存与取消；列表按条目管理；枚举字段使用受约束的选择控件。固定字段本身不能任意增删，必填字段不能保存为空，可选字段和列表项按各自规则清空或删除。自然语言字段保留表达自由，不因界面结构化而全部改成枚举。

项目级内容要求和视觉要求不依赖已存在的页面。尚未形成设计稿的页面提供明确空态及创建入口，提交完整、合法的业务内容后生成该页 Spec，不以空白占位数据冒充已完成设计稿。

管理操作应反馈保存成功、校验失败、冲突或暂不可修改的原因。继续遵守项目任务互斥和历史现场规则，避免覆盖 Agent 或其他窗口的新修改。读取失败或数据损坏时显示错误，不能当成空数据覆盖；不恢复 JSON 源码修复入口。

## 5. HTML 预览与只读源码

底部查看方式切换只服务于幻灯片 HTML，在“预览”和“源码”之间切换。内容要求、视觉要求、目录结构与设计稿管理界面不显示该控件；从源码视图进入这些界面时，正常展示业务内容。

采用底部切换方案，不另设此前讨论的源码弹窗。只有定位到具体页面时才有对应源码可看；没有选中页或该页 HTML 尚未生成时，提供明确的不可用状态。概览不能被当作一份 HTML 源码展示。

源码视图应满足：

- 明确显示当前页面的页码或标题，内容始终与选中的稳定页面 ID 对应。
- 提供代码行号、HTML 语法高亮、滚动、文本选择和复制。
- 展示实际保存的 HTML，不混入预览时注入的主题、公共装饰或交互代码。
- 全程只读，不允许输入、替换、格式化后写回或保存；不提供编辑草稿、保存按钮和源码编辑快捷键。
- 切页、Agent 更新和历史恢复后显示对应的正式内容；加载失败与文件尚未生成分别反馈，不展示错页或将旧内容当作最新内容。

只读限制针对用户界面的源码查看。Agent 通过正式工具生成和修改 HTML 的能力保留，用户仍可通过对话提出修改要求。

## 6. 移除旧在线源码编辑能力

删除面向原始 JSON 和 HTML 文本的人工在线编辑功能，而非仅隐藏入口或禁用按钮。

前端移除源码编辑专用的保存、保存全部、格式整理、撤销重做、草稿持久化、未保存文件列表、导航保护及 Agent 启动前草稿拦截。保留结构化管理界面自身必要的编辑状态和错误反馈；只读代码展示可以复用仍有用途的现有组件能力。

后端移除 JSON 源码读取及原始 JSON、HTML 的人工保存接口和专用处理逻辑，保留或调整 HTML 只读读取能力。正式业务修改接口与 Agent HTML 写入能力继续存在，不能随旧编辑器一起删除。

同步清理失去用途的类型、状态、依赖、样式、快捷键、测试和文档引用，不保留无人使用的旧编辑链路。

## 7. 关联能力与行为约束

- **工具继续按业务对象操作。**`read_ppt`、`mutate_ppt` 等工具可以保留现有业务语义。读取某页 Spec 只返回该页，修改某页只更新对应项；不能要求前端或 Agent 提交整份旧集合来修改一页。文件路径、命令操作和提示词同步切换到新结构。
- **集中存储不扩大修改范围。**Spec 集合写入应完整可靠，保留页面权限、单页冲突检查和变更识别。修改一页不能覆盖其他页，也不能因共享文件就认定全稿发生变化。
- **保持全链路可用。**项目初始化、内容加载、上下文、渲染、导出、Git、历史回退、失败恢复及生成参考快照均应识别新结构。Spec 集中保存后，原先依赖单页文件路径推断身份的行为需要同步调整。
- **修改参考不等于修改 HTML。**管理 UI 保存要求或 Spec 后刷新相关展示，但不自动启动 Agent、重写已有 HTML 或推进生成参考基线。公共装饰继续由 Runtime 应用，渲染结果按实际依赖判断有效性。

[创作 JSON 元数据精简](2026-09-25-authoring-json-metadata-removal-design.md) 的业务字段规则继续有效，页面身份的文件承载改为本文规定的 Spec 对象键和 HTML 文件名。[HTML 生成参考快照与变化上下文](2026-09-25-html-generation-reference-snapshots-design.md) 的参考基线与变化语义继续有效，文件路径按本文更新，人工 HTML 保存入口不再存在。

实施时前后端和 Agent 合同一次性切换，不保留旧目录兼容、双读双写或历史开发数据迁移，使用新建项目验收；不因实施而擅自清空现有开发数据。不修改数据库持久化职责，不新增源码弹窗，也不修改 `DESIGN.md`。

## 9. 验收目标

- 新建项目采用隐藏 JSON、集中 Spec 和平铺 HTML；页面生成后不再创建旧的按页目录。
- 四类结构化数据均可通过相应业务 UI 管理，JSON 原文查看和编辑入口全部消失，非法值不能保存。
- 页面插入、删除与重排保持 Outline、Spec、HTML 的对应关系；修改某页 Spec 不影响其他页。
- 只有幻灯片 HTML 支持预览与源码切换；源码具备页面身份提示、代码行号和高亮，能够复制且不能编辑或保存。
- 旧源码草稿、保存及启动拦截链路已移除，结构化管理和 Agent 创作仍可正常修改内容。
- 新结构下的渲染、导出、Git、历史回退、恢复及生成参考语义保持正确；隐藏文件没有被遗漏。

## 10. 实施与验证记录

已完成隐藏 JSON 与平铺 HTML 的统一读写；Spec 以页面为单位维护冲突校验、变更识别、工具权限和生成参考，物理集合按完整文件写入并保留失败恢复。管理 UI 使用字段表单、列表操作与枚举选择；HTML 源码使用只读高亮展示。原始文本保存接口、JSON 源码接口、时间线及完成摘要中的 JSON 文件打开入口、源码草稿及相关拦截已移除。

项目初始化、上下文、Agent 工具及提示词、渲染、导出冻结快照、Git 文件收集与项目历史均已对齐新路径。导出冻结快照保留四类隐藏 JSON；面向播放交付的导出包继续使用独立的播放结构。未迁移或清空既有开发项目，未改动 `DESIGN.md`。

已通过前端生产构建、后端构建及全部测试包编译检查；本次新增的源码响应隔离、表单现场冲突、单页 Spec 更新、权限与恢复等定向测试通过。没有进行浏览器自动化或视觉验收。

后续复查已补齐两处边界：`run_command` 直接删除 Outline 页面或整个 Outline 文件会被拒绝，页面删除须走 `mutate_ppt outline.remove` 以联动清理 Spec 与 HTML；发送 DOM 选区时拒绝所有不在当前 Outline 的页面引用，并移除依赖旧删除记录的判断与断言。相关工作流、服务、存储及历史定向测试已通过；界面手动验收仍待执行。

手动验收请使用新建项目：

1. 在没有页面时修改内容要求、视觉要求，检查保存、取消、必填项及枚举选择；这里不出现源码切换。
2. 新增章节、子节与页面，创建两页设计稿，修改和重排元素；更改一页后另一页内容保持不变。删除页面后对应 Spec、HTML 和关联状态同时清理，页面重排不改文件名。
3. 通过 Agent 生成 HTML，在单页幻灯片视图切换预览与源码，检查页码、行号、高亮、复制及只读；切页、进入项目文档或概览后不显示错页源码。
4. 打开管理表单后，在其他窗口修改同一内容或切换历史，再保存应收到冲突提示；Agent 运行期间不能提交管理修改。读取损坏数据时显示错误而非覆盖为空。
5. 修改要求或设计稿，确认已有 HTML 不自动重写；继续让 Agent 修改并渲染，检查导出与历史回退／恢复。检查创作目录只使用四类隐藏 JSON 和稳定 ID 命名的 HTML，Git 与历史包含这些隐藏文件。
