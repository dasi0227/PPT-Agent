# Create 模式名称统一

日期：2026-10-18。

状态：代码已实施；构建、测试及运行验证交由用户手动完成。

## 设计理由

创作模式的内部标识统一使用 `create`，使斜杠命令、前后端协议和提示词保持同一名称；界面展示名称为「开发」。本次仅重命名现有模式，保留讨论、分析、规划和项目编辑能力及原有权限边界。

## 名称约定

| 位置 | 名称 |
| --- | --- |
| 后端常量 | `ModeCreate` |
| API、事件、状态、检查点和数据库模式值 | `create` |
| 斜杠命令及内部 ID | `/create`、`create` |
| 界面模式名称 | 开发 |
| 提示词文件及模块 ID | `backend/prompts/mode/create.md`、`mode.create` |
| 提示词模式称谓 | `Create Mode` |

计划批准后继续在同一 Run 中切换到 Create，保留上下文刷新、批准状态持久化、事件去重和工具权限控制。前端默认模式、模式菜单、命令匹配、事件校验与历史恢复同步使用新名称。

仅修改提示词中的模式名称和文件注册，保留用户最新精简的规则正文。普通执行动作、通用 `Execute` 方法与 `executing` 运行阶段保持原名。

## 数据直接切换

数据库开发格式从 8 升至 9，`runs.mode` 的约束直接使用 `chat`、`ask`、`plan`、`create`。旧格式数据库沿用现有机制拒绝加载，需初始化新的工作目录；不添加模式别名、兼容分支或历史数据迁移。

## 人工验证范围

- 模式选择和命令菜单展示「开发」；`/create` 命令、新会话默认值和输入恢复的模式值均使用 `create`。
- Create 的读取、编辑、渲染和完成检查沿用现有行为；其他模式的权限不变。
- Plan 审批后切换到 Create，重连与历史恢复保留正确模式及批准状态。
- 使用格式 9 的新工作目录执行相关现有测试、构建与运行检查；旧格式数据库拒绝加载。
