# Run 模型调用 Token 消耗

## 统计口径

- 以每次真实模型 HTTP 请求为单位，记录供应商返回的输入、输出和总 Token；不使用上下文估算，不按 Tool Call 数量重复计算。
- 同一 Run 执行上下文内的所有模型请求统一采集，包括主 Agent、Jev、预览评估、审查、自动压缩及其重试和备用模型请求，不按模型用途排除。
- 独立命令没有 Run 计量上下文，不并入某次 Run；由 Run 内部触发且继承该上下文的调用正常计入。
- 每次请求拥有独立 UUID。HTTP 返回的内容即使未通过解析或业务校验，其有效 usage 仍记录；没有有效 usage 时保存 `null`，不冒充零。
- Messages 的缓存创建、缓存读取 Token 加入输入量；Responses 已包含在输入量中的缓存明细不再重复加。

## 采集与持久化

- 生成接口和决策接口复用 `modelusage` HTTP Transport。请求结束、响应读取失败或关闭响应体时发布一次记录，EOF 与 Close 不重复发布。
- 每条 `run.usage.updated` 事件携带调用身份、模型、供应商、耗时和用量，通过现有 Run Bus、会话日志和 SSE 链路持久化与分发，不新增数据库结构。
- Bus 从历史恢复调用 ID 去重状态；前端在实时接收与历史回放中使用同一累计函数，按 Run 分开计算并按调用 ID 去重。
- 失败、取消、继续执行不会清空已有用量。迟到的请求结束记录仍属于原 Run，不获得执行或检查点写入权限，也不改变 Run 终态。
- 用量事件只更新调用账本；不生成时间线条目，不改变活动 Run、执行状态、计划、待回复问题、进度与执行计时。时间线 reducer 显式处理该事件，并穷尽公开事件类型。
- 前端按 Run ID 和调用 ID 合并实时与历史记录；旧快照只补充缺失调用，不覆盖已记录的消耗，不把重叠快照的累计值相加。
- 统计写入失败仅记录诊断日志，不取消或暂停任务，不改写模型 HTTP 响应、读取错误与关闭错误，也不触发模型重试。缺失记录不能伪造为零或完整统计；非法的用量事件不阻断后续任务事件。

## 展示

- 运行中：`已进行 Xxx，已耗费 Xxx Tokens`。
- 终态：`耗时 Xxx，耗费 Xxx Tokens`，覆盖完成、失败、取消和系统异常。
- 数字使用千位分隔。没有有效用量记录时不显示 Token 消耗文案；部分调用用量缺失时只显示已记录的累计值，不添加前缀。
- 状态文字在窄栏自然换行，不通过省略号隐藏消耗信息。
- 等待审批或回答时显示等待确认，执行计时按原有交互事件暂停；等待期间收到用量更新只改变 Token 数字。

## 手动验收

- 一次模型响应产生多个工具调用时只记录一次；没有工具调用的文本响应同样计入。
- 主 Agent、Jev、审查、压缩调用结束后分别更新当前 Run 的累计值；重试与备用模型请求各有记录。
- 刷新、断线重连、切换会话及继续执行后，历史累计值不丢失、不重复；多个 Run 的用量互不混入。
- 模型有 usage 但返回无效内容、发生失败或取消时，仍保留已知消耗；usage 全部缺失时隐藏消耗文案，部分缺失时显示已记录的累计值。
- 拖窄右侧栏目后，耗时与 Token 消耗均可完整查看。
- 第一条用量事件到达后，进度、工具结果、计划审批与后续回复继续正常显示；等待、终止和新 Run 开始后收到旧用量，不恢复旧动画或切换当前任务。
- 统计写入单独失败时，模型响应及任务执行不受其错误影响；较早发出的历史请求晚于实时事件返回时，用量不回退、不重复。
