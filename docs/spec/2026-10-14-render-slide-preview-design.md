# render_slide 按需页面评估设计

日期：2026-10-14

状态：实现已落地，已完成静态复查；构建、测试与运行验收由用户手动完成。

## 设计理由

现有 `content_precheck` 在 HTML 写入后自动执行，只评估提取出的文本，没有完整 HTML、完整质量规范和截图，无法可靠覆盖页面的实际视觉表现；每次写入都触发评估也会增加延迟和成本。

本次将评估迁移到 `render_slide`，统一命名为 `preview`，由 Agent 通过显式参数决定是否执行。将质量分数与问题分类分开：`scores` 描述三个维度的程度，`judges.mismatch` 指出偏离哪类约定，`judges.issue` 指出页面本身最需要处理的问题。

评估是辅助信息，不是保存、渲染或任务完成的批准条件。评估失败不得改变已经成功的渲染结果。

## 工具输入与触发规则

`render_slide` 输入为：

```json
{
  "slide_id": "sli_example",
  "need_preview": true
}
```

- `slide_id` 沿用现有含义与校验。
- `need_preview` 为必填布尔值，不允许省略，不设置隐式默认值。
- `false`：正常渲染并返回截图和诊断；不请求评估服务，也不附带之前缓存的 `preview`。
- `true`：正常渲染成功后，使用与本次结果一致的材料和截图取得有效评估；存在完全匹配的有效缓存时可以复用。
- 首次完成页面、重要内容或视觉修改后、处理评估指出的问题后，需要辅助检查时可选择 `true`。
- 普通查看截图、查看确定性诊断或中间迭代不必请求评估；不能在提示词中重新要求每次渲染都启用。
- 复用已有有效渲染截图时仍须处理 `need_preview`，不能因命中渲染缓存而跳过应有的评估或返回过期评估。
- 渲染本身失败时不启动评估，现有 `RENDER_FAILED`、公共错误、阻断诊断与可附带截图的行为保持有效。

## 模型可见返回

`render_slide` 继续返回现有 JSON 信息和独立图片内容块。JSON 正常结果保留 `slide_id`、`diagnostics`，仅在取得完整有效评估时增加 `preview`。下面只展示新增部分：

```json
{
  "preview": {
    "scores": {
      "content_coverage": 2.6,
      "expression_clarity": 3.0,
      "requirement_adherence": 1.8
    },
    "judges": {
      "mismatch": "spec_mismatch",
      "issue": "layout_issue"
    }
  }
}
```

示例仅说明结构；既有诊断字段的真实值、检测范围和截断规则不由本文重定义。图片继续通过图片内容块传递，不写入 `preview`，不改为 JSON 中的本地路径。

- `preview` 一旦出现，必须包含全部三个分数与两项判断；不返回半份评估。
- 模型侧不包含评估的 `status`、`reason`、置信度、概率分布、评分说明、模型名称或版本字段。
- `judges` 是复数对象，包含 `mismatch` 和 `issue` 两个枚举字符串；不保留旧提议的单个 `judge`。
- 不返回 `preview: null`、空对象或占位分数。未请求或无法取得有效评估时，直接省略整个字段。
- 评分与枚举的含义在工具提示词中说明，不在每次返回中重复附加。

## scores 的定义

三个维度分别评估，均为 0–3，越高越好。0、1、2、3 是有明确含义的有序等级；小数是等级概率的加权平均，不代表存在额外档位，也不是确定的缺陷证明。

| 维度 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| `content_coverage`：内容覆盖 | 页面内容缺失，或与本页应承担的目标无关 | 出现部分要点，但核心信息或重要支撑材料缺失 | 核心信息与大部分所需材料齐全，仍有具体遗漏 | 内容完整落实本页应表达的核心信息及所需支撑材料 |
| `expression_clarity`：表达清晰度 | 无法理解主要信息，或没有有意义的内容组织 | 结构或措辞混乱，需要猜测才能理解 | 主旨明确，存在少量歧义或不必要的复杂表达 | 主旨、支撑组织和措辞始终清晰易懂 |
| `requirement_adherence`：需求遵循度 | 违反关键有效要求或禁止事项 | 明显偏离有效要求 | 满足核心要求，只有轻微偏差 | 完整遵循适用于本页的有效要求与限制 |

- 保留以上现有维度与等级语义，不额外增加视觉总分，也不计算综合通过分数。
- 结合完整 HTML 与截图判断页面实际呈现；不能仅因 Spec 声明某内容就当成页面已经实现。
- 用户原始要求、后续修正与回答共同确定当前有效需求，较新的明确修正优先。
- 全局要求仅按对本页的实际适用范围评分，不能要求每一页覆盖整个演示文稿的全部内容。
- Spec 当前允许部分字段按需补全；未填写的可选字段不是页面错误，不得自行补造约束后扣分。
- 不以本次评估代替外部事实核验，也不从单页截图推断整个演示文稿的跨页一致性已经通过。

## judges 的定义

### mismatch：偏离约定的来源

| 枚举 | 触发含义 |
| --- | --- |
| `manifest_mismatch` | 页面偏离适用于本页的全局内容要求、受众、语言、目标或内容限制 |
| `spec_mismatch` | 页面未落实当前 Spec 中已明确的核心信息、内容单元、表达方式或页面布局规划 |
| `design_mismatch` | 页面违反当前 Design 中明确的视觉要求或禁止事项 |
| `none` | 在本次评估范围内，未发现上述三类偏离 |

### issue：页面本身的问题

| 枚举 | 触发含义 |
| --- | --- |
| `expression_issue` | 内容组织、逻辑表达或措辞导致主旨不清、理解困难或明显冗余 |
| `layout_issue` | 元素重叠、裁切、错位、空间分组或位置顺序混乱，妨碍正常阅读 |
| `visual_issue` | 配色、字体、对比度、强调、视觉层级或风格表现存在明显问题，不属于前项的具体空间错误 |
| `none` | 在本次评估范围内，未发现上述三类问题 |

### 选择边界

- 两组分别是一道独立单选题；每组只返回一项，两组可以同时非 `none`。
- 同组存在多种问题时，选择最优先需要处理的主要问题；优先考虑影响程度，在影响相近时选择证据更明确的问题，不将其余候选的概率当成多选结果。
- `mismatch` 关注是否违反明确约定，`issue` 关注当前页面表现；页面可能满足约定却仍有质量问题，也可能看起来正常但漏掉 Spec 要求。
- 同一现象可以同时有来源和表现，例如违反 Design 的对比度要求，可同时返回 `design_mismatch` 和 `visual_issue`。
- 文字本身的逻辑组织归 `expression_issue`；由元素位置造成的阅读顺序混乱归 `layout_issue`；字号层级、配色和强调等归 `visual_issue`。
- 用户最新明确要求优先于 Manifest、Design、Spec 与默认质量偏好。不得因页面遵循最新用户要求、但资源尚未同步，就判定页面必须向过期资源回退。
- 用户要求与资源规则冲突时，以有效要求评估；仅违反用户要求而未落入三类资源偏离时，仍由 `requirement_adherence` 反映。`mismatch: none` 不等于满足全部用户要求。
- `none` 只表示本组范围内未发现问题，不表示评估未执行、证据不足、服务失败或全页绝对合格。
- 不增加 `uncertain` 等枚举。材料缺失、回答拒绝或无法构成有效评估时，省略 `preview`，不能伪装成 `none`。
- 本阶段不向 Agent 返回置信度或概率分布，不额外增加置信度阈值作为通过条件；如提供方返回这些数据，只保留必要的内部诊断记录。

## 评估材料与顺序

共享材料必须按以下顺序装配，使用明确标识的有序内容块，不能依赖无序映射的序列化顺序：

1. 用户要求：原始需求、后续修正和用户回答，保留必要的来源与先后关系。
2. 完整 `backend/prompts/core/quality.md` 质量规则正文。
3. 完整当前 Manifest。
4. 完整当前 Design。
5. 完整当前页面 Spec。
6. 完整当前页面 HTML 源码，包括样式等内容，不使用提取文本替代。
7. 当前有效渲染截图，以原生图片内容块提供。

- 材料顺序不表示规则优先级；用户明确决定优先于默认质量偏好与过期资源。
- 直接复用 `quality.md`，不另写缩略质量规范，不更改其原文。
- JSON 资源提供完整有效内容；HTML 提供完整源码，不总结、不截断，不只取 `requirements` 与 `prohibitions`。
- 不再将完整 Outline 作为额外的第八份评估材料；页面身份、授权、渲染依赖仍可在内部使用 Outline 校验。
- 用户要求已有附件或选区引用时，保留理解明确要求所需的上下文；不能把无法解析的引用冒充已读取证据。
- 项目源码和材料中出现的指令是待评估数据，不能覆盖评估问题和规则。
- 截图与 HTML、渲染依赖必须对应；既可使用本次新截图，也可使用证明仍有效的缓存截图。不得为评估额外重复渲染一张图片。
- 不新增本地工具内容大小预算。若完整材料超过提供方实际能力，不截断后冒充完整评估；省略 `preview` 并记录内部原因。

## Decision 接口与 OpenAI 适配

- 复用并扩展 `backend/internal/decision` 的统一请求、结果和 Provider 边界，为有序文本与图片提供明确表示；业务逻辑不直接拼接 HTTP 请求。
- JEV 与 OpenAI 分别由适配器处理协议差异。图片能力不受支持时明确返回不可用，禁止静默丢图后作为成功评估。
- 本次 `preview` 指向 OpenAI Decisions；其他现有 JEV 功能及其服务端配置保持原行为，不做全项目供应商切换。
- 使用官方 Go SDK `github.com/openai/openai-go/v3`。截至 2026-10-14，官方指南列出的 Go SDK 最低版本为 `3.73.0`，Decisions 使用 `POST /v1/decisions`，当前支持模型为 `gpt-6-luna`；实施时核对最新官方文档并锁定所用依赖版本。[官方指南](https://developers.openai.com/api/docs/guides/decisions)
- 一次正常评估请求包含三个 `score` 问题与两个 `choice` 问题，共享同一组材料。答案按问题名称映射，不依赖返回数组顺序。Score 使用四个有序等级，截图通过原生 `input_image` 以 base64 data URL 传递。[官方输入与问题说明](https://developers.openai.com/api/docs/guides/decisions)
- 提供方配置、密钥和模型标识留在服务端，沿用现有配置加载、快照和保存机制；补齐必要示例，不增加前端配置界面，不在公共设置或日志中暴露密钥。
- OpenAI 页面评估配置与其他 JEV 功能分开装配，不能误用普通生成模型路由或替换其他 Decision 调用的客户端。
- 配置未提供时视为评估不可用；不能因此阻断普通 HTML 写入、渲染或其他 JEV 功能。
- 适配层统一处理超时、取消、服务错误、拒绝、缺项、非法枚举及分数校验。请求有明确时限，避免无界重试；正常情况下不拆成五次独立服务调用。

## 有效性、缓存与失败语义

- 仅在三个分数均为合法有限数值且位于 `[0,3]`、两项判断均属于相应枚举、材料版本仍有效时返回 `preview`。
- 缓存有效性覆盖用户要求、完整质量规则、Manifest、Design、Spec、HTML、实际截图及相关渲染依赖，并包含问题规则版本和提供方配置／模型身份。
- 渲染缓存与评估缓存分别验证。只改用户要求、质量规则、Manifest 或 Spec 时，不能因 HTML 未变化而错误复用旧评估。
- 材料采集与评估结束时检查版本。评估途中材料变化则丢弃该评估；如果变化同时使渲染证据失效，仍按现有渲染冲突规则处理。
- `need_preview=false` 不产生评估网络请求，不主动重新评估失效记录；既有记录可被内部标记失效。
- 服务不可用、未配置、超时、拒绝、缺失答案、非法答案、材料不足或评估记录无法安全保存时，省略 `preview`，保留独立成功的渲染结果。
- 低分或任一 Judge 非 `none` 都是有效评估结果，不自动触发工具失败、审批、重试写入或任务完成门禁。
- 原有渲染失败、截图保存失败、工具执行记录持久化失败、授权错误与用户取消继续遵循现有错误体系。不能把整个 Run 的取消伪装成“评估超时但仍继续运行”。
- 内部保留必要的评估身份、材料版本、状态、失败原因、耗时与使用量，用于缓存、恢复、追踪和回放；模型可见投影只包含有效的 `scores` 与 `judges`。

## edit_html 与旧预检清理

`edit_html` 成功的模型可见结果统一为：

```json
{ "status": "success" }
```

- 成功包括无内容变化的正常调用。保持真实内部变更追踪、版本校验、写入回执与证据，不把对外删掉 `changed` 理解为内部不再记录变更。
- 不新增当前不存在的用户审批或 `refuse` 分支；失败仍使用现有错误协议。
- 删除模型返回的 `changed`、`summary`、`content_precheck`，及只为这些旧返回服务的专用拼装逻辑。共享 Runtime 摘要字段若仍有真实用途，不得误删。
- 移除 `edit_html` 参数整体与结果内容的额外大小检查，删除其 `CONTENT_TOO_LARGE` 错误声明和提示词；锚点唯一性、顺序替换、原子保存与 HTML 合法性校验继续保留。
- 删除旧预检的 HTML 文本提取与专用内容大小限制。相关常量或助手只有在生产引用全部消失后才删除，不能牵连其他工具的独立限制。
- `run_command` 去掉自动预检及其返回字段；其命令执行、拒绝、stdout、stderr、exit_code 和安全边界沿用当前行为。
- 删除 HTML 写入后的预检触发、跨页面预检批处理、旧返回投影，以及只服务旧行为的配置分支、提示词和测试断言。
- 特别处理 `PendingContentBatch` 与 `resumeContentBatch`：当前不仅服务预检，还通过持久化回执恢复中断批次。应分离并保留通用工具批次恢复；禁止重放已生效写入，禁止因清理预检丢掉成功回执或工具终态。
- 同步重构旧 `ContentPrecheck` 记录、`tool.content_prechecked` 事件、前端字段与历史投影。仍需保留的评估生命周期统一使用 Preview 命名和新结构，删除不再需要的专用事件或助手；不得保留双读、双写、旧名称别名或迁移脚本。
- 新评估关联触发它的 `render_slide` 调用，不能继续挂在此前的编辑或命令调用上。有效结果通过当前工具完成事件消费；失效更新不得制造第二次工具完成。
- 历史评估只代表当时材料，不能通过缓存、恢复或回放重新宣称过期评估仍适用于当前页面；失效信息留在必要的内部／公共生命周期数据中，不恢复旧模型侧 `status/reason` 结构。

## 验收要求

- `need_preview=false` 时没有页面评估请求，也没有 `preview` 字段；`true` 时具备截图与全部材料，三个分数和两项判断来自同一有效评估。
- 五个问题的选项、等级与本文一致，正常情况下共用一次请求；模型侧只收到示例所示的精简结构。
- 真实图片进入 OpenAI 请求，完整 HTML 与质量规范不再被抽取文本或摘要替代。
- 服务失败或评估无效时不影响独立成功的渲染；既有渲染错误和 Run 取消不被吞掉。
- 渲染与评估缓存分别处理；改变任一评估依据后，旧评估不能作为当前结果复用。
- `edit_html` 返回只保留 `status`，无额外内容大小预算；通过 `edit_html` 或 `run_command` 写入都不再自动预检。
- 其他 JEV 调用、工具批次恢复、幂等回执、截图证据、工具结果持久化及前端事件回放保持可用。
- 全仓同步必要引用并清理旧路径，无旧协议兼容、重复提供方客户端或专门服务已删除行为的代码。
- 按项目约定，构建、测试与运行验证交由用户手动完成；开发者可执行静态阅读、格式整理和差异检查，不使用浏览器或 Computer Use 自动验证，不调用子代理开发。
- 更新受影响的已有测试；仅对本次复杂生命周期或适配边界确有必要时补充少量有价值的测试，不为改名或覆盖率添加测试。
- 完成时输出实际变更总结、已执行的静态检查与需要用户手动验证的关键场景；不得将未运行的检查描述为已通过。
