# 普通文本完成与独立后续建议

## 已确认行为

- 移除主 Agent 的 `finish_task`。Chat / Ask / Execute 的非空、无工具回复自动进入原有完成检查；通过后保留最终回复持久化、证据检查、事务收尾、检查点和终态事件。
- 完成检查拒绝时，将具体问题作为 Runtime 反馈交回同一循环。最新反馈位于当前用户需求之后；同一问题且证据未变化连续拒绝三次即停止。
- Plan 仍使用 `create_plan` 和原有审批。连续三次仅返回文本、没有工具调用时，以 `PLAN_SUBMISSION_MISSING` 失败结束。真正空响应或供应商截断仍走错误路径。
- 后续建议通过独立 `suggest` command 生成，仅此 command 暴露 `suggest_request(requests)`。接受零至三条不同的单行请求，每条最多 80 个字符；无有用建议时允许空数组。
- 自动建议开关按会话保存，默认开启。主任务成功完成、释放运行句柄后异步启动；失败、取消和等待审批不自动触发，不延迟主任务终态。
- `/suggest` 使用灯泡图标，打开与 rename 一致的面板。提供自动开关与“立即生成”；手动生成不改变自动开关。会话运行中及无历史记录时禁用生成。
- 建议列表的视觉、快捷键和点击填入输入框行为保持原样；suggest 不插入时间线卡片。自动失败仅记录日志，手动失败在面板反馈。
- 支持 `side-road.suggest` 单独选择模型，未配置时跟随旁路默认模型及备用模型。

## 生命周期与协议

- `message.final` 和主 Runtime outcome 不再携带建议字段。前端从持久化 command 事件恢复建议。
- 每个建议 command 绑定 `run_id` 和 `suggest_version`。新任务、重新生成、自动开关变化使旧生成版本失效；保存完成结果时在事务内再次检查，失效结果记为取消。
- 前端仅接受当前空闲 run 的最新 attempt，不覆盖草稿；新任务接受或恢复运行时清除建议。
- 建议生成采用现有 `SubmissionSession`，首轮加最多两次追加请求，并设置独立 20 秒超时。
- 数据库结构直接升级到开发格式 8：增加会话开关及生成版本，command kind 增加 suggest。没有旧结构兼容或历史数据迁移；已有格式 7 的工作目录需要重新初始化，不能直接启动新服务。

## 手动验收

- 普通问答及拒绝类回答只产生一条最终回复并结束；主 Agent 工具列表没有 finish_task 或 suggest_request。
- Execute 缺少必要证据时继续修复，同一拒绝三次停止；Plan 正常审批且连续三次纯文本会停止。
- 自动开关开启时，先结束 run，再出现建议；关闭后不自动生成，手动生成仍可用且不会开启自动。
- 新任务开始或恢复期间，迟到建议不出现；刷新和切换会话能恢复当前建议，时间线不出现 suggest 卡片。
- 手动生成失败显示面板错误；自动失败不改变主任务状态。新模型用途能保存并跟随旁路默认配置。
