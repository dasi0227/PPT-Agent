# 渲染前后对照与容器文字裁切诊断

## 目标

修复页面反复删加同一段文字却无法确认改进的问题：为 Agent 保留前后版本的视觉证据，并把容器内部的文字裁切作为明确诊断返回。

## 截图版本

- 每个页面的渲染索引保存最新截图与上一份不同版本截图的引用。版本由 HTML、运行时外观/装饰、资源依赖与渲染校验版本共同确定。
- 相同版本重复渲染不会挤掉上一版；首次渲染仅提供当前版。缓存命中沿用原截图引用。
- 只有当前 Run 已读取或渲染的页面注入图片。读取当前页时可带上项目中已有的上一版，跨 Run 修改也能比较。
- 模型上下文明确标记 `previous`、`current`，同一图片只注入一次；检查点恢复和上下文压缩后保留这组证据。
- 修改后尚未渲染时，仅保留最后一张截图并标记为历史。删除页面或图片不可用时移除对应图片。
- 有有效截图但诊断不通过的渲染仍参与比较；它不能产生成功渲染证据。上一版图片始终只供比较，不影响当前完成检查。

## 文字裁切

- 在浏览器中测量可见文本节点的 Range，与实际生效的祖先裁切区域比较。
- 覆盖横向、纵向的 `overflow: hidden/clip/auto/scroll` 及矩形 paint containment，允许 1 CSS px 的测量误差；忽略空白和不可见文字。
- `diagnostics.text_clipping` 返回文字元素、裁切容器、受影响文字片段、方向、超出像素及容器边界；最多返回 50 项。
- 只检查文字，不把图片或无文字装饰的正常裁剪作为文字裁切。绝对定位/固定定位逃逸的非包含块不作为裁切祖先。
- 发现文字裁切时返回 `RENDER_FAILED`，阻断原因是 `RENDER_TEXT_CLIPPING`，同时提供截图和诊断供修复。
- 渲染校验版本写入证据和缓存依赖，旧诊断缓存与旧成功证据不能跳过新增检查。
- 这项检测针对矩形容器文字裁切；它不判断元素相互遮挡、任意形状的 mask/clip-path 或伪元素生成文字，仍需结合截图检查。

## 提示词

同步工具目录及实际工具定义、Execute 模式、HTML/Task playbook 和质量要求：围绕本次目标比较前后截图，检查内容丢失和新增缺陷，依据结果保留、调整或回退。文字装不下时修正空间分配、换行或布局，避免在同一空间反复删加内容。

## 手动验收

1. 渲染 A 后修改为 B：模型请求包含标明上一版 A、当前版 B 的两张图；再次渲染 B 不丢失 A。再改为 C 后应为 B/C。
2. 修改 B 但尚未渲染：B 仅作为历史图片；完成检查要求当前版本的渲染证据。
3. 跨 Run 修改已有页面、恢复检查点、压缩上下文：仍能得到对应前后两版，图片不重复。
4. 页面内容处于画布内，但固定高度代码框截断最后一行：返回文字、代码框定位、bottom 方向及超出像素，结果为 `RENDER_FAILED`。横向截断、嵌套容器、滚动容器分别检查。
5. 扩大代码框或调整布局后重新渲染：裁切诊断消失，前后图显示原文字完整保留。
6. 无文字图片裁剪、隐藏文字、仅空白溢出：不产生文字裁切诊断。正常文字布局保持通过。
7. 使用旧缓存的页面重新请求渲染：执行新检测，旧完成证据不能继续通过。

按项目约定，以上运行及浏览器验收由用户手动完成。
