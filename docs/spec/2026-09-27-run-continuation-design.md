# 任务结束提示与继续执行

## 用户已确认的交互

- 结束提示统一使用 Timeline 浅灰卡片，标题为「任务执行失败」「任务执行异常」「任务执行中断」。
- 标题下仅展示语义化原因，不展示技术详情、已更改内容或附加操作行。
- 主动中断固定显示「你已停止本次任务。」。
- 可继续的失败、中断在标题右侧显示「继续执行」，带 Play 图标、浅蓝背景与对应颜色边框。
- 系统异常无继续入口。内部 paused 状态仍用于运行安全隔离，前端展示为任务执行异常。

## 继续边界

继续使用同一个 run_id、原始请求及其持久化运行检查点，不创建新的用户消息或复制原始请求重试。保留已提交的文件、对话、计划、授权范围、已完成操作收据及累计用量。未提交的当前工具操作回滚。

规则限制导致的停止（轮次、时长、连续工具失败、重复完成检查失败等）和主动取消，可以保存可继续检查点；未知错误、模型服务异常、记录写入失败、进程异常不开放继续。已取消的计划不重新执行。

每次用户明确继续后，重新计算本段的轮次与活动时长额度，重置完成检查失败次数，累计统计不清零。完成检查、提交等内部阶段恢复到对应的可执行阶段。

GET run 返回后端计算的 can_continue；POST resume 在项目锁与数据库事务内重新校验资格。仅允许项目最新任务继续，且执行版本、检查点版本必须一致，无其他活动任务。接受新任务后，旧检查点的继续资格永久失效。

继续前恢复工具事务日志，并核对检查点记录的文件变化。外部改动、缺失文件、未确认写入、已提交内容被回退均拒绝继续；已完成的删除允许保持缺失。检查点中已结束的工具调用不自动重放；已记录取消结果的命令需要模型重新提出调用及必要授权。

## 事件与界面

新增执行版本后发布 run.resumed，沿用原任务序号继续推送。事件总线重置终态、取消标志和最终回复计数，同时保留已完成调用的防重复约束。前端收到恢复事件时移除该任务的旧终态展示，使进度行恢复；后续终态重新展示。

恢复失败显示语义化错误提示，保持原终态，不伪造新任务。继续按钮在请求期间禁用。

## 验证重点

覆盖同一任务恢复、重复点击/认领、被新任务替代、系统异常不可恢复、执行版本过期、额度重新计数、文件冲突、完成删除、终态后事件流重启及前端进度恢复。
