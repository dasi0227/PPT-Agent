# 页面范围选择重构

## 决策与边界

本方案以 2026-09-23 最新用户决定为准，替代此前「修改对象 × 页面」的范围模型。范围只回答“哪些页面可以修改”，不再提供设计稿、幻灯片、演示文稿、全局资源四种对象选项。

- 选中页同时允许修改 Spec 和 HTML，不要求额外对象授权。
- 全局 manifest、outline、design 默认允许修改，包括共享资源及结构操作；工具已有字段限制（例如不可替换用户选定主题）不变。
- 读取其他页面仍然允许，直接写入其他页面的 Spec／HTML 仍需页面扩权。全局资源开放不等于所有页面可写。
- chat、grill、plan 的只读限制保持不变；以上写权限仅适用于 execute。
- 共享设计可能影响整份演示文稿；需要同步范围外页面时先扩展页面范围。页面范围不是共享资源的视觉影响隔离机制。

## UI

一级浮层按纵向排列「当前页／全部页／自选页／自选章」，沿用现有顶部栏入口、向上弹出、Portal 避让、soft blue 选中反馈。

点击自选页或自选章进入同一个浮层内的二级多选列表，不同时堆叠一级选项。二级顶部为返回按钮、范围名称及已选数量；行内为「第 x 页／第 x 章」、标题和右侧勾选态。页序跟随大纲，章序使用一级章序，不显示章内页数，不预留多余左侧缩进。

选择即时生效，无重置、完成按钮或解释段落。入口只显示范围名称，不附带数量。返回或第一次 Escape 回到一级，一级 Escape／外部点击关闭。关闭后再次打开从一级开始。空项目仅允许全部页；自选为空时禁止发送，沿用输入区校验。

## 协议与执行

创建任务的 scope 只含 selection，例如：

```json
{"selection":{"kind":"custom_pages","slide_ids":["sli_one","sli_two"]}}
```

selection.kind 支持 current_page、all_pages、custom_pages、custom_sections；分别使用 current_slide_id、无附加字段、slide_ids、section_ids。后端按大纲顺序解析为稳定页 ID、去重并拒绝未知或空的自选项；选择章包含该章的子节页面。

运行期 scope 保留 slide_ids、source、include_run_created_slides、revision，删除 object。all_pages 包含本次运行创建的页面；其他选择不会因创建页面而自动扩大。DOM 引用合并页集合的现有规则不变，但引用共享 chrome 不再升级成“全局对象”。

request_privilege 只接受 add_slide_ids 和 reason；扩权事件及审批仅传递页面增量。已包含页为无变化操作，批准新增页后递增 revision，不允许缩小既有授权。审批卡可调整为全部页。

页面写入、渲染及完成检查统一依据稳定页 ID；上下文不再按 Spec／HTML 对象拆分。工具同时提供两种页面内容及全局资源操作，实际页授权仍在执行时检查。

前后端类型、输入区草稿、历史恢复、重试、SSE、上下文、运行快照和 SQLite 投影一起切换。数据库通过 0018 结构变更删除 scope_object，不保留兼容读写；不迁移旧版任务／草稿的对象语义，旧任务不作为继续执行入口。新版草稿使用独立存储键，不误读旧对象选择。

## QA 决策记录

1. 还需要对象维度吗？不需要，默认允许全部对象。
2. 全局资源是否另设入口？不设，后续新的全局资源处理方式不在本次范围。
3. 页面选项怎么排？纵向一级菜单，自选进入二级列表。
4. 自选页有标题吗？展示大纲页标题，与章节列表保持一致。
5. 序号显示什么？第 x 页／第 x 章，章序不是页数。
6. 需要确认或重置吗？不需要，直接选择即可。
7. 入口显示数量吗？不显示，数量只在二级列表内。
8. 选中态是什么？使用项目统一 soft blue。
9. 开放全局会解除页面限制吗？不会，范围外页面的直接写入仍需扩权。
10. 需要改后端吗？需要，同步移除对象字段和对象权限分支，不只隐藏 UI。

## 验证范围

仅进行类型／编译检查与相关行为回归：二级选择、草稿及历史恢复、事件解析、范围规范化、页面扩权、写入边界和存储结构。无需浏览器自动化或覆盖率测试。视觉与实际操作由用户手动验收。
