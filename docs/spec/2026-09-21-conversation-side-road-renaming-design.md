# 会话旁路自动命名设计

- 日期：2026-09-21
- 状态：产品决策已确认并完成实现。
- 决策来源：本次 grilling Q1–Q18 及用户后续修订；以本文最终行为为准。
- 实现基线：`2832f1b1`。近期相关提交为模型配置精简 `9617f703`、压缩标题协议 `0f46e70f`、运行进度 activity 协议 `1c36bb37`。

## 1. 目标与边界

### 1.1 本次需求

用户希望产品根据用户需求与任务进展，为会话自动生成具有辨识度的名称。命名应由旁路小模型完成，不增加主 Agent 的推理负担，也不让用户在每个会话创建时填写名称。自动命名需要跨多次输入理解目标，不能跟随每个工具步骤频繁变化；用户必须能随时人工接管名称或控制自动命名开关。

本次必须同时解决五项问题：何时调用命名模型、主旁路模型如何分别配置、命名模型读取哪些输入、如何返回可靠结果，以及持久化后的名称与开关如何独立同步到前端。追加需求是通过无参数 `/rename` 打开操作面板，统一承接立即命名、人工命名、开启与关闭。

### 1.2 产品范围

仅自动更新项目下的会话名称 `Thread.title`。项目名、演示文稿标题、大纲和页面标题不在本次范围。

标题概括一段较长对话的持续目标，随着需求澄清或实质转向修正。任务阶段变化、普通工具执行和局部修改不要求改名。达到调用条件只代表重新评估，模型可以保留当前标题。

命名是独立的后端旁路：独立模型、Prompt、输入预算、任务生命周期、超时与结果通知。主路首字、工具执行和结束不等待命名；主路成功、失败或取消不影响已接受的命名请求。命名结果合法且仍有效时，立即保存并通知前端。

实施前已有手动会话重命名接口，但 Thread 尚无自动命名开关；主路配置为 `llm.default + profiles`。压缩采用局部工具 Schema 返回结构化结果，但自动压缩仍使用主路选中的模型。前端在 Run 终态关闭 Run SSE，因此不能依赖该连接送达旁路结果。

本期不增加后台定时命名、跨会话摘要、主路重命名工具、名称修改历史 UI、长期任务队列恢复或其他旁路能力的模型迁移。历史开发数据按仓库约定直接切换新结构，不设计旧数据兼容层。

## 2. 会话开关与操作入口

新会话默认 `auto_rename_enabled = true`。用户通过现有弹窗表单明确保存名称后，保存标题和关闭旁路必须是同一次原子更新。

新增无参数指令 `/rename`。执行指令只打开聊天区域的临时操作面板，不直接调用模型，不写入聊天历史或模型上下文。关闭面板不留下 timeline 记录，不改变会话状态。面板展示当前开关状态和四项操作：

| 操作 | 开关 | 标题与调用 |
| --- | --- | --- |
| 立即自动命名 | on | 有有效对话内容时立即请求旁路；空会话保留默认名称，等待首条需求。 |
| 手动命名 | off | 校验并保存输入的名称，不调用模型。 |
| 开启自动命名 | on | 只开启，不立即调用；计数重新开始。 |
| 关闭自动命名 | off | 只关闭，保留当前标题。 |

不支持 `/rename xxx`、`/rename on`、`/rename off` 等参数语法；此前讨论的这些语法已被面板替代。不增加额外的恢复自动命名按钮。菜单与无参数命令均进入同一面板；不应意外吞掉其他普通输入或将命名指令送入主路。

主路运行期间也可操作命名面板，不能沿用仅适用于主路互斥操作的禁用条件。

用户通过表单创建会话并明确填写名称时，将“新建默认 on”和“人工命名关闭”按顺序执行，最终为 off。程序内部生成的占位标题不等于用户人工命名，不可仅靠 title 是否非空推断用户行为。

## 3. 自动触发与计数

只有以下三个入口会请求命名：

1. 开关 on 时，首条有效用户需求持久化后。
2. 开关 on 时，上次请求发起后累计新增 5 次有效用户输入。
3. 用户在 `/rename` 面板选择“立即自动命名”。

不设 10 分钟门槛，不使用定时轮询模型。单个长 Run 内的工具进度不重复触发。

有效输入指服务端成功接受并持久化的一次普通用户消息或运行中补充指令；按输入身份去重。是否成功执行主路不影响计数。工具调用、助手回复、命名操作、确认按钮及尚未发送的草稿不计数。

计数规则：

- 第一条有效需求触发首次请求，不同时算作下一周期的第 1 条；之后第 5 条新输入再次触发。
- 请求实际发起时重置计数，后续请求运行期间收到的输入继续累计，不能在结果返回时清零而丢失这部分输入。
- `keep`、成功改名、超时或模型输出失败均已消费本次请求，进入下一个周期。
- off 期间不累计；重新开启从 0 开始，不补算关闭期间的输入。
- 显式立即命名绕过计数，开始新周期。
- 尚未有任何有效需求的会话，开启或立即命名不调用模型，首条需求到达后才调用。
- 请求因并发被合并等待时，不应把它误记为已经调用；实际启动时确定快照和计数边界。

计数更新和任务触发由后端负责，不能依赖当前页面是否打开。首次输入需保留在独立可读取的已接受输入中，不能等到 Run 结束保存 model transcript 才获得首次命名素材。

## 4. 模型配置

直接切换到用户指定的配置结构；不保留旧结构双读、兼容或静默回退。

```yaml
llm:
  main-road:
    default: 主路模型
    profiles:
      - name: 主路模型
        provider: openai
        model: your-main-model
        key: your-main-key

  side-road:
    rename:
      name: 命名模型
      provider: openai
      model: your-rename-model
      key: your-rename-key
```

`main-road.profiles` 沿用现有列表语义，default 精确匹配其中一个 name。`side-road.rename` 为完整独立配置，不通过主路 profile 名引用模型；name 是该旁路模型的显示与诊断名称。

主路下拉列表只使用 `main-road.profiles`。命名模型不混入主路候选，用户切换主路模型不改变命名模型。可复用现有 Provider 构建与适配代码，但使用独立命名服务和请求上下文。

本期只增加 rename，不改动 compact、polish、briefing 等已有能力的模型归属。将来可在 side-road 下按用途扩展。配置加载、校验、示例、服务装配和相关协议在实施时同步切换；错误诊断不得输出密钥。

name/provider/model/key 均按现有 Profile 的基础要求校验；主路列表内 name 唯一，旁路名称不参与主路选择。新配置要求显式提供 rename 项；配置缺失或结构不合法在启动校验时报出配置路径，不回退使用主路模型。合法配置对应的供应商运行时失败按第 9 节处理，不中断主路请求。

## 5. 命名输入快照

命名服务在请求开始时构造不可变 `rename_context`，包含：

| 字段 | 内容 |
| --- | --- |
| `current_title` | 当前会话名称，空字符串表示尚未命名。 |
| `trigger` | `first_input`、`input_threshold` 或 `manual`。 |
| `first_user_request` | 首条已接受的有效用户需求。 |
| `recent_user_inputs` | 最近用户需求和补充指令，保留先后顺序，优先保留最新内容。 |
| `recent_assistant_replies` | 最近已有的助手最终回复。 |
| `plan` | 当前已有计划的标题、步骤和状态。 |
| `context_summary` | 已有的上下文压缩摘要。 |

后四类上下文按实际可用性提供；首条需求即可发起请求，不等待计划、压缩或主路回复。不为命名额外生成摘要，不复制主路的完整上下文组装流程。

完整命名请求输入预算初始为约 4,000 tokens，包含系统 Prompt 和局部工具 Schema 的开销。优先保留当前标题、触发来源、首条需求的有效片段及最新用户意图，再为计划、助手最终回复和已有摘要分配预算。超长单条文本也需要裁剪并标记截断，不能仅按条数限制。

不发送图片二进制、HTML 全文、工具日志或其他会话内容。附件型输入可使用已持久化的用户说明和必要引用信息；缺少足以命名的文字证据时允许 keep，不为本功能引入视觉解析请求。

用户最近明确修订的目标优先于旧计划、旧摘要和首条需求。主路任务进度仅帮助理解目标，不用于判定旁路是否应执行。快照中的所有文本均是待概括的数据，不是命名服务的运行指令。

## 6. Prompt 与模型输出

Prompt 文件为 `backend/prompts/command/rename.md`，在 Prompt catalog 中以 `command.rename` 注册，并通过现有加载和内容哈希机制使用。

参考当前压缩请求的局部工具 Schema 范式，命名请求只提供 `rename_thread`，要求恰好返回一次调用。该工具仅作为结构化输出通道：不加入主路工具注册表、不进入 ReAct、不产生主路 tool 事件、不写入主路 transcript。

模型只允许返回以下两种结果：

```json
{"action":"rename","title":"面向投资人的产品路演"}
```

```json
{"action":"keep"}
```

Schema 使用 action 枚举、可选 title 和禁止额外字段；后端执行分支校验：rename 必须有合法 title，keep 不带 title。只校验结构化工具参数，不从正文、Markdown 代码块或自然语言中提取降级结果。

自动触发和显式立即命名都允许 keep。没有足够证据时保留当前标题；不得编造特定主题。生成候选与当前标题相同，按未改变处理。

标题使用主要对话语言，中文通常 6–20 字，去除首尾空白后硬上限为 60 个 Unicode 字符。单行纯文本，不含 HTML、Markdown 格式、控制字符、包裹引号、句末句号；突出主题、对象、受众或持续目标，不添加完成/失败等状态前缀，不追踪琐碎步骤。自动与手动路径的基础长度和文本安全校验保持一致。

## 7. 独立生命周期与并发

命名请求使用应用生命周期派生的独立 context 和 20 秒超时，不继承 Run 的取消上下文，也不因发起它的 HTTP 请求结束而取消。不等待主路终态，不持有覆盖整个模型请求的项目执行锁。

每个会话最多一个在途命名请求。运行中再次显式立即命名时，最新用户操作使旧结果失效，并合并为至多一个采用最新快照的后续请求；先结束或取消旧调用，再运行新调用。自动阈值重复命中同样合并，避免请求堆积。

以下操作均建立新的命名操作版本，阻止此前结果覆盖：人工保存标题、开启/关闭旁路、显式立即命名。特别是 off 后再 on，不能重新接受 off 之前的结果。普通对话新输入不等于撤销命名；它们继续计数，供下个周期使用。

落库时原子检查会话存在、开关仍为 on、操作版本和请求身份仍有效，然后保存标题并推进公开版本。不接受旧请求“最后返回者覆盖”的行为。过期任务失败也不应向用户展示误导性的当前失败提示。

删除会话/项目、回退和恢复历史时使相关在途任务及合并请求失效。关闭会话标签、切换项目不取消任务。

持久化标题、开关、计数、首次输入状态和操作版本；在途任务与合并请求不做重启补跑。服务重启后保留已保存状态，等待下一次触发。

## 8. 前端数据与独立通知

现有 Thread 响应保留原字段，新增 `auto_rename_enabled` 和 `naming_revision`：

```json
{
  "id": "thread_id",
  "project_id": "project_id",
  "title": "面向投资人的产品路演",
  "auto_rename_enabled": true,
  "naming_revision": 3
}
```

上述 JSON 只展示本功能相关字段，不替代 Thread 的其他现有字段。内部输入计数、模型配置、密钥、完整命名快照不暴露给前端。

使用专门的命名操作接口承接面板动作，操作枚举为 `generate`、`manual`、`enable`、`disable`。manual 携带 title；其余操作不携带 title。保留现有手动重命名入口，但统一调用同一服务原语，原子完成标题与开关修改。模型生成请求异步接受，返回请求身份；同步操作返回权威 Thread，前端不自行拼接 updated_at 或开关状态。

项目级会话 SSE 独立于 Run SSE。`thread.naming.updated` 携带服务端 Thread 状态，`thread.naming.result` 携带请求身份及 `renamed | kept | failed | superseded` 结果，用于显式操作的简短反馈。结果中不包含模型原始输出或凭据。路由与事件契约见下文；Go/TypeScript 内部名称可按仓库规范确定，但不得重新依赖 Run 连接。

在同一项目历史代次内，前端只接受更新版本的命名状态；请求结果只反馈给匹配的显式操作。初次连接和重连需取得权威会话快照，并正确衔接后续事件，避免查询和订阅之间漏掉更新。回退/恢复或重启后以新的权威快照重建状态，不拿旧缓存的高版本拒绝恢复后的合法状态。

UI 直接替换会话标题；命名过程不生成 timeline 卡片、模型消息或 loading 历史。面板与命令操作提供简短反馈：已开启、已关闭、已更新、当前名称仍适合，或请求失败。打开面板的会话身份必须固定，切换会话不能把操作应用到错误会话。

### 8.1 REST 契约

以下是落实已确认产品行为的工程接口约定，不是新增用户决策：

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/threads/:id/naming` | 执行命名面板操作。 |
| `PATCH /api/v1/threads/:id` | 保留现有手动标题修改协议，内部同时关闭自动命名。 |
| `GET /api/v1/threads/:id` | 返回含命名开关和版本的完整 Thread。 |
| `GET /api/v1/projects/:id/threads` | 返回含命名状态的会话列表。 |
| `GET /api/v1/projects/:id/thread-events` | 独立会话事件流。 |

操作请求：

```json
{"operation_id":"client-generated-id","action":"generate"}
```

```json
{"operation_id":"client-generated-id","action":"manual","title":"季度经营汇报"}
```

enable 和 disable 使用同一结构，不提供 title。operation_id 标识一次用户操作；网络重试复用同一个 ID，新的用户点击使用新 ID。后端避免同一操作因 HTTP 重试再次重置计数或重复调用。复用相同 ID 携带不同参数返回冲突，不能误当新操作。

有内容的 generate 返回 `202`，响应包含 `operation_id`、`request_id`、`status: "accepted"` 和最新 `thread`。manual/enable/disable 返回 `200`，包含 `operation_id`、`status: "completed"` 和最新 `thread`。空会话 generate 返回 `200`、`status: "waiting_for_input"`，开关已为 on，但不生成 request_id、不调用模型。

命名操作响应同时返回当前 `stream_epoch`；既有 Thread 查询和 PATCH 响应通过统一响应头 `X-Thread-Stream-Epoch` 提供同一代次。前端在应用异步响应前核对项目代次和 naming_revision，防止历史切换前发出的旧 HTTP 请求在新快照之后返回并覆盖当前状态。

非法 action、多余参数、非法 title 返回 `400`；会话不存在返回 `404`。错误不得改开关、计数或原名。generate 已接受后发生模型失败，通过命名结果事件反馈，不把此前的 HTTP 接受结果伪装为成功改名。

### 8.2 SSE 契约

会话事件不使用强制要求 run_id 的主路事件封套，使用独立 `schema_version: 1`。所有事件 data 至少含 `project_id`、`stream_epoch` 和同一连接代次内的 `sequence`；SSE id 与该代次/序号对应。

| 事件 | 额外 data 字段 | 用途 |
| --- | --- | --- |
| `threads.snapshot` | `threads` | 首次订阅、重连及历史切换后的权威状态。 |
| `thread.naming.updated` | `thread` | 标题或开关等公开命名状态已提交。 |
| `thread.naming.result` | `thread_id`、`operation_id`（显式操作时）、`request_id`、`outcome`，失败时含安全 error | 反馈一次请求的结果。 |

outcome 为 `renamed`、`kept`、`failed` 或 `superseded`。事件中的 thread 是完整的前端 Thread DTO，禁止只传 title 让前端猜测开关或时间戳。updated 必须在事务提交之后发布；keep 不制造标题变化事件。过期请求的 superseded 不展示错误提示。

采用“订阅登记 + 权威快照 + 按序应用后续事件”的握手，服务器在两步之间暂存事件，避免快照读取期间出现丢更新窗口。本期不要求跨进程重放全部通知；重启或重连从快照恢复持久状态。旧连接及旧历史代次事件必须被丢弃，不能仅依赖可回滚的 naming_revision。

只对匹配当前用户显式请求的结果显示简短反馈；自动请求静默。浏览器断线期间的历史反馈不补成 timeline 记录。命名流重连不要求主路仍处于 running，主路 SSE 的关闭逻辑不关闭该项目流。

## 9. 失败与历史一致性

超时、供应商报错、工具调用不符合协议或标题不合法时，保留原名和开关，不立即重试。自动调用失败只写后台诊断；用户主动立即命名失败给予简短反馈，允许再次操作。实际发起过请求就消费本周期，避免每条新输入都重试同一次失败。

会话命名状态纳入项目快照清单并随会话恢复。版本字段可能随快照回到过去，因此防迟到写入必须同时检查不可复用的运行代次/任务身份，不能只比较可回滚的数字版本。

旁路短暂读取或保存状态需要与项目快照切换保持原子一致，但不能把整个模型调用放在主路的锁中。回退/恢复先使旧任务失效，再切换会话状态。自动结果不能绕过历史门禁修改另一历史代次，也不能替用户确认丢弃待恢复的旧未来。用户显式命名操作在回退状态下遵循现有项目历史修改约定。

命名结果属于会话元数据，不写入 PPT 创作文件或项目 Git，不创建主路 Run，也不伪装成主路完成事件。

### 9.1 持久状态与运行状态

| 状态 | 存储与职责 |
| --- | --- |
| `title` | 沿用 Thread 持久字段。 |
| `auto_rename_enabled` | 持久布尔值，新会话默认 true。 |
| `naming_revision` | 持久公开版本，命名公开状态修改时推进，供前端排序。 |
| `rename_operation_version` | 持久内部版本，人工操作改变它，使旧结果失效。 |
| `rename_input_count` | 持久输入计数，off 不累计，请求启动或重新开启时重置。 |
| `rename_first_input_seen` | 持久首次有效输入状态，不依赖主路执行成功；off 期间首次输入也标记已出现。 |
| 输入去重边界/记录 | 复用已接受输入身份或事务记录，防止同一输入重复计数。 |
| 操作幂等记录 | 防止同一 operation_id 重复产生副作用，按项目历史清单管理。 |
| 在途 request、取消句柄、至多一个合并请求 | 仅服务运行状态，重启不恢复、不主动补跑。 |
| 项目命名运行代次与事件流代次 | 防止删除/恢复/回退后复用旧任务或旧通知；不能通过恢复快照复活。 |

首次输入发生在 off 期间时不调用模型；之后 enable 只重启 5 次计数，不把已有会话伪装成尚未收到首条需求。新会话尚无输入时 enable 后仍保留首次触发资格。

收到有效输入时原子更新去重状态、首次状态和计数。命名任务开始时固定快照输入边界并重置本周期计数；模型返回时只条件更新标题等命名状态，不覆盖在请求期间更新的输入计数。启动时已消费但进程中断的请求不自动重发。

实现中可以调整内部字段命名或复用已有记录，但不能删去去重、并发版本、首次输入和历史代次这四类语义。新增字段、PO 映射、DTO、数据库定义、项目快照和恢复代码必须一起切换。

## 10. 实施与验收清单

实施需同步完成配置解析与服务装配、Prompt catalog、独立命名服务、持久化字段和快照清单、用户输入触发点、操作 API、独立事件通道、前端 Thread store、斜杠菜单与临时面板。

核心验收场景：

1. 首条需求触发一次；随后 4 次不触发，第 5 次触发；无工具调用计数或时间门槛。
2. 首次命名与主路并行；主路失败、取消或结束均不阻止结果写入。
3. 模型 keep 不修改标题，正常进入下一周期。
4. 表单和面板手动命名原子关闭旁路；off 后输入不计数；on 不立即调用。
5. 立即命名开启并绕过计数；空会话不调用；重复点击合并且旧结果不能覆盖。
6. 请求在途时 off、off→on、手动命名、删除或回退均使旧结果失效。
7. 超时和非法输出保留原名，自动失败不打扰用户，显式操作失败有反馈。
8. 主路 SSE 已关闭或用户切换会话时仍能正确同步命名状态；重连没有状态漏更新。
9. 重启不补跑在途请求；计数、标题和开关保留；历史恢复不接受旧代次写入。
10. rename 模型配置独立；主路选择列表不显示旁路模型；旧配置结构不再被接受。
11. 输入裁剪保留最近修订意图；模型只收到本会话命名快照与局部工具 Schema。
12. `/rename` 仅打开临时面板，不接受参数，不产生 timeline 命名过程记录。

遵循 AGENTS.md：实现阶段不运行计算机或浏览器自动化，验收交由用户手动完成；不调用子代理。Git 提交仅按用户明确授权执行，不推送远程仓库。
