# UI 设计规范

**本文记录已确认的前端 UI 设计约定，作为后续开发和修改界面的依据**。

### 全局底色与容器层次

- 浅色模式采用暖白面板、浅米灰画布和暖灰文字；蓝色继续表达主操作与交互状态。深色模式保留石墨蓝配色，沿用相同的圆角和容器层级，并使用对应的深色阴影。
- 颜色、圆角与阴影统一定义在 `frontend/public/interaction-tokens.css`，组件引用语义变量，不另行配置一套相近颜色。

| 表面 | Token | 浅色值 |
| --- | --- | --- |
| 工作区底色 | `workspace` | `#F8F6F2` |
| 顶部项目栏 | `titlebar` | `#F6EDE3` |
| 固定面板与工具栏 | `panel` | `#FCFAF7` |
| 面板内的次级区域 | `panel-muted` | `#F4F0EB` |
| 画布底色 | `canvas` | `#F8F6F2` |
| 输入与弹层表面 | `surface` | `#FFFDFA` |
| 普通边框与分隔线 | `border` | `#E8E1D8` |

- 顶部项目栏使用带轻微橙棕调的浅杏米色底色，与下方暖白面板形成轻微层次；深色模式沿用工作区底色。
- 边框保持低对比，正文与操作图标保持清晰；不通过降低整个容器的透明度获得柔和感。面板内部的标题、摘要与会话分隔线内缩，避免连续横线切割整个界面。
- 阴影只表达空间层级：固定面板和顶部工具栏使用 `shadow-panel`，输入框使用 `shadow-input`，底部悬浮工具条使用 `shadow-floating`，菜单和弹窗复用 `shadow-overlay`。浅色常规阴影采用暖灰色；底部悬浮工具条单独使用 `ui-shadow-floating` 的米棕色，带轻微橙调，以低透明度和柔和模糊表达厚度。不给普通按钮或列表项添加常驻阴影。
- 公共控件、导航与会话标签使用 `radius-control`（8px），菜单及命令卡片使用 `radius-card`（10px），编辑器面板、顶部工具栏、输入框和公共弹窗使用 `radius-panel`（16px）；底部悬浮工具条使用 `radius-pill`（999px）。侧栏朝向画布的顶角使用面板圆角：左栏右上角、右栏左上角为 16px；侧栏外侧顶角与中间顶部工具栏的顶角保持直角，底部保留圆角。侧栏内容随容器裁切，保证圆角完整；嵌套输入表面的圆角随外层扣除边框宽度。
- 三栏紧贴项目标签栏下沿，不添加顶部外边距；侧栏不添加左右外边距，中间顶部工具栏左右各内缩 8px。标题行共用 `workspace-header-height`（48px），保证图标、文字及下沿处于同一水平位置。浅色画布与工作区共用底色，避免在栏目间隙形成更深的色带。
- 左栏显示时，第一个项目标签的左下圆角与左栏最小宽度下的右上圆角对齐，标签起点复用布局计算出的最小宽度，不随左栏拖宽移动。标签滚动区预留完整圆角宽度；窄窗下品牌文字可省略，左栏隐藏时品牌区恢复自适应宽度。
- 编辑器栏目间仅保留 1px 接缝，分隔条默认透明；悬浮时在中部显示 36px 高的暖灰短柄，拖动和键盘聚焦时加深。保留扩大的拖动命中区域，不使用贯穿整栏的蓝色竖线。
- 界面底色不添加装饰性纹理、波浪或渐变，也不改变幻灯片内容及导出文件的配色；空状态沿用现有表现。

### 画布布局与输入框

- 基本信息、全局约束、目录结构隐藏底部画布工具条，不为其预留空白；页面设计稿、幻灯片与总览等页面视图显示工具条时，在内容下方预留工具条高度、底部距离和 12px 净间距。工具条默认位于该区域，仍可自由拖动。
- 设计稿与三个项目文档复用相同的紧凑内容节奏：模块间距为 28px，窄屏为 24px，适度收紧字段和内容元素间距，保持正文字号与行距。正文独立滚动，底部状态和操作仍保持可见。
- 幻灯片横向以中间工作区居中，纵向以网页可见区域的中线为目标，受顶部工具栏与底部工具条区域约束；适应画布时保持完整比例，缩放拖动范围跟随实际位置计算，全屏放映仍在全屏区域内居中。
- 输入框上下两区共用输入表面底色，上方模式与范围区仅叠加极淡面板色，中间分界线弱化，不将输入区绘制为带独立顶部圆角的嵌套卡片。

### 工作区字号层级

- 左右栏目标题使用 16px；项目标签、左侧项目文档导航及章节／页面主标题使用 15px；会话标签、顶部工具栏、底部画布工具条以及输入框的模式／范围控件使用 14px。
- 栏目标题与主要操作图标使用 18px，保留原有描边宽度；下拉箭头、更多操作等辅助图标，以及统计、模型名称等辅助文字沿用原尺寸。
- 通过文字和图标在容器内的占比增强饱满感，保留既有栏目高度、模块间距与选中字重规则，不整体缩放界面。

### 按钮的颜色语义

- 按钮颜色由操作含义与交互角色决定，不按排列顺序分配，也不要求同时出现所有颜色。
- 对于先选择、再提交的审批按钮组，所有选项统一使用中性色；选中后使用极淡暖灰背景、深色文字、适度加深的暖灰边框与较高字重，蓝色集中在「继续」等提交按钮。
- 按钮保留明确的文字标签，不仅依赖颜色区分操作。

| 颜色 | 语义 | 颜色 Token |
| --- | --- | --- |
| 绿色 | 成功、完成、已批准等结果反馈 | `success` / `success-soft` |
| 黄色 | 警告、确实需要关注的状态 | `warning` / `warning-soft` |
| 红色 | 删除、停止等危险操作，失败或拒绝结果 | `danger` / `danger-soft` |
| 蓝色 | 当前选中位置、主操作、提交、确认 | `accent` / `accent-soft` / `selected-foreground` |

### 全局悬浮态与选中态

- 普通按钮、图标按钮、导航、标签页、列表、管理字段和菜单的浅色悬浮态与持久选中态均使用极淡暖灰；悬浮时使用深灰文字，选中时使用蓝色文字／图标与较高字重。深色模式沿用对应的深色交互 Token。
- 颜色唯一来源为 `frontend/public/interaction-tokens.css`，应用与隔离的画布 iframe 共用；Tailwind 颜色引用该文件的 CSS 变量。禁止在业务组件中重新写十六进制状态颜色或黑色透明叠加。
- 公共状态规则位于 `frontend/src/components/ui/interaction.css`。优先复用 `Button`、`IconButton`、`Select`、`DropdownMenu`；自定义控件复用同一组状态类，审批选择项统一复用 `DecisionControls` 与 `ui-decision`。

| 状态 | 背景 | 文字／图标 | 公共用法 |
| --- | --- | --- | --- |
| 悬浮、键盘候选高亮 | `hover`：`#F6F2ED` | `ink`：`#2A2723` | `ui-interactive`；程序控制候选高亮用 `ui-highlighted` |
| 持久选中 | `selected`：`#F6F2ED` | `selected-foreground`：`#2558DB`，字重 600 | `ui-selected`，或 `ui-interactive` 配合正确的 ARIA／Radix 选中状态 |
| 审批选项选中 | `selected`：`#F6F2ED` | `ink`：`#2A2723`，字重 600 | `ui-interactive ui-decision` 配合 `aria-pressed`；边框使用 `border-strong` |
| 选中后悬浮／聚焦 | 保持选中背景 | 保持选中文字 | 选中态优先于悬浮态，不退回普通悬浮色 |
| 菜单展开 | 保持悬浮背景 | 普通深色文字 | `ui-interactive` 的 `data-state="open"`；用箭头方向表达展开 |
| 禁用 | 保持禁用样式 | 沿用禁用色及透明度 | 禁用控件不响应悬浮、候选高亮或展开反馈 |

- `accent-soft` 独立使用浅蓝 `#E8EFFF`，与极淡暖灰的 `selected` 分开；主操作与蓝色提示表面使用 `accent-soft`，当前位置与普通选择使用 `selected`，不将两者重新绑定为同一个变量。
- 选中除了颜色，还应按组件语义使用勾选、指示条、下划线或字重；键盘／鼠标正在浏览的候选项不等于已经提交的选择。
- 导航、标签、筛选、分段切换、菜单与审批／问答选项的主文字，常态使用 400–500 字重，选中使用 600；只悬浮或展开菜单时不加粗。子元素不要用固定字重覆盖选中反馈，说明文字、输入内容和辅助数值保持原字重，图标维持原描边宽度，不通过放大字号或使用 700 字重强化普通选项。
- `aria-selected` 用于标签和列表选择，`aria-pressed` 用于切换按钮，`aria-checked` 用于开关与单／多选菜单；不要用菜单展开状态代替选中状态。
- 普通小字号选中文字统一用 `#2558DB`，不要通过降低文字透明度或使用更浅的主蓝色来削弱选中反馈；审批选项使用清晰的深色文字。
- 演示文稿导航中的页面选中时，序号与标题统一使用选中蓝，保留左侧细蓝条，外边框使用暖灰 `border`；拖动柄与更多操作按钮保持中性色。

### 语义操作与画布例外

- 主按钮使用 `ui-primary`：浅蓝 `accent-soft` 背景、蓝色文字与主蓝色 20% 的细边框，悬浮／键盘聚焦时保持蓝色主操作语义；禁用时不变色。
- 批准、拒绝、手动编辑与跳过等决定选项使用中性色；删除、停止等危险操作保留红色，成功反馈使用绿色，真正的警告使用黄色。复用 `ui-danger`、`ui-success`、`ui-warning`，实心语义操作使用 `ui-danger-solid`／`ui-success-solid`。
- 复制、重试、展开等普通操作使用普通悬浮规则；复制成功可以通过成功通知表达，不因按钮悬浮而变绿。
- 通知关闭按钮可沿用所属通知的语义色，所有变体颜色同样集中在交互 token 中。
- 画布元素悬浮、拖动框选、已添加选区与缩略图选中统一使用 `accent` 蓝色描边；元素悬浮填充为主蓝色 6%，框选及已添加选区填充为 12%。不再使用另一套蓝紫色，不用不透明填充遮挡内容。
- 画布选择描边表达对象选择，不属于控件焦点描边；启用开关可以使用实色主蓝表达开启状态，栏目分隔条使用暖灰短柄反馈。
- 普通文本与 CodeMirror 源码预览的文本选区均使用 `selected` 背景，移除编辑器默认的灰色／淡紫色选区。

### 焦点状态无描边

- 控件获得焦点时不添加蓝色边框、外圈或轮廓，避免全局与组件样式叠加形成多层线条。
- 键盘焦点使用与悬浮一致的背景反馈；已选中控件保留选中态，文字标签可增加下划线辅助定位。

### 设置表单布局

- 模型分配、快捷键等设置表单共用内容容器与分组样式；分组卡片占满内容区，与页面标题左右对齐，不为单独栏目设置不同的最大宽度。
- 设置项采用左侧字段名称、右侧设置值的行式布局，垂直居中；必要的简短说明放在字段名称下方，相关设置项归入同一分组，以细分隔线区分。
- 同类设置行统一内边距、行间距和控件宽度，右侧控件保持右对齐；字段或说明较长时自然换行，不挤压控件。
- 窄屏下改为上方字段、下方设置值，控件占满可用宽度，避免水平溢出。

### 项目文档只读状态

- 基本信息、全局约束、目录结构共用 `DocumentCanvas` 的底部状态栏；任务运行、提交、导出等原因导致暂时不能修改时，将原有原因文案放入该状态栏，不在标题与正文之间显示红色提示。
- 状态栏使用 `panel` 底色、细暖灰上边框与统一的 13px `text-600` 文字，左右内边距与文档正文一致；窄屏允许自然换行。文档正文独立滚动，状态栏保持可见。
- 普通只读状态使用 `role="status"`，原因解除后状态栏消失；加载、保存失败以及版本冲突继续使用独立的错误反馈，不将其降为普通状态。
- 无只读状态、无底部操作时不渲染空状态栏；已有底部操作复用同一个底部容器。

### 最右栏目的操作按钮样式

- 输入框底部的操作按钮采用透明背景、无可见描边，视觉上直接贴合输入框背景，不形成独立的控件块或分隔感。
- 底部辅助按钮默认态仅展示图标，收起文案，保持输入栏在紧凑宽度下的整洁与低干扰；悬浮时展开文案，以动态过渡效果揭示按钮用途，但仅作为临时反馈，移出后恢复图标态。
- 常规态不引入背景色、阴影或边框，交互反馈主要通过悬浮展开文案与轻微变色传达，避免在输入区堆叠视觉层级。

### Timeline 工具调用行

- 工具调用在时间线中统一以 `icon + text` 的紧凑行呈现，图标、文字对齐方式及上下内边距保持一致。
- 摘要默认单行显示，超出宽度时省略，图标与展开控件不压缩，同时有详情内容的行需要支持折叠和展开。
- 外层条目、分组内条目及分组标题与首条子项之间，间距统一为 8px。
- 用户随请求选择的技能和引用的组件不单独显示在时间线中，但仍正常随请求发送；仅 Agent 主动调用加载工具时显示「已加载技能／组件」记录。
- 渲染调用统一使用「正在渲染第 N 页幻灯片」「已渲染第 N 页幻灯片」「渲染第 N 页失败」，分组显示「已渲染 N 张幻灯片」，不使用「检查」「渲染通过」「渲染未通过」作为调用摘要。
- 动词使用【读取】、【编辑】、【渲染】、【执行】、【加载】、【完成】
- 名词使用【内容要求】、【目录结构】、【视觉要求】、【设计稿】、【幻灯片】、【技能】、【组件】、【命令】

### 图标统一使用 Lucide

- 界面功能图标统一使用 `lucide-react`，同类操作保持一致的图标含义。
- 默认沿用全局 `1.75` 的描边宽度，保持线性图标风格一致。
- 纯图标按钮提供明确的 `aria-label` 和提示文字，优先复用公共 `IconButton`。
- 各模块的对象与图标映射参考同目录的 [ICON.html](ICON.html)，其中已列出的对象以该文件为准；本文不重复维护图标映射表。未列出的图标沿用前端现有组件和同类操作的图标约定。

### 公共组件

- `Dialog`：弹窗统一基于公共组件实现，保持遮罩、容器、标题、操作区和关闭交互一致；新场景优先组合现有组件，可复用的模式继续沉淀为公共组件。
- `ConfirmModal`：用于操作确认弹窗。
- `FormModal`：用于表单填写与编辑弹窗。
- `PickerModal`：用于资源或对象选择弹窗，保留复合选择场景所需的结构与交互。
- `Select`：用于表单单选，不使用浏览器原生可见下拉列表；列表默认在触发框下方间隔 6px 展开，空间不足时向上避让，不覆盖触发框。列表与触发框等宽，长内容可换行、长列表内部滚动，支持禁用、空值、方向键选择、文字定位和 Escape 关闭；通过 Portal 避免裁切，选择选项时不触发外层编辑卡片关闭。
- `DropdownMenu`：用于操作菜单，与 Select 共用暖白底、细暖灰边框、适度阴影和 `radius-card` 圆角的面板样式；深色模式引用对应表面颜色。选项悬停和键盘高亮使用 `hover`，已选项使用 `selected` 与 `selected-foreground`，以勾选标记当前值，不添加蓝色焦点描边。
- `MarkdownMessage`：按原始 Markdown 语义渲染 Agent 消息，加粗只改变字重，标题仅由 Markdown 标题语法决定，不根据独行、字数或编号自动提升。
- `LongContent`：用于长内容截断与展开，默认限制展示高度，超出时显示渐隐入口与「展开全部」，未超出时不显示切换按钮，操作区不参与截断；展开后「收起」按钮居中放在内容区域内部底部，与正文使用相同背景，在正常文档流中独占一行并保留间距，不遮挡正文。
- `GlobalToasts`：全局通知统一通过 toastStore 触发，在视口顶部居中显示；普通、成功、警告、错误通知使用对应的语义图标与颜色，每条显示 3 秒后自动关闭，倒计时动画与显示时长一致，并支持手动关闭。
-  `CommandActivity`：六类命令统一使用 `surface` 底色、细灰边框、`radius-card`（10px）圆角容器，头部展示图标、命令名、时间及单行省略的标题，悬浮可查看完整标题；运行时显示真实阶段进度，完成后默认折叠，失败或停止后提供重试。正文复用 LongContent，结果与操作区通过细线分隔；调整建议、重试、复制及主操作优先同一行排列，窄栏自然换行。
