# 智能体设置与失败展示

日期：2026-10-10。状态：已实施，未执行自动验证，待用户手动验收。

## 已确认决策

设置新增「智能体」栏目，采用现有设置页的分组、行式布局和开关样式。三个设置项均在名称下提供简短说明：

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 显示工具调用失败 | 关闭 | 隐藏单次失败及执行前阻止记录，Agent 继续依据完整工具反馈修复或重试。打开后显示这些记录。 |
| 资源编辑审批 | 开启 | 统一控制内容要求、视觉要求和目录结构的创建与修改；关闭后跳过人工等待，直接提交真实工具结果。 |
| 高风险操作审批 | 开启 | 统一控制命令修改文件、敏感文件读取和扩大页面修改范围；关闭后跳过后续请求的人工等待。 |

三个开关全局持久化，点击保存成功后热更新。资源审批和高风险操作审批独立，在每次进入相应审批前读取最新设置；已出现的待审批项保持原流程，恢复同一待审批调用时也不能因开关关闭而自动提交。

保留实际工具执行、失败预算、原子提交、基线冲突校验及模型 Observation。计划审批和用户问答沿用原流程，不受这两个审批开关控制。用户已提交的拒绝决定仍保留可见记录。

## 配置与 API

`config.yaml` 增加 `agent`：

```yaml
agent:
  show_tool_failures: false
  require_resource_approval: true
  require_high_risk_approval: true
```

未配置字段使用上述默认值，显式值必须为布尔值。配置不进入固定模型快照；运行中通过原始 live Registry 读取审批设置。

- `GET /settings/agent`：读取设置与独立 `revision`。
- `PUT /settings/agent`：提交 `revision` 和三个必填布尔值，拒绝缺失字段、未知字段及过期修订。
- `POST /settings/agent/reload`：加载有效磁盘配置后返回智能体设置。

智能体与模型设置共用配置管理器的锁及原子文件写入。分别维护修订身份，修改智能体设置不替换当前模型快照；任一设置保存都保留另一类字段及原有凭据。外部文件修改需先刷新，不能直接覆盖。

前端在保存成功后更新共享 store，使用跨窗口通知及窗口重新激活时的读取同步设置；忽略与本窗口保存交错的旧读取响应。保存失败保留服务端确认的值。

## 高风险操作审批

说明文字：开启后，命令修改文件、读取敏感文件或扩大修改范围需手动审批。

命令策略仍先做完整预检。只有 `confirm` 判定可以因开关关闭跳过人工等待；`deny` 仍直接阻止。命令白名单、语法限制、项目路径限制、单调用限制、完整文本读取、版本和原子写入校验全部保留。三类全局参考仍必须通过专用编辑工具，不能用命令绕过资源审批。自动执行在命令审计中记录 `approval: disabled`，不伪造用户批准事件。

`request_privilege` 关闭审批时自动授权本次申请的新增页面，保持原范围并增加修订，不直接开放全部页面。它与人工审批共用范围和 checkpoint 的原子保存流程；自动扩圈用 `scope.updated` 的 `cause: approval_disabled` 发布真实范围变化，不发布虚假的人工审批请求或回答，模型反馈也不标记为用户回答。

待扩圈 checkpoint 记录 `automatic`，确保自动授权提交前后中断恢复仍按该次操作的来源处理，并避免重复授权。已有人工待审批项不读取新开关来改变其决定来源；恢复时仍等待原答案。

## 失败展示与最终原因

工具失败事件、持久化记录及模型反馈继续完整保留。前端在 Timeline 分组前应用当前开关，实时记录与历史记录遵循同一展示规则，开关切换无需新建任务。正常成功记录及最终任务状态始终可见。

运行内自动 Git 提交失败同样隐藏；用户主动发起的提交和其他独立命令保持原有反馈。人工拒绝属于已提交的决定，不因失败展示开关消失。

因连续工具修复失败而停止时，终止事件的原失败说明附带最后一次实际工具失败的公共原因。依赖跳过不能覆盖实际原因；成功修复后清除该原因。公共原因进入 checkpoint，最终展示不泄漏原始内部报错、请求信息或凭据。其他任务停止原因沿用已有终止投影。

## 手动验收

1. 在设置中找到「智能体」；确认默认失败展示关闭、资源审批与高风险操作审批开启。切换、刷新及重启后确认保存值。
2. 运行期间关闭失败展示，确认失败工具行消失，后续修复成功仍展示正常结果；重新开启后确认记录可见。终止失败原因始终可见。
3. 开启审批时编辑三类资源，确认仍需手动决定。关闭后重新触发创建或修改，确认直接提交并展示真实结果与 diff。
4. 在已有待审批或手动编辑草稿时关闭审批，确认当前提案保持等待；处理完成后，下一次操作按新设置执行。重启并恢复待审批任务时也保持此边界。
5. 在其他窗口切换设置，确认同步；交错保存模型与智能体设置，确认两类字段均保留，冲突或保存失败不会展示为成功。
6. 高风险操作审批关闭时，受支持的命令修改、敏感文件读取及所请求页面的扩圈直接执行，不出现人工审批卡片；禁止执行的命令仍被阻止。重新开启后，后续高风险请求恢复人工审批。
7. 已等待命令或扩圈审批时关闭开关，确认原项仍等待，重启恢复也不自动放行；自动扩圈在原子提交后中断，恢复不重复提交、不要求补做人工审批。独立切换两个审批开关，确认互不影响，计划仍需原审批。
