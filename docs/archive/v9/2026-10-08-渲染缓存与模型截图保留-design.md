# 渲染缓存与模型截图保留

日期：2026-10-08。状态：已实施；模拟渲染器定向测试、模型协议测试及 TypeScript 检查通过，真实渲染与界面由用户手动验收。

## 问题与目标

本轮后端日志记录了 9 页、55 次渲染，其中 30 次的 HTML 和完整渲染依赖未变化；不同 screenshot_id 的历史图片持续进入模型请求。

未变化的输入复用截图和诊断。每页只向 LLM 保留最新有效截图，旧 PNG 和 screenshot_id 保持不可变，用于历史展示。本次不更改防循环算法、阈值或终止行为，也不修改已审定的核心提示词。

## 缓存与有效性

- 缓存复用检查 HTML、manifest、outline 页面节点、spec、design、运行时 frame、主题 CSS、内嵌样式及字体等共同资源。
- Worker 记录实际请求的项目文件内容哈希，覆盖图片、额外样式、脚本和本地字体；缺失文件也记录，新增该文件使截图失效。只检查已请求的资源，不扫描整个项目。
- 渲染前后复核依赖，实际加载的资源内容必须与保存时一致；完成证据、read_image、项目状态及 Reviewer 使用相同依赖规则。
- 最新索引保存原始诊断和资源哈希；PNG 缺失、损坏或依赖变化时重新渲染，不用缓存结果掩盖失效。
- inspect_selectors 被缓存诊断覆盖时可复用，只返回本次请求的选择器；新增检查需求执行新渲染。字体未完成加载的诊断不复用。
- 复用沿用原截图的 run_id、screenshot_id、引用和时间，不创建新 PNG。前后端预览校验允许来自同类受控截图路由的历史 Run 地址，实际文件读取仍由原 Run 所属项目解析。

## 模型上下文与历史

- 同页新截图替换 Run 中保留的旧截图引用；不同页面分别保留最新截图，用户上传的原图保持独立。
- 每次请求准备时检查截图是否仍为当前有效版本，移除过期、被替代和已删除页面的截图。
- 移除旧工具消息和派生图片消息中的历史像素；工具调用与回执配对、文本诊断继续保留。相同截图重复读取时仅保留一份图片。
- 检查点保存当前图片集合；压缩与恢复都通过相同筛选，不重新补入历史截图。Provider 的历史哈希变化规则继续处理图片替换后的协议重放。
- 最新索引按页更新，历史截图文件及其授权引用不覆盖、不删除；历史活动继续展示当时的截图。
