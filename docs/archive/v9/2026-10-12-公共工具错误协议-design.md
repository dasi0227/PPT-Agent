# 公共工具错误协议

日期：2026-10-12。状态：代码与工具文档已切换；未运行测试、构建、模型调用或浏览器验证，待用户手动验收。

## 返回约定

普通工具和提交类工具的失败文本统一使用四个必填字段：`code`、`category`、`reason`、`measure`。六种 category 保持不变；reason 解释实际失败原因，必要时自然包含字段路径。类型校验继续使用原校验器，直接保留其错误原因，不重复拆分期望值和实际值。

错误正文不再重复当前调用、操作、资源、字段和重试元数据。外层 Responses call_id / Anthropic tool_use_id 继续关联当前调用。Runtime 重试策略、持久化 ToolResult、日志操作名与 HTTP 公共错误接口保持各自职责。

`DEPENDENCY_FAILED` 额外返回 `dependency_call_ids` 字符串数组。调度器等待全部前置结束后，收集 success 依赖中所有未成功的调用；已成功或仅 wait 的调用不进入数组。当前调用不执行，回执、事务和批次顺序沿用原机制。

错误可按需携带工具专属诊断：命令输出、验证 findings、完成检查 issues、HTML checks 或用户 feedback 等。完成问题中的补救措施也使用 measure；验证 findings 将字段路径并入 reason。渲染存在截图但有阻断问题时，失败文本采用同一公共协议，并保留截图和模型诊断，不披露内部图像路径或持久化证明。

## 披露入口

`backend/prompts/core/error.md` 是独立公共协议，模块 ID 为 `core.error`；`backend/prompts/playbook/retry.md` 只保留 execute 的重试流程。两个文件复用标准提示词加载器，各自记录版本与内容哈希，不使用分段标记或提取代码。

- chat、ask、plan、execute 每个请求披露一次公共模块；只有 execute 另行加载重试行为。
- Reviewer、rename、compact、polish、handoff、commit 的初始政策加载一次公共模块，纠正轮沿用上下文。
- Reviewer 的持久化 prompt manifest 记录公共模块；命名、压缩等上下文估算包含实际注入内容。
- 工具 OutputSchema 和 provider description 仅包含正常输出约定，删除公共错误 Schema 工厂及提交包装层。
- `backend/prompts/TOOLS.md` 保留原工具 review 格式，只提取工具自身描述、输入和正常输出。该文件不作为生产提示词嵌入。

## 清理范围

删除仅用于旧模型错误正文的 ErrorResource 类型、AgentError.Resource / CallID、旧 Schema 工厂、重复类型错误解析和字段生成。保留有实际消费者的操作日志、重试策略、校验字段定位、依赖资源分析和外层调用关联。没有旧协议别名、双读、过滤旧字段或历史数据迁移。
