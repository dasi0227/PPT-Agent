# 最终变更总结与写入格式化

日期：2026-10-01。状态：已实施，待用户手动验收。

## 1. 范围

落实已确认的 [最终变更总结原型](../demo/2026-09-30-final-change-summary-demo.html)。仅替换最终总结中的完整源码展示；单次工具调用继续沿用现有展示。成功、取消及失败的终止事件均携带已保存内容的任务净差异。

## 2. 任务基线与冻结结果

复用 Run 开始前持久化的 review baseline，终止时与实际项目文件比较；继续同一 Run 使用原基线。恢复到原值的内容不进入总结，不累加中间操作统计。比较范围沿用创作文件边界，排除 `.runtime`、`.git`、`.run`、`.commit-tmp`、`versions`。

差异结构随 `message.final`、`run.completed`、取消及失败事件持久化，前端直接展示该事件中的旧值、新值及行号。打开历史记录不重新读取当前文件生成差异；后续任务不会改变旧总结。预览操作仍打开当前文档。

`.spec.json` 按 `slide_id` 拆分为页面设计稿条目；物理集合文件的重排和格式变化不产生其他页面变更。条目名称与页序在终止时冻结，已删除页面沿用原页序。

## 3. 公共事件结构

`PublicTarget` 增加终止投影 `diff`，单次工具目标不携带此字段。沿用现有公共事件版本及业务目标类型；前后端同步采用同一结构。

- `kind`：`outline`、`fields`、`text`、`binary`、`unavailable`。
- `status`：`added`、`modified`、`deleted`。
- `filename`：用于显示文件名。
- 字段差异使用 `fields[]`，每项具有 `field`、可选中文 `label`、`rows[]`；行的 `kind` 为 `removed` 或 `added`，`value` 为 JSON 编码的值字符串。
- 目录差异使用 `groups[].rows[]`，保存节点类型、缩进深度、章节编号和旧、新文本，详见 [目录结构树形差异](2026-10-01-outline-change-summary-design.md)。
- 文本差异使用 `hunks[]`，包含新旧起始行、行数及 `rows[]`；行携带 `kind`、`text` 和对应的 `old_line` / `new_line`。未变化行同时具有两侧行号，删除和新增行仅具有各自侧的行号。区块间被省略的未修改行保存为后一区块的可选 `context_before[]`，使用相同行结构，且只允许 `context` 行；无省略内容时不携带。
- 二进制文件显示文件状态；快照读取或 JSON 解析失败显示实际失败状态，不伪装成完整差异或给出错误计数。

字段值编码为字符串，避免任意业务 JSON 键名与公共事件禁止透传的内部字段冲突；展示时解析值并作为 React 文本渲染。HTML 差异同样按文本渲染，不执行源码。

## 4. 差异和统计

JSON 使用语义字段差异，忽略缩进、对象键顺序。标量新增 `+1`、删除 `−1`、修改 `+1 −1`；数组按增删项计数，保留重复项及顺序，每个改动项为一个单位。对象字段递归展开，数组对象作为一个完整项。显式 `null` 与字段不存在分别处理。

大纲按稳定节点 ID 生成独立树形差异，展示章节、子章节及页面的标题、目的和位置变更；保留淡色层级上下文，不展示移动说明或目录内部省略按钮。每条红绿行计为一项，插入、删除节点不把其后的所有节点误计为移动，父标题修改或位置变化不把全部子节点误计为独立变更。

HTML 使用后端序列差异算法生成三行上下文的统一差异块，增删统计来自同一份差异行，未调用 Git。数字为实际保存文件的行号。JSON 数字为语义单位，HTML 数字为文本行；外层仅汇总变更对象数量，不混加两类单位。

## 5. 前端展示

复用 Timeline 卡片、公共颜色、预览按钮和长内容展开控件。总结条目右侧使用绿色 `+N`、红色 `−N`；展开后的共享差异卡片也在文件名旁边显示该文件的计数，右侧保留预览操作。单次工具编辑仅在文件卡片显示计数，不放到工具调用行。JSON 展示字段名称，同字段删除行集中在新增行之前，字段之间使用水平分隔线；复用中文语义标签。HTML 展示差异块、新旧行号及红绿增删行，不展示 `@@` 原始区块标记。连续变更合并为一个区块，前后保留三行上下文；间隔较远的区块用浅色分隔带和省略图标区分，点击后展开当时保存的未修改行，再次点击可收起。只有一个区块时不添加分隔带。

省略内容随差异事件冻结，展开不读取当前文件、不执行 HTML，也不改变增删统计。该展示同时用于最终总结与单次工具编辑。历史事件中未保存的省略原文不从当前文件补取。

差异内容不自动折行，支持内部水平滚动并隐藏滚动条，长内容默认收起。已删除或当前不可预览的页面禁用预览。取消和失败仍保留已完成编辑的总结。

## 6. 保存格式

JSON 创作资源写入时采用两空格缩进并带末尾换行。HTML 完整写入或精确替换成功后、校验与提交前使用 Prettier 统一换行、缩进；复用 render-worker 的 Node 环境，新增固定版本的 Prettier 依赖。采用严格 HTML 空白敏感配置，保留文本空白语义并格式化内嵌 CSS / JavaScript。

受限 `run_command` 的 HTML / JSON 编辑也在提交前格式化；格式化失败不保存文件。哈希、版本戳和后续读取得到的是格式化后的实际内容。主源码视图直接显示并复制实际保存源码，避免仅展示时格式化导致行号和编辑原文不一致。

结构化资源读取继续使用紧凑模型观察；HTML 和大纲读取保持实际源码，供精确文本替换。HTML 编辑后应重新读取保存源码再制作后续精确替换。

## 7. 手动验收

遵循项目规则，不运行自动测试、构建或浏览器验证；已补充复杂差异逻辑的回归用例并同步受影响的界面测试。

- 同一任务修改标题两次、删除并新增数组项：最终显示原始值到最终值，计数与可见红绿项一致。
- 修改后恢复到任务开始的值：最终总结不再列出该字段或文件。
- 编辑其中一个页面的设计稿：不列出集合中未变化的页面；数组重复项的增删数量正确。
- 修改 HTML：看到保存文件对应的新旧行号、红绿差异、内部水平滚动和展开收起。
- 在相距超过六行的位置修改 HTML：不出现 `@@`，区块之间显示可点击的省略分隔带；展开内容的双侧行号连续，计数保持不变，再次点击收起；完成后修改当前文件不影响历史展开内容。
- 插入大纲页面、移动已有页面、重命名父章节：仅呈现实际节点变动，避免出现批量虚假移动。
- 完成后另一次任务再次编辑文件，并重载历史：旧总结值与计数保持不变。
- 任务途中取消或失败，以及继续同一任务：保留已保存差异，继续后的最终总结沿用原始基线。
- 检查实际保存的 JSON / HTML 文件、源码视图和复制结果；均以文件内容为准。格式化失败时确认原文件未被替换。
