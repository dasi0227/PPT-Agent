# 全局文件打开设置

设置页「文件」栏目提供四个永久内置选项：系统默认应用、VS Code、文本编辑、在访达中显示。默认使用系统默认应用。下拉列表不提供「其他应用」占位选项。

「添加应用」按钮打开系统 Application 选择窗口，添加的应用逐项显示在默认打开方式下方，并以应用名称加入下拉列表。添加不会改变当前默认方式；相同规范路径去重，取消选择不修改配置。每个自定义应用提供「删除应用」，没有更换按钮；删除只移除配置，不删除磁盘上的应用。删除当前默认应用时，同一次保存中将默认方式切回 system；删除其它应用保留当前选择。

选择和增删均立即保存；资源库、Agent 活动和最终结果中的文件图标直接执行当前配置，悬浮提示显示对应动作。

## 数据

SQLite `file_settings` 为全局单行表，与项目无关：

| 字段 | 含义 |
| --- | --- |
| id | 固定为 1 |
| open_with | system / vscode / textedit / finder / custom |
| custom_app_path | custom 时保存列表内选中应用的绝对 .app 路径，其余为空 |
| custom_apps | JSON 数组，保存自定义应用的 name 和规范绝对 path，默认 [] |
| revision | 单调递增的并发保存版本 |

数据库为配置的唯一持久化来源，浏览器仅缓存读取结果。窗口聚焦、可见性变化以及其它窗口保存通知会触发重读。保存使用 revision 比较更新，冲突不覆盖现有值。应用名由 .app 名称派生。新增路径验证应用包；已注册但后来被卸载的应用允许保留或移除，避免阻塞其它设置操作。选择、列表和版本在一条 SQL 更新中原子保存。

开发数据库格式切换至 3；按仓库开发约定不提供旧结构迁移或兼容读取。已有数据库保持原样，旧工作目录启动会提示格式不兼容，需要使用新的工作目录（后端启动参数 `-work-root /绝对路径/新目录`）。

## API 与打开行为

- GET `/api/v1/settings/files`：返回配置、应用名称及当前平台是否支持。
- PUT `/api/v1/settings/files`：严格校验配置并以 revision 保存。
- POST `/api/v1/settings/files/pick-application`：打开 macOS 应用选择窗口，返回名称与路径；取消返回 application=null，不修改配置。
- POST `/api/v1/files/open?path=...`：读取最新配置并打开文件，成功返回 204。

后端生成的 open_url 统一为上述 POST 入口；前端公共 FileOpenButton 调用接口，不作为网页链接导航。没有旧 vscode:// 协议兼容分支。

macOS 使用参数数组调用 `/usr/bin/open`，系统默认应用不加额外参数，VS Code 使用 `-b com.microsoft.VSCode`，文本编辑使用 `-e`，访达使用 `-R`，其他应用使用 `-a <app>`。不拼接 shell。文件必须存在、是普通文件，且解析符号链接后位于工作目录中。新增或实际打开时，自选应用必须是存在的 .app 包并含 Info.plist。失败显示提示，不自动改用其它应用。

选择应用使用固定 AppleScript 的 `choose file`，直接从 `/Applications/` 打开系统文件选择窗口，仅允许选择应用程序包（`com.apple.application-bundle`），单选且不展开包内容。用户可以切换到 `/System/Applications/`、`~/Applications/` 或其它目录选取应用；不依赖系统应用列表。最长等待两分钟，同一时刻只允许一个选择窗口，取消后保持原配置。

原生操作要求本机 Host、同源 Origin 和 JSON 请求；跨站请求和表单不能触发。GET 不会唤起应用。远程部署和非 macOS 打开方式不在本次支持范围。

## 验收

自动检查覆盖应用列表持久化与冲突、重复添加去重、删除选中应用回到系统默认、已卸载应用仍可移除、打开参数、路径与符号链接边界、选择取消、保存失败保留原配置、同源请求约束及公共按钮调用。

按项目约定，浏览器和真实应用操作由用户手动验证：检查四个内置选项；添加多个应用并在下拉框中选择；重复添加、取消选择、删除非默认应用及删除默认应用；刷新页面及重启后确认保留；移除文件或所选应用后确认错误提示。验证前需重启后端，并使用格式 3 的新工作目录。
