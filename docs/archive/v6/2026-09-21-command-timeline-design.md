日期：2026-09-21。以用户确认的 `docs/demo/2026-09-21-command-timeline-demo.html` 为视觉依据；本文覆盖此前关于显式 rename 等待后续输入、前端保留重试版本的约定。

## 展示与交互

2026-09-22 最新视觉约定见 [命令统一容器设计](2026-09-22-command-unified-component-design.md)，覆盖下述分离式摘要、彩色标签与独立详情卡片的旧布局。真实进度、取消和历史恢复语义保持不变。

六种命令共用 `CommandActivity`：紧凑摘要可点击展开；无折叠箭头；成功绿色；完成态详情卡片沿用计划卡片边框、圆角与留白。进行态节点全宽贴在时间线，停止在标题右侧；失败与停止只有摘要及同位置重试入口，不展开错误详情。

2026-09-22 更新：完成态详情卡片改为全宽，与摘要行整体左右边界对齐，取消图标区域的外部缩进；摘要与卡片间距为 8px，正文保留 16px 内边距。已处理计划、已回答问题、工具命令输出和渲染预览同步使用全宽布局，窄屏不恢复缩进。

| 命令 | 时间以外的元信息 | 展开内容 | 推进节点 |
| --- | --- | --- | --- |
| kickoff | 无 | 交付内容 | 读取项目 → 组织目标 → 生成简报 |
| handoff | 无 | 交付内容 | 梳理进展 → 提炼待办 → 生成交接 |
| commit | 分支、commit id、files、增删行数 | 提交项目 | 整理变更 → 生成说明 → 写入版本 |
| compact | 手动／自动、窗口占比变化、回收 Token | 压缩总结 | 读取上下文 → 提炼摘要 → 更新上下文 |
| rename | 手动／自动 | 旧名称 → 新名称 | 理解会话 → 生成名称 → 更新名称 |
| polish | 无 | 润色后内容 | 理解意图 → 优化表达 → 生成建议 |

kickoff／handoff／polish 的建议输入直接呈现，可为空；Enter 或独立重试按钮提交。重试黄色悬停，复制绿色悬停，新建会话和应用到输入框蓝色悬停，其余时刻保持中性。polish 完成后只给出建议，点击应用才替换输入框；下一次带建议重试以最新润色文本为输入。

rename 的显式生成由 `/rename` 或菜单点击立即触发，不依赖新消息。自动后台命名和 Agent 发起的命名不新增命令行；用户自定义标题仍从已有管理入口操作，结果显示旧名到新名，详情不再提供自定义或重新生成按钮。

## 真实进度

kickoff、handoff、polish、手动 compact 和显式 rename 的 POST 响应使用 `application/x-ndjson`，按行返回：

```json
{"type":"phase","phase":0}
{"type":"phase","phase":1}
{"type":"phase","phase":2}
{"type":"result","result":{}}
```

`phase` 在服务的真实边界发出：读取／整理上下文、生成调用、结果校验／写入。kickoff 和 handoff 的第三阶段是生成交付内容；内部模型执行不报告虚构百分比。失败返回 `type: error` 和安全错误体；请求断开不继续返回结果。请求进入流前的 HTTP 校验仍返回普通错误响应。阶段帧穿透项目历史的普通响应缓存，终态帧在历史事务确认后发出，保证进度实时到达。

commit 继续使用真实 Git SSE：staging、analyzing、committing。自动 compact 在 `context.window.updated` 附带 `compaction: {id, phase}`，随后通过 `context.compacted` 返回结果。

前端按收到的顺序展示节点，每个节点至少保留 450ms；服务器无需等待动画。结果已确认但动画尚未播放完时，撤下停止入口。失败和停止立即收敛，剩余节点不伪装成完成。

## 取消与竞争

- 普通命令使用 AbortController 断开请求，取消传递至后端 provider；生成返回后、持久化前再次检查上下文。旧请求的迟到响应不能覆盖停止态或新一轮结果。
- 显式 rename 使用当前上下文立即执行，并取消旧命名请求；操作版本与项目代次防止旧标题写回。手动命令执行中，后台触发不会与它同时写入标题。
- commit 新增 `POST /git-commits/:id/cancel`，取消分析和生成阶段并等待执行退出。进入实际写入版本的临界区后不可取消，接口返回真实终态。取消使用现有终止记录结构 `failed + error.code=COMMIT_CANCELED`，前端显示已停止，无数据库结构变更。
- 自动 compact 属于主任务，停止由主任务的停止入口负责，不伪装成可独立取消的请求；取消后不应用迟到的压缩输出。
- 已完成的持久化无法通过断开 HTTP 撤销；前端取消保障是拦截迟到响应，服务端在写入前检查取消。
