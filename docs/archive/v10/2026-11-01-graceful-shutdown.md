# 服务快速退出与任务安全停止

## 目标

- 空闲时收到 SIGINT、SIGTERM 或桌面父进程管道关闭后立即开始退出，不等待固定超时。
- 有任务时先保存暂停状态，再取消执行并等待写入收尾；已完成的任务保留终态。
- HTTP、任务、独立命令、导出与渲染使用同一个 8 秒优雅退出期限。超时必须记录错误，依靠既有持久化回执、事务及启动恢复处理未完成工作。

## 关闭流程

1. 取消 HTTP 请求的服务生命周期，主动结束 SSE、下载等连接，并停止接收新连接。任务执行使用独立上下文，不因 HTTP 断开而提前取消。
2. 并行暂停 Run、取消独立命令、取消导出及关闭 HTTP。关闭后拒绝新任务与新命令；停止已完成任务的后续排队处理和自动建议调度。
3. Run 的暂停标志先阻止后续执行写入，暂停状态落盘后再取消各工作流，等待工作流完成现有安全收尾。独立命令等待其终态回执保存；导出快照在写入者停止后才删除。
4. 渲染进程使用剩余期限关闭 Chromium 与子进程；到期后终止渲染进程组，最多额外 1 秒回收子进程。正常清理再次调用 Close 不重复等待。
5. 输出 `server stopped` 及实际耗时；任一阶段失败输出 `server shutdown incomplete` 与原因。

## 启动器

- Web 重启脚本先核对进程归属，去重 PID，再同时发出 TERM。每 100ms 检查一次，共用 12 秒等待期限，忽略已退出的僵尸进程。
- 脚本到期仍有进程存活时报告失败并停止重启，不强杀后台服务，不重置项目数据，不覆盖仍在使用的端口。
- 桌面端同时停止初始化进程与后台服务，保留 10 秒异常兜底窗口，覆盖 Go 的优雅退出和子进程回收预算。
- 桌面管道 EOF 只取消退出请求上下文，不提前撤销信号监听；随后到达的 TERM 仍由关闭流程接收，避免保存途中被默认信号处理直接终止。
- 删除旧的每进程 35 秒串行等待和桌面端 25 秒等待，保留启动健康检查原有行为。

## 手动验收

- 打开项目页面但不运行任务，保持会话 SSE 与项目命名 SSE 连接后重启，确认关闭阶段不再固定等待 5 秒。
- 在模型请求、工具写入、审批等待与命令执行阶段退出，重启后检查已保存内容、任务停止状态和历史结果；不应恢复运行中的动画，不应重复执行已提交写入。
- 在润色、压缩、Git 提交和导出过程中退出，检查已完成结果保留，未完成状态可由既有恢复流程识别，无继续写入的遗留进程。
- 多个项目同时运行或导出时退出，确认不会按任务数量逐个累加等待窗口。
- 桌面退出和 Web 重启后确认 Go、Vite、渲染 worker 及 Chromium 子进程退出；关闭超时时脚本不得继续初始化或启动。
- 观察后台日志中的实际退出耗时及失败阶段。上述目标尚未通过自动化测试、构建或实际启停验证，验证由用户手动完成。
