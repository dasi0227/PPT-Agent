# Web 前后端并行启动

## 启动顺序

- 旧进程全部退出、端口确认可用后，前端与后端准备流程开始并行。
- 前端分支准备自己的依赖并启动 Vite；前端可以在后端未就绪时监听端口，但此时不自动打开页面。
- 主分支先初始化项目数据与预置资源，等待初始化释放工作目录锁，再准备渲染及命令执行依赖并启动 Go 后端。
- Go 后端在对外服务前启动、检查其常驻渲染 worker，因此删除脚本中另起 Chromium 再关闭的重复健康检查。
- 前后端均就绪后才打开页面。健康检查保留 60 秒总等待窗口，每 100ms 检查，并在启动进程已退出时提前失败；每次 HTTP 检查限制连接及请求耗时。

## stdout 与日志

stdout 始终保持以下顺序，不按并行任务完成顺序输出：

1. 关闭前后端进程。
2. 初始化项目数据。
3. 启动后端。
4. 启动前端。
5. 打开应用。

前端准备流程的输出进入 `tmp/run/frontend-startup.log`，Vite 输出进入 `frontend.log`；后端依赖输出进入 `backend-dependencies.log`，Go 和其渲染 worker 输出进入 `backend.log`。不再产生独立渲染启动步骤；失败时 stdout 指向对应日志。

## 生命周期

- Vite 直接通过 Node 启动，PID 文件记录实际服务进程，减少 pnpm 包装进程带来的停止与就绪判断歧义。
- 前端启动分支处理取消信号，并在退出前写入已启动服务的 PID；主流程先等待该分支停止，再回收服务，避免清理后又启动进程。
- 初始化、依赖或任一服务启动失败时，退出前清理已经启动的服务；不打开页面。
- 两端成功后，打开浏览器失败仍保留可访问的服务，与原脚本一致。
- 保留 `--reset 0|1` 和 `--mode app|web` 语义。桌面模式仍先初始化再构建、打开 App，不启动额外的 Vite 开发服务。

## 手动验收

- 普通 Web 重启，确认前端在初始化和后端准备期间已经启动，但 stdout 仍按五个步骤顺序输出。
- 分别使用保留数据与清空数据模式，确认后端在初始化完成后才获取工作目录锁，预置资源照常重置。
- 前端依赖缺失、渲染依赖缺失时，确认各自先安装再启动；渲染 worker 不可用时后端启动失败，不重复启动临时 Chromium。
- 分别制造初始化、依赖、后端与前端启动失败，确认日志归属正确，脚本不打开页面，已经启动的进程被清理。
- 启动期间中断脚本，确认后台分支不会在清理结束后继续启动 Vite。
- 桌面模式仍按原四步运行。

本次未执行脚本、实际启停、构建或自动化验证；运行结果由用户手动确认。
