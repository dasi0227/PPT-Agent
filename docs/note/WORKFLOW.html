Harness 工作流

设计讨论

围绕 agent/service 的八个职责包，展开主循环、工具执行与人工等待，以及命令、历史和通知边界。图中类名为本轮设计建议。

主循环工具执行命令与历史类职责

主循环

执行路径回到循环条件 / 等待能力调用
  • 同会话仅一个非终态 Run；同项目不同会话允许并行。项目锁只覆盖必要的提交或排他操作，不覆盖整次模型调用与人工等待。
  • 等待答复不创建新 Run；首条闲聊被拒绝时，已受理但未处理的后续输入按契约交接。取消或异常保留已确认的工具结果与已提交修改。
  • 主循环拥有工具执行权。Spring AI 只返回一次模型响应；单次调用允许有限重试，模型切换重新组装请求。

工具执行、审批与提交

  • 16 个模型工具名映射到 11 个具体工具类；五个编辑工具共用 ResourceEditTool，技能 / 组件加载共用 AssetLoadTool。
  • 图中的候选提交路径适用于所有项目文件写入，包括 run_command。基准冲突、校验失败或审批拒绝均不覆盖现有文件；资源编辑不采用 JSON Patch。
  • 通过工具结果反馈可修复错误；持久化失败或执行结果无法确认时停止 Run。已成功结果不因后续取消改写，调用去重不等于承诺外部命令恰好执行一次。

命令、历史与运行边界

  • 自动压缩由 HarnessLoop 协调，经 CommandService 留下命令记录后复用 ContextCompactor。手动 compact 与本会话新 Run 互斥；Git 提交要求项目内无活动 Run。
  • 检查点是 Run 开始前的历史基准，不是断点续跑快照。文件改变会使同项目其他会话的检查点失效；回退 / 返回不重放原任务。
  • SSE 提供通知，查询接口提供事实。业务变化可读取后才发送 changed；断线不停止后台执行，重连或 reset 后重新读取。

类职责

共 51 个服务类、工具实现与直接依赖的边界类型。输入、输出只描述业务含义；数据对象与基础设施内部实现不在本次展开。

类名输入输出作用
agent/service/run
RunService新开、追加或取消请求；主循环的结束结果受理的 Run；状态变化与最终持久结果组织受理、模型配置固定、后台执行和统一收尾。协调会话占用与初始检查点；回复、净差异、终态及必要的输入交接协调提交。
HarnessLoop本次 Run 的配置、输入、上下文及取消信号待收尾的执行结果唯一主循环：处理输入、选择工具、组装上下文、调用模型、执行工具、等待交互、检查完成条件。工具调用与下一轮请求始终由它掌握。
RunGuard当前 Run 的取消状态、执行用量与最近进展继续执行或停止原因在循环和外部调用边界检查取消、轮次与活动时间预算、连续失败、重复读取及重复完成驳回；等待人工的时间不计入活动执行时间。
CompletionChecker候选回复、当前模式与计划、实际修改及最新校验证据允许结束，或需要继续处理的事项结束前重新检查已受理输入、计划状态、授权和产物证据。Plan 模式的普通文本不能代替计划审批；有问题则反馈给同一 Loop。
RunRecoveryService启动时遗留的活动 Run、命令与文件事务完成清理的文件状态；中断状态先协调遗留文件提交或回滚，再将无法继续的执行标记为 interrupted。保留已确认成功的工具与 Git 结果，不恢复旧 Loop，也不重新执行未知结果的工具。
agent/service/input
InputService首条指令或追加输入；引用、当前授权与待答状态受理回执；已判定输入与合并后的授权校验消息幂等、引用与输入开关；调用 JEV 判定，在安全边界消费队列。追加授权取并集，引用本身不扩大范围；首条闲聊拒绝后交接已受理的剩余输入。
agent/service/context
ContextServiceRun 状态、项目内容、会话上下文、引用与公开工具本轮模型上下文及 Token 估算刷新项目来源，按 ASSEMBLE 组装上下文，保留 Assistant / Tool 配对与消息顺序；识别压缩需要，压缩后重新估算。
PromptAssembler模式或任务类型、提示词模块及所需业务内容按固定顺序拼装的提示词内容复用主 Agent、Reviewer 与旁路命令的拼装规则。仅拼装，不调用模型、不决定业务流程。
ContextCompactor原摘要、待压缩内容、保留内容及压缩模型新摘要、保留的上下文成员及前后用量生成并校验压缩结果；保留工具轮次完整性。由 CommandService 提交摘要与上下文位置，历史正文不删除；不反向调用 command。
agent/service/tool
ToolRegistry已有工具实现、当前模式、授权及 JEV Prune 结果本轮可见工具定义；工具名对应的实现集中注册、选择与查找工具；以 ASSEMBLE 的工具集合为上限。工具声明可见性与执行时权限校验分别负责。
ToolGuard工具调用、已公开定义、授权、资源基准与审批结果允许执行、复用已确认结果，或拒绝原因校验工具参数、可见性、模式、目标权限和调用身份；实际应用修改前再次校验基准与审批。按固定顺序直接检查，暂不建责任链框架。
ToolExecutor模型返回的工具调用及当前运行上下文有序工具结果、必要的待答状态与修改结果调用先记录，再分发到 AgentTool，结果可读后通知。独立只读调用可并行，冲突写入受提交边界约束；可修复工具失败返回模型，持久化不确定等错误终止 Run。
AgentTool接口已验证的工具参数与当前运行上下文工具结果，或候选变更 / 人工交互请求统一工具定义与执行契约。这里存在多种真实工具实现，使用接口多态；不为普通 Service 机械增加接口与 Impl。
agent/service/interaction
InteractionService提问或审批申请；用户答复及当前待答版本有效答复、拒绝或关闭结果；同一 Run 的唤醒信号统一 question、plan、permission、scope、resource 五类交互。答复只受理一次；计划批准同时更新模式、计划与工具结果；范围变化合并，资料批准应用完整定稿前仍检查基准。
agent/service/command
CommandService手动命令、修订请求或自动触发；任务上下文独立命令执行记录及实际产物受理、取消并执行 rename、suggest、polish、handoff、compact、commit。有限的固定类型直接分派；压缩复用 ContextCompactor，提交使用 GitGateway。修订保留每次执行与最近成功产物。
CommandTrigger明确的生命周期时点、行为设置与当前会话状态符合条件的 rename / suggest 发起请求，或不触发处理自动命名、自动建议的业务条件与去重；可返回最新时不自动发起。由所属服务在明确时点直接调用，不引入通用 Hook 总线。
agent/service/session
SessionService会话管理请求或执行引起的会话状态变更会话信息、状态及一致版本管理会话创建、改名、删除、当前计划与状态查询。删除协调停止本会话活动；会话占用规则由原子持久化操作最终保证。
agent/service/history
HistoryService历史游标、Run / 命令 / 工具定位信息历史分组、执行详情与已保存差异按 API 聚合可公开历史，过滤供应商原生数据和内部提示；失败工具结果仍可持久化，展示设置不改变事实。
CheckpointService新 Run 的起始状态，或回退 / 返回请求与预览版本起始快照、可用回退目标，或历史恢复结果创建 Run 前的一致基准；管理回退、返回最新与分支确认。共享文件修改使其他会话检查点失效；恢复只影响目标会话及其可恢复文件。
agent/service/tool · AgentTool 实现
ReadResourceTool资源目标及读取要求资源内容、版本基准与可用观察结果实现 read_resource；读取项目资料、结构、规格或 HTML，并记录后续修改所依赖的内容基准。
ReadImageTool允许访问的图片引用图片内容及必要描述实现 read_image；解析项目附件或工具截图，校验归属与存在性，供模型理解图片。
AssetLoadTool技能或组件的稳定资产标识资产正文与更新后的活动资产集合共用实现 load_skill、load_component；通过 AssetService 读取数据库正文，再加入本 Run 上下文。
ResourceEditTool资源种类、字段更新或正文修改意图，以及已读基准完整候选文档、审批请求或实际修改结果共用实现 edit_meta、edit_constraints、edit_outline、edit_spec、edit_html。委托项目领域校验与提交；按设置审批资料修改；不使用 JSON Patch。
RunCommandTool模型提出的命令、工作目录与已授权能力进程输出、候选文件变更及最终执行结果实现 run_command；调用命令 worker，在沙箱准备结果。需审批时先展示命令与候选变更；批准仅作用于该候选，主项目写入走统一提交边界。
RenderSlideTool幻灯片及当前渲染输入；可选评分要求截图、版面检查与可选评分结果实现 render_slide；调用渲染 worker，按最新综合输入基准更新截图索引。可选评分调用 JEV，结果及复用基准存入 tool_result。
ReviewPptTool当前需求、项目源码及本 Run 的实际修改内容审查结论与可执行改进意见实现 review_ppt；按 Reviewer 提示词调用模型，起始基准复用检查点。审查结果返回主 Loop，由主 Loop 决定后续行动。
AskUserTool待澄清问题与可选答案用户选择、自填内容或跳过结果实现 ask_user；由 InteractionService 创建待答项，答复后继续原 Run。
CreatePlanTool规划模式下的完整计划提案计划审批结果及生效后的计划 / 模式实现 create_plan；批准后同一 Run 从 plan 转为 create，拒绝后继续规划，不覆盖已有生效计划。
UpdatePlanTool执行中的计划步骤更新更新后的生效计划实现 update_plan；经 SessionService 更新计划，校验步骤状态与同时最多一个 processing。
RequestPrivilegeTool当前范围之外的目标及申请理由范围批准、拒绝或被追加授权满足的结果实现 request_privilege；创建 scope 交互，与期间新增授权合并；剩余申请变化时更新待答版本。
interfaces/controller · 接入边界
ExecutionController发送指令、发起命令及取消的 HTTP 请求受理 ID 或空成功响应负责 DTO 校验与领域输入转换，调用 RunService / CommandService；不承载 Loop 或业务编排。
InteractionController待答读取或人工答复 HTTP 请求公开待答表单或空成功响应调用 InteractionService；空响应仅表示答复已受理，实际工具结果仍从详情读取。
SessionController会话列表、状态或管理 HTTP 请求会话 VO 或管理结果调用 SessionService；公开字段遵循会话接口契约。
HistoryController历史 / 详情查询或会话订阅请求历史 VO、详情 VO 或 SSE 连接查询交给 HistoryService；订阅交给 SessionSsePublisher。
CheckpointController检查点列表、预览、回退或返回请求检查点信息、预览或恢复结果调用 CheckpointService，保留预览版本与分支确认约束。
相邻领域 · 调用边界
ProjectContentService资源读取、候选修改、渲染结果或遗留事务合法候选、实际提交结果或一致的项目内容归 domain/project/service；统一资源规则、Schema / 引用校验、内容基准和文件提交。工具与人工保存复用；批准前候选不覆盖主项目，实际变更协调检查点失效。
AssetService资产标识与使用场景可用技能、组件或主题内容归 domain/asset/service；数据库是资产正文来源，统一存在性、类型与禁用校验。
SettingService模型选择与所需行为设置已校验的模型 / 路由与行为配置归 domain/setting/service；Run 开始时读取并固定所用配置，后续全局修改不改变正在执行的 Run。
domain · repository 边界接口
RunRepository接口Run 受理、输入处理、模型 / 工具消息或收尾业务变更持久结果、消息或一致快照负责 Run 相关复合提交与查询：起始快照、首条输入、凭据一起受理；完成结果与终态一起保存；输入移交保留身份与序号。不是逐表 CRUD 包装。
SessionRepository接口会话信息、计划或上下文成员的读写需求会话数据及对应 revision保存和读取会话业务状态。受影响数据与版本在同一事务处理，跨实体业务提交通过仓储实现协调，不能单独先递增版本。
CommandRepository接口命令受理、修订、取消或完成业务变更单次命令记录、成功产物与执行状态保证受理幂等、同操作占用与命令终态；命令产物及关联会话状态一并提交。compact 的摘要写入、上下文位置调整与 done 同事务保存。
CheckpointRepository接口一致快照、检查点查询或历史恢复集合检查点、恢复基准或恢复后的会话数据归 agent/repository；支持普通 / 返回快照、分支清理和受影响会话版本更新；不保存周期性 Loop 运行快照。
ProjectContentRepository接口带基准和归属的候选文件集合、提交标识或恢复请求一致读取或可确认的文件提交结果归 project/repository；基础设施实现组合文件系统与数据库。使用本次修改事务记录、成功凭据和启动清理协调提交，避免把文件系统当作数据库事务的一部分。
domain/agent/gateway · 外部能力接口
LlmGateway接口已组装上下文、工具定义、模型配置及取消信号文本 / 推理 / 工具请求、用量与必要原生回传数据抽象一次模型请求。业务层只依赖领域类型，不暴露 Spring AI / SDK 类型；不在 gateway 内循环执行工具。
JevGateway接口判定任务与对应内容Intent、Prune、Rename 或 Preview 判定结果封装 JEV 能力调用；业务上何时调用及如何使用判定仍由 input、tool、command 负责。
CommandGateway接口允许的命令、沙箱参数与取消信号退出结果、输出及沙箱文件候选对接 command-worker；执行与超时、取消、输出限制属于基础设施，是否允许应用结果由领域决定。
RenderGateway接口固定的完整渲染输入与取消信号截图及必要版面检查结果对接 render-worker；不负责主 Loop、批准或会话历史。
GitGateway接口项目 Git 操作及确定的提交意图状态 / 差异或已确认的提交结果执行 Git 能力；项目互斥和命令生命周期由 CommandService 协调。无法确认的提交结果不能假定成功或重复执行。
SessionEventPublisher接口已可读取的业务变化，或瞬时进度 / 待答变化面向会话订阅者的通知领域侧事件出口；持久变化提交成功后发送 changed，进度与待答通知按实际状态发送。通知只负责促使前端读取，不承担持久历史。
interfaces/sse · 通知实现
SessionSsePublisher会话订阅与 SessionEventPublisher 通知SSE changed / reset / 进度 / 交互消息实现会话通知出口并管理连接。断线不取消 Run；不提供历史事件补放，重连或 reset 后按 API 重新读取。
infrastructure/llm · 模型实现
SpringAiLlmGateway领域模型请求及固定的协议 / 路由配置转换后的领域模型响应或可识别错误实现 LlmGateway，以 Spring AI 适配 OpenAI / Anthropic；关闭框架自动工具执行。处理有限重试、模型切换、取消与原生协议转换，切换后按目标协议重建请求。
设计依据目录与职责边界接口与执行规则持久化与一致性提示词与工具集合Spring AI 工具调用边界
