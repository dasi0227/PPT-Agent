类职责
类名 输入 输出 作用
agent/model/enumeration
ToolErrorCode 枚举 工具调用契约或执行失败的具体原因 稳定的工具错误标识 归属工具专属错误，如参数不合法、替换目标不存在、渲染失败。用于失败 ToolResult 和模型 observation；按业务含义分类，不按前端或模型接收方分类，不表示所有工具错误都可重试。跨领域共用错误仍保留 shared/exception/ErrorCode。
HarnessErrorCode 枚举 运行协调、持久化或执行状态异常的具体原因 稳定的 Harness 错误标识 归属 Harness 专属错误，如持久化结果无法确认、内部执行状态异常。由执行边界根据具体含义决定重试、终止与收尾；即使发生在工具内部，也不能一律转成失败 observation 继续运行。取消走独立取消流程。
agent/model/event
BeforeInputProcessedEvent 不可变事件 已受理落库、即将开始处理的输入及必要上下文 输入处理生命周期的不可变输入 只携带 Intent 的输入材料及自动命名所需的 Run 固定开关、路由和命名依据；同步 Hook 另行接收 currentResult，异步 Hook 仅接收此事件。事件不包含可写 RunState 或可变阶段结果。
BeforeModelCallEvent 不可变事件 本轮材料及按模式、授权允许的候选工具 主模型调用前生命周期的不可变输入 仅用于 Harness 主模型请求，不覆盖 JEV 或旁路命令；候选工具是裁剪上限，事件及集合保持不可变，筛选结果单独保存在 BeforeModelCallResult。
BeforeRunCompletedEvent 不可变事件 主流程准备的候选回复、模式、计划、授权、产物与本次任务所需校验结果 完成检查生命周期的不可变输入 由主流程控制输入边界、处理剩余输入后准备；只提供完成检查材料，不提供修改输入开关、Run 状态或提交终态的能力。
RunCompletedEvent 不可变事件 Run 已成功提交的完成结果及关联信息 供 AutoSuggestHook 读取的不可变事件 由 RunService 在完成结果提交成功后构造；携带触发 Run 的最后用户输入 ID、已固定的自动建议开关及所需路由，不作为 SSE 消息或可写运行状态。
agent/model/result
BeforeInputProcessedResult 不可变阶段结果 阶段初始值，或前序同步 Hook 已产生的输入处理结果 供 InputService 应用的最终输入处理结果 由 IntentHook 写入每条输入的判定：task 沿用模式，gossip 切换提示词与工具，disclosure / bypass / irrelevant 直接拒绝。未取得有效判定进入技术错误处理。
BeforeModelCallResult 不可变阶段结果 允许的候选工具，以及前序同步 Hook 的筛选结果 供 HarnessLoop / ToolRegistry 应用的最终工具选择结果 属于 beforeModelCall 生命周期。初始保留允许的候选工具，同步 Hook 基于 currentResult 更新；Prune 不可用时保留该 Hook 调用前的结果，不能扩大授权。
BeforeRunCompletedResult 不可变阶段结果 阶段初始值，或前序同步 Hook 的完成检查结果 完成判定及需要继续处理的问题 属于 beforeRunCompleted 生命周期。初始尚未确认完成，由 CompletionHook 更新；HarnessLoop 据此继续执行或交给 RunService 提交。检查失败不能按允许完成处理。
ToolResult 工具执行结果 工具成功产物、受阻结果，或可反馈的执行失败 供 ToolExecutor 保存并转换为 observation 的完整结果 归 agent/model/result，承载一次工具调用的业务结果；失败包含错误码、具体原因及修正提示，可使用工具专属或共享错误码。通过 success / failure 等入口构造完整结果，不散落修改 RunState.error。待审批候选不是已提交成功；取消与未知故障不伪装成可反馈失败。不是 HTTP 通用 Result 包装。
agent/service/run
RunService 新开、追加或取消请求；对话调用用量、已提交修改事实与主循环结束结果 受理的 Run；状态变化与最终持久结果 组织受理、模型配置固定、后台执行和统一收尾；协调会话占用与初始检查点。在同一受理临界区将模型配置、执行开关与审查文件基准固定在内存，受理成功后释放锁并调度。收尾时将自动建议所需材料交给异步事件，再释放本 Run 的执行材料。累计并保存主循环对话用量；通过 RunChangeSet 按本 Run 的成功提交记录汇总净差异，抵消自身撤销的修改。完成条件满足后通过 IRunRepository 将最终回复、回复后检查点、净差异与终态一起保存；传播至 Run 边界的异常按具体原因及 HarnessErrorCode 处理；取消独立收尾，保留已确认修改和已发生用量。完成提交成功后调用 afterRunCompleted；Hook 不负责终态提交。
RunStateRun 内存状态 受理时固定的 RunConfig 与审查基准，当轮实际路由与最近一次完整请求的 ContextEstimate 本次执行材料及最近一次完整的上下文估算 由 RunService 按 Run 创建并释放。ContextService 按完整请求计算总量与明细并整体替换估算，SessionService 读取该值。
HarnessLoop 本次 Run 的配置、输入、上下文及取消信号 待收尾的执行结果 唯一主循环：调用 beforeModelCall 并应用阶段 Result，完成请求组装、估算与校验。实际发送前协调 InputService 检查新输入；有新输入则处理并重新准备请求，无则调用模型。掌握工具执行、交互等待和自动压缩。尝试结束时协调输入边界、剩余输入与检查材料，调用 beforeRunCompleted；不满足则恢复受理并继续循环，满足则交给 RunService 提交。
RunGuard 当前 Run 的取消状态、执行用量与最近进展 继续执行或停止原因 在循环和外部调用边界检查取消、轮次与活动时间预算、连续失败、重复读取及重复完成驳回；等待人工的时间不计入活动执行时间。
RunRecoveryService 启动时遗留的活动 Run、命令与文件事务 完成清理的文件状态；中断状态 先按 file_undo 还原项目文稿，整批成功后删除记录。随后将无法继续的执行标记为 interrupted，保留已确认的工具与 Git 结果。旧 Loop 和结果未知的工具均不重放。
agent/service/input
InputService 首条指令或追加输入；引用、当前授权与待答状态 受理回执、已处理输入与授权状态；输入边界控制结果 校验消息引用与输入开关，受理时一并保存发送前检查点，随后在安全边界消费队列；发送前检查是否有新输入待处理。输入开始处理时调用 beforeInputProcessed，应用 Result 并保存处理状态。输入出队、授权变化及实际接入对话由本类负责。按主流程要求封闭或恢复受理；追加授权取并集，引用不扩大范围，首条输入被拒后关闭入口，未处理输入留在原 Run 历史。
agent/service/hook
HookDispatcher 四个生命周期各自的不可变 Event 前三个入口返回各自的 Result；afterRunCompleted 返回 void 通过构造器接收 Hook 与执行器。为阶段创建初始 Result，按明确顺序调用同步 Hook 并传递 currentResult；按阶段规则投递异步 Hook，再返回最终结果。统一负责顺序、异步调度和阶段错误处理，不应用业务状态变化。
SyncHook 接口 不可变 E event 与前序 R currentResult 更新后的不可变 R SyncHook<E, R> 契约：R execute(E event, R currentResult)。接收前序阶段结果，返回新结果并保留其他已产生的信息；失败交由 Dispatcher 按阶段规则处理，不直接控制 Loop、修改 Run 状态或提交终态。
AsyncHook 接口 不可变 E event void；不参与同步阶段结果 AsyncHook<E> 契约：void execute(E event)。执行附加行为，只接收事件，不读取或修改同步链的 Result；调度和错误隔离由 Dispatcher 负责，Hook 不创建线程池。
agent/service/hook/beforeinputprocessed
IntentHook BeforeInputProcessedEvent 与当前 BeforeInputProcessedResult 更新后的 BeforeInputProcessedResult 实现 SyncHook，使用 IntentPromptAssembler 组装材料后，通过 IJevGateway 执行 Intent 判定并更新输入处理阶段结果；不控制队列或直接更新授权。由 InputService 应用最终结果，Intent 调用失败或无有效判定时经 Dispatcher 传播，由 RunService 按 failed 收尾。
AutoRenameHook BeforeInputProcessedEvent 及命名所需设置、会话状态 void；符合条件时发起 rename 实现 AsyncHook，输入开始处理时使用 Run 固定的开关及路由检查自动命名，按需使用 RechristenPromptAssembler 组装材料并通过 IJevGateway 判定，再调用 CommandService 统一受理；可返回最新时不自动发起。意图拒绝不统一短路命名，不参与同步 Result。
agent/service/hook/beforemodelcall
ToolPruneHook BeforeModelCallEvent 与当前 BeforeModelCallResult 更新后的 BeforeModelCallResult 实现 SyncHook，使用 PrunePromptAssembler 组装材料后，通过 IJevGateway 取得裁剪判定，基于当前 Result 更新工具选择；只缩减允许的候选集合。候选已为空（如 gossip）时直接沿用空集。不可用时由 Dispatcher 保留进入该 Hook 前的 Result，不在 Hook 内分散定义阶段降级规则。
agent/service/hook/beforeruncompleted
CompletionHook BeforeRunCompletedEvent 与当前 BeforeRunCompletedResult 更新后的 BeforeRunCompletedResult 直接实现 SyncHook<BeforeRunCompletedEvent, BeforeRunCompletedResult>。检查计划、授权、产物及任务要求的必要校验，更新完成判定与问题。不以所有页面或每次 HTML 修改都有最新截图为门槛；明确要求的截图检查须完成，旧截图不证明新版已检查。Plan 模式的任务须通过计划审批；仅含 gossip 的 Run 按闲聊答复完成，不要求计划或文稿产物。只检查条件，不控制输入、Loop 或终态提交。
agent/service/hook/afterruncompleted
AutoSuggestHook RunCompletedEvent 及建议所需设置、会话状态 void；符合条件时发起 suggest 实现 AsyncHook，在完成提交成功后使用事件内的开关与路由，核对触发输入仍是会话最新用户输入，通过 CommandService 受理 suggest；可返回最新时不自动发起。调度及执行失败由 Dispatcher 隔离，不改变已提交的主流程结果。
agent/service/context
ContextService Run 状态、项目材料、会话上下文与引用；请求准备或会话统计查询 最终请求材料、Token 估算与校验结果；当前上下文统计 应用 BeforeModelCallResult 后，选择 PromptAssembler 组装请求并校验。仅使用已有全部配对结果的 Assistant / Tool 轮次，保留消息顺序，压缩或处理新输入后重新组装。根据完整请求的实际路由、消息及工具估算 Token 总量和分类明细，发布到 RunState。空闲时使用 Create 提示词、工具及当前会话材料估算。
ContextCompactor 原摘要、待压缩内容、保留内容及压缩模型 新摘要、保留的上下文成员及前后用量 由 CompactCommandHandler 调用；使用 CompactPromptAssembler 和 ILlmGateway 生成并校验压缩结果，对明确格式或业务约束违规执行有限纠错，保留工具轮次完整性。校验通过后交给 CommandService 保存，历史正文不删除；不反向调用 command。
PromptAssembler 接口 当前场景需要的提示词模块、业务材料及工具或判定约定 按场景顺序拼装的输入材料及工具定义或判定问题 提示词拼装接口，不加 I。由 XxxPromptAssembler 实现各场景的模块选择、材料组织、可选块与拼装顺序；复用公共模板渲染。只拼装，不调用模型、不管理执行状态或持久化。
agent/service/context/assembler
ChatPromptAssembler 会话历史、当前输入及必要运行上下文 Chat 模式或当轮 gossip 的提示词与消息 task 在 Chat 模式按 ASSEMBLE 的顺序拼装 mode_chat 与上下文。任一模式收到 gossip 时仅拼装 prompts/gossip.md 与该条输入，工具为空。
AskPromptAssembler 咨询需求、项目上下文、会话历史与引用 Ask 模式提示词与消息 按 ASSEMBLE 的 Ask 顺序拼装公共模块、mode_ask 和上下文；提问工具仍由 ToolRegistry 选择。
PlanPromptAssembler 规划需求、项目与计划状态、会话历史 Plan 模式提示词与消息 按 ASSEMBLE 的 Plan 顺序拼装公共模块、mode_plan 和上下文；计划执行与审批仍归原服务。
CreatePromptAssembler 创作需求、项目与计划状态、资产及会话上下文 Create 模式提示词与消息 按 ASSEMBLE 的 Create 顺序拼装核心、playbook、rule、mode_create、边界提醒与上下文。
RenamePromptAssembler 当前标题、会话历史及命名要求 命名提示词与所需工具定义 拼装 command_rename、当前标题、历史和用户要求，附带 rename_thread 输出约束。
SuggestPromptAssembler 项目与计划状态、会话历史及建议要求 建议提示词与所需工具定义 拼装 command_suggest、项目与计划上下文、历史和用户要求，附带 suggest_request 输出约束。
PolishPromptAssembler 用户草稿、上一修订、反馈及当前要求 润色提示词与所需工具定义 拼装 command_polish、草稿及修订材料，附带 polish_instruction 输出约束；保持修订材料顺序。
HandoffPromptAssembler 项目上下文、会话历史、上一修订及反馈 交接提示词与所需工具定义 拼装 command_handoff、项目与历史、修订反馈和用户要求，附带 handoff_thread 输出约束。
CompactPromptAssembler 原摘要、待压缩上下文与需要保留的上下文 压缩提示词与所需工具定义 拼装 command_compact、previous_summary、compressed_context、retained_context，附带 compact_context 输出约束。
CommitPromptAssembler Git 状态、变更统计、暂存差异及提交要求 提交分析提示词与所需工具定义 拼装 command_commit、文件状态、行数统计、暂存差异和用户要求，附带 git_commit 输出约束；不执行 Git。
ReviewPromptAssembler 用户需求、审查要求、当前源码及本 Run 差异 Reviewer 提示词与审查材料 拼装 reviewer_agent，并按 ASSEMBLE 顺序加入需求、审查要求、当前源码和差异；不执行审查调用。
IntentPromptAssembler 会话历史、当前输入及是否包含显式引用 Intent 判定材料与问题 拼装 jev_intent、会话历史、引用标记和当前输入及对应问题；供 IntentHook 调用 IJevGateway。
PrunePromptAssembler 会话历史与当前输入 Prune 判定材料与问题 拼装 jev_prune、历史与当前输入，附带 meta / constraint / outline 裁剪问题；供 ToolPruneHook 调用 IJevGateway。
RechristenPromptAssembler 当前标题、会话历史与当前输入 是否需要改名的判定材料与问题 拼装 jev_rename、当前标题、历史和输入，供 AutoRenameHook 调用 IJevGateway 判断是否需要改名；不生成新标题。
PreviewPromptAssembler 项目资料、页面规范、HTML 与截图 Preview 判定材料与问题 拼装 decision_preview、meta、constraint、spec、HTML 与截图，附带内容与视觉检查问题；供 RenderSlideTool 调用 IJevGateway。
agent/service/tool
ToolRegistry 已有工具实现、当前模式、授权及 BeforeModelCallResult 允许的候选工具、最终工具定义及工具名对应的实现 按 ASSEMBLE、输入路由、模式与当前授权产生候选集合，gossip 的集合固定为空，再由主流程应用最终阶段 Result；最终工具集合只能是允许候选集合的子集。Prune 不可用时沿用未额外裁剪的当前结果，执行权限仍由 ToolGuard 强制校验。
ToolGuard 工具调用、已公开定义、授权、资源基准与审批结果 允许执行、复用已确认结果，或带错误码的拒绝原因 校验工具参数、可见性、模式、目标权限和调用身份；实际应用修改前再次校验基准与审批。拒绝原因由 ToolExecutor 构造对应 ToolResult；按固定顺序直接检查，暂不建责任链框架。
ToolExecutor 模型返回的工具调用及当前运行上下文 有序 ToolResult、必要的待答状态与修改结果 先记录调用，再分派 AgentTool；统一保存 ToolResult，并将可反馈失败映射为配对 observation。只将已识别、允许反馈给模型的业务异常转换为失败结果；持久化不确定、内部状态损坏和未知异常向上传递至 RunService，取消走取消流程。独立只读调用可并行，冲突写入受提交边界约束；结果可读后通知。
AgentTool 接口 已验证的工具参数与当前运行上下文 ToolResult，或待主流程处理的候选变更 / 人工交互请求 统一工具定义与执行契约，由具体工具实现。可明确处理的执行失败直接返回完整 ToolResult.failure，成功返回业务结果；深层调用的异常交由 ToolExecutor 边界识别，不在各处改写 RunState.error，也不把所有 Exception 转为 observation。审批中的候选继续走原交互流程。
agent/service/interaction
InteractionService 提问或审批申请；用户答复及当前待答版本 有效答复、拒绝或关闭结果；同一 Run 的唤醒信号 统一 question、plan、permission、scope、resource 五类交互。答复只受理一次；计划批准同时更新模式、计划与工具结果；范围变化合并，资料批准应用完整定稿前仍检查基准。
agent/service/command
CommandService 手动或 Hook 发起的命令、修订与取消请求；任务上下文 命令受理结果、独立执行记录与实际产物 统一处理命令受理、当前状态与占用校验、修订、调度及取消，按类型选择 CommandHandler。命令受理时固定写回依据；提交时在同一事务校验并写入产物、关联变更与终态。过期的 rename / suggest 记 cancelled 且 result 为空，再通知；保留每次执行及最近成功产物。自动发起条件由 AutoRenameHook / AutoSuggestHook 判断。
CommandHandler 接口 已受理的命令类型、业务上下文与取消信号 可校验的命令产物、关联变更及外部执行事实 命令业务执行接口，不加 I。每种命令对应一个 XxxCommandHandler，负责组装、调用及明确格式与业务约束校验；可纠正的违规反馈到该命令模型上下文，有限重试。校验通过前不应用产物；不把文案质量等主观判断作为程序校验。公共纠错步骤可复用，生命周期与终态保存交给 CommandService。
agent/service/command/handler
RenameCommandHandler 命名请求、当前标题、会话历史及取消信号 校验后的标题与待应用的会话变更 调用 RenamePromptAssembler 与 ILlmGateway，解析并校验 rename_thread 结果；交由 CommandService 比较会话标题是否仍等于受理时原名，匹配才写回。
SuggestCommandHandler 建议请求、项目与计划上下文、会话历史及取消信号 校验后的下一步建议 调用 SuggestPromptAssembler 与 ILlmGateway，解析并校验 suggest_request 结果。CommandService 比较最新用户 instruction ID，并核对本次仍为会话内 seq 最大的 suggest，均匹配才写回。
PolishCommandHandler 润色请求、原草稿、上一修订、反馈及取消信号 当前执行生成的润色产物 调用 PolishPromptAssembler 与 ILlmGateway，解析并校验 polish_instruction 结果；修订记录与最近成功产物由 CommandService 管理。
HandoffCommandHandler 交接请求、项目与会话上下文、修订反馈及取消信号 交接产物及待应用的关联变更 调用 HandoffPromptAssembler 与 ILlmGateway，解析并校验 handoff_thread 结果；交接产物及关联会话变更由 CommandService 统一保存。
CompactCommandHandler 压缩请求、当前摘要、会话上下文及取消信号 压缩产物与待调整的上下文位置 委托 ContextCompactor 完成压缩；将结果交还 CommandService，保证摘要、上下文位置与命令终态同事务提交。
CommitCommandHandler 提交请求、项目 Git 状态、用户要求及取消信号 已确认的 Git 提交事实或明确失败 通过 IGitGateway 获取状态、暂存及差异，调用 CommitPromptAssembler 与 ILlmGateway 分析并生成提交意图，再由 IGitGateway 提交和核实。已确认提交不因随后取消而改记失败。
agent/service/session
SessionService 会话管理请求或执行引起的会话状态变更 会话信息、状态及一致版本 管理会话创建、改名、删除、当前计划与状态查询。查询时返回会话持久版本与实时上下文估算。删除时协调停止本会话活动，占用规则由原子持久化操作保证。
agent/service/history
HistoryService 历史游标、Run / 命令 / 工具定位信息 历史分组、执行详情与已保存差异 按 API 聚合可公开历史，过滤供应商原生数据和内部提示；失败工具结果仍可持久化，展示设置不改变事实。
CheckpointService 用户指令、最终回复，或携带预览版本的回退与返回请求 消息检查点、可用回退目标，或历史恢复结果 在用户发送前、最终回复后采集快照。新 Run 受理时同时取得内存审查基准。回退与返回均恢复五类文稿、有效计划、有序上下文和当前分支的历史位置。标题沿用当前值。回退或返回实际改变共享文稿文件时，清理同项目其他会话的检查点及返回快照。
agent/service/tool/builtin
ReadResourceTool 资源目标及读取要求 资源内容、版本基准与可用观察结果 实现 read_resource；读取项目资料、结构、规格或 HTML，并记录后续修改所依赖的内容基准。
ReadImageTool 允许访问的图片引用 图片内容及必要描述 实现 read_image；解析项目附件或工具截图，校验归属与存在性，供模型理解图片。
LoadAssetTool 技能或组件的稳定资产标识 资产正文与更新后的活动资产集合 共用实现 load_skill、load_component；通过 AssetService 读取数据库正文，再加入本 Run 上下文。
EditResourceTool 资源种类、字段更新或正文修改意图，以及已读基准 完整候选文档、审批请求或实际修改结果 共用实现 edit_meta、edit_constraint、edit_outline、edit_spec、edit_html。委托项目领域校验与提交；按设置审批资料修改；不使用 JSON Patch。
RunCommandTool 模型提出的命令、工作目录与已授权能力 进程输出、候选文件变更及最终执行结果 实现 run_command；调用命令 worker，在沙箱准备结果。需审批时先展示命令与候选变更；批准仅作用于该候选，主项目写入走统一提交边界。
RenderSlideTool 幻灯片及当前渲染输入；可选评分要求 截图、版面检查与可选评分结果 实现 render_slide；调用渲染 worker，按最新综合输入基准更新截图索引，历史截图随项目保留，当前缩略图可重建。可选评分使用 PreviewPromptAssembler 组装材料后调用 IJevGateway，结果及复用基准存入 tool_result。
ReviewPptTool 当前需求、项目源码及本 Run 的实际修改 内容审查结论与可执行改进意见 实现 review_ppt。用 ReviewPromptAssembler 独立组装请求，按本 Run 固定的主模型和主路备用配置调用 ILlmGateway。结合受理时固定的内存文件基准、已提交净差异与当前源文件审查，检查点失效后仍可审查。结果交回主循环。
AskUserTool 待澄清问题与可选答案 用户选择、自填内容或跳过结果 实现 ask_user；由 InteractionService 创建待答项，答复后继续原 Run。
CreatePlanTool 规划模式下的完整计划提案 计划审批结果及生效后的计划 / 模式 实现 create_plan；批准后同一 Run 从 plan 转为 create，拒绝后继续规划，不覆盖已有生效计划。
UpdatePlanTool 执行中的计划步骤更新 更新后的生效计划或 null 实现 update_plan；steps 必传。非空数组以有序 {title, status} 替换，状态限 pending / processing / completed，最多一步 processing；steps=null 清空 sessions.plan，空数组无效。计划、配对工具结果和 revision 同事务提交，提交后按实际变化通知 run、plan、history、context。
RequestPrivilegeTool 当前范围之外的目标及申请理由 范围批准、拒绝或被追加授权满足的结果 实现 request_privilege；创建 scope 交互，与期间新增授权合并；剩余申请变化时更新待答版本。
interfaces/controller · 接入边界
ExecutionController 发送指令、发起命令及取消的 HTTP 请求 受理 ID 或空成功响应 通过 @Valid 触发 DTO 校验，调用 DTO 的 toEntity() 转换领域输入，再调用 RunService / CommandService。
InteractionController 待答读取或人工答复 HTTP 请求 公开待答表单或空成功响应 调用 InteractionService；空响应仅表示答复已受理，实际工具结果仍从详情读取。
SessionController 会话列表、状态或管理 HTTP 请求 会话 VO 或管理结果 调用 SessionService；公开字段遵循会话接口契约。
HistoryController 历史 / 详情查询或会话订阅请求 历史 VO、详情 VO 或 SSE 连接 查询交给 HistoryService；订阅交给 SseEventPublisher。
CheckpointController 检查点列表、预览、回退或返回请求 检查点信息、预览或恢复结果 按消息 ID 查询和预览检查点，提交回退与返回请求时校验预览版本。
相邻领域 · 调用边界
DeckService 带来源归属的资源修改、读取、渲染结果或遗留事务 已校验的 DeckEditCandidate、带归属的已提交修改事实或读取到的项目内容 归 domain/project/service；统一资源规则、Schema / 引用校验、内容基准和文件提交，工具与人工保存复用。真实提交时可靠记录来源和实际修改，候选不计入已提交差异；工具实际写入时协调检查点失效，人工保存保留各会话原有的检查点和版本。明确业务冲突可抛 BusinessException，由调用边界决定 HTTP 错误响应或失败工具结果；本类不返回工具专属 ToolResult，提交不确定等故障向上传递。
AssetService 资产标识与使用场景 可用技能、组件或主题内容 归 domain/asset/service；数据库是资产正文来源，统一存在性、类型与禁用校验。
SettingService 模型选择与所需行为设置 已校验的模型 / 路由与行为配置 归 domain/setting/service，提供全局模型、路由和行为设置。RunService 在受理时组装 RunConfig，主循环、审批判断及该 Run 的自动命令复用这份配置。手动命令在自身受理时取配置，show_tool_failures 即时影响展示。
domain · repository 边界接口
IRunRepository 接口 Run 受理、输入处理、模型 / 工具消息或收尾业务变更 持久结果、消息或一致快照 由 infrastructure/repository/RunRepository 实现。负责 Run 复合提交与查询：首条指令及追加指令分别与发送前检查点同事务写入。对话用量去重累计。最终回复、回复后检查点、净差异与终态一起保存。输入受理后固定归属与序号。失败、取消或中断保留已确认修改与已发生用量。不是逐表 CRUD 包装。
ISessionRepository 接口 会话信息、计划或上下文成员的读写需求 会话数据及对应 revision 由 infrastructure/repository/SessionRepository 实现。保存和读取会话业务状态。受影响数据与版本在同一事务处理，跨实体业务提交通过仓储实现协调，不能单独先递增版本。
ICommandRepository 接口 命令受理、修订、取消或完成业务变更 单次命令记录、成功产物与执行状态 由 infrastructure/repository/CommandRepository 实现。核对同操作占用并保存命令终态；命令产物及关联会话状态一并提交。compact 的摘要写入、上下文位置调整与 done 同事务保存。
ICheckpointRepository 接口 一致快照、检查点查询或历史恢复集合 检查点、恢复基准或恢复后的会话数据 由 infrastructure/repository/CheckpointRepository 实现。归 agent/repository。负责普通及返回快照与分支清理，不保存周期性 Loop 运行快照。历史切换在同一事务中恢复计划、上下文消息顺序和历史位置，处理返回行并按预期版本推进会话版本。
IProjectRepository 接口 项目 ID、文稿文件变更集合及本次提交的业务写入 项目记录与状态、文稿文件内容或已提交的业务变更 由 infrastructure/repository/ProjectRepository 实现。归 project/repository。在改文稿前独立提交整批旧内容，文件落盘后将业务变更与撤销记录的删除同事务提交。恢复失败时保留整批记录并暂停该项目写入。
domain/gateway · 外部能力接口
ILlmGateway 接口 LlmRequest（Spring AI 的 List<Message> 与本次开放的工具定义）、模型配置及取消信号 LlmResponse，含正文、推理、有序工具调用、逐次可得用量与必要协议回传数据 由 infrastructure/gateway/LlmGateway 实现。网关按目标协议发送已组装的消息，报告每次实际请求（含重试）的可得用量。调用场景决定统计归属，主循环对话用量由 RunService 累计。工具执行由 ToolExecutor 负责。
IJevGateway 接口 结构化问题、提示词材料及输入基准 Intent、Prune、Rename 或 Preview 判定结果 由 infrastructure/gateway/JevGateway 实现。网关将拼装器提供的材料和问题发送到同一 HTTP 接口并解析结果。Intent、Prune、Rename 由对应 Hook 发起，发送 JSON。RenderSlideTool 按需发起 Preview，使用 multipart/form-data 上传截图。JEV 调用在主模型 Hook 生命周期之外执行。
IBashGateway 接口 允许的 Bash 命令、沙箱参数与取消信号 退出结果、输出及沙箱文件候选 由 infrastructure/gateway/BashGateway 实现。对接 command-worker；执行与超时、取消、输出限制属于基础设施，是否允许应用结果由领域决定。
IRenderGateway 接口 单页渲染输入与取消信号，或整稿快照与导出格式 单页截图与版面检查结果，或整稿成品文件流 由 infrastructure/gateway/RenderGateway 实现，调用外部 render-worker。
IGitGateway 接口 项目 Git 操作及确定的提交意图 状态 / 差异或已确认的提交结果 由 infrastructure/gateway/GitGateway 实现。执行 Git 能力；项目互斥和命令生命周期由 CommandService 协调。无法确认的提交结果不能假定成功或重复执行。
domain/shared/sse · 订阅事件与发布接口
EventPublisher 接口 投递目标和具体 SseEvent 面向会话订阅者的通知 项目和 Agent 服务共用的发布接口。持久变化可查询后按归属发布 project_changed 或 session_changed，进度与待答通知按当前状态发布。
interfaces/sse · 通知实现
SseEventPublisher 会话订阅、投递目标与 SseEvent SSE 流中的事件名和 JSON 数据 实现 EventPublisher，管理订阅连接。项目文稿、外观或会话列表变化时向同项目所有已连接会话发送 project_changed，对应区域为 content、appearance 或 sessions。历史、计划和检查点变化时向受影响的会话发送 session_changed，携带该会话的 revision。断线后 Run 继续，重连或 reset 后通过查询重新同步。
infrastructure/gateway · 模型实现
LlmGateway 领域模型请求及固定的协议 / 路由配置 转换后的领域模型响应或可识别错误 实现 ILlmGateway，由 Spring AI 2.1 的 OpenAiResponsesChatModel 对接 responses，AnthropicChatModel 对接 anthropic。关闭框架自动工具执行。处理请求层有限重试、模型切换、取消、逐次用量报告与协议转换；切换后按目标协议重建请求。命令产物的业务校验与纠错归对应 Handler 或 ContextCompactor。
