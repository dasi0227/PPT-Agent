<user_request>

  • 用户输入与 @ 页面引用（标题、幻灯片 ID）。
  • 附件：<image_attachment> 元数据（ID、路径、尺寸、可选文件名）及原始图片。
  • Annotation：<selected_dom> 批注、页面与选区信息，以及选中目标的 HTML、位置和样式等快照。
  • 后续用户输入、澄清回答，以及计划、命令、范围和资源编辑的审批反馈。

每条输入以 <request_input kind="…"> 分块，按接收顺序汇总；块内先放文本，再按 reference_order 放附件与 annotation。

按需注入

  • <run_read_image>：本轮读取的图片或渲染截图，附来源信息；幻灯片截图标记 current / previous。
  • Runtime 反馈：完成检查拒绝原因、计划提交纠正等。

Tools

  • read_resource
  • read_image
  • load_skill（已配置加载器时）
  • load_component（已配置加载器时）
  • run_command（写入仅限执行阶段并受审批约束）
  • render_slide
  • edit_manifest（执行阶段）
  • edit_design（执行阶段）
  • edit_outline（执行阶段）
  • edit_spec（执行阶段）
  • edit_html（执行阶段）
  • ask_user
  • create_plan（无计划或计划待批准）
  • update_plan（计划已批准且进行中）
  • request_privilege（执行阶段）
  • review_ppt（执行阶段）

提供工具定义及参数 Schema；每轮按模式、阶段及运行时限制筛选。

消息顺序：System → 七条 Runtime Context（User）→ 对话历史 → 当前 User Request → 完成检查反馈（如有）。

历史保留 User / Assistant / Tool 原角色；读取图片的 User 消息保留在对话中的位置。当前输入汇总至末尾，澄清与审批结果同时保留原 Tool 配对。
